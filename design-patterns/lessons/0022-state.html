State

Design Patterns · Lesson 0022 · step 22 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: replace state-dependent conditionals with state objects that trigger their own transitions.

Intent

State is "a behavioral design pattern that lets an object alter its behavior when its internal state changes." It relates to finite-state machines: put each state's behavior into its own class and let the context delegate to the current state object. Use it when an object behaves differently in many states or a class is polluted with large conditionals.[1]

Example

java design-patterns/examples/StateDemo.java
draft: sending to moderation
  state -> Moderation
moderation: approved, publishing
  state -> Published
published: already public, ignoring
published: already public, ignoring
published: cannot reject a public document

The same publish() call does different things in Draft, Moderation and Published, and each state decides the next one. Source: StateDemo.java. Key difference from Strategy: "particular states may be aware of each other and initiate transitions from one state to another, whereas strategies almost never know about each other."[1] For a small fixed set of states, an enum with constant-specific behavior is a lighter option.

Pros and cons

Pros

  • Single Responsibility and Open/Closed
  • Eliminates bulky conditionals

Cons

  • Overkill for a few states or rare changes

(From the pattern's page.)[1] State, Strategy and Bridge share a composition-based structure but solve different problems.
