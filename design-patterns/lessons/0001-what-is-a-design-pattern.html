What is a design pattern?

Design Patterns · Lesson 0001 · step 1 of 30 · Foundation · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: define a design pattern, say what it is not, and name the parts of a pattern description.

Definition

"Design patterns are typical solutions to commonly occurring problems in software design." They are customizable blueprints, not ready-made code you copy. Unlike an algorithm, which "always defines a clear set of actions that can achieve some goal", "a pattern is a more high-level description of a solution": the same pattern can look very different in different programs.[1]

How a pattern is described

  • Intent: the problem and solution in brief.
  • Motivation: the problem in depth and how the pattern solves it.
  • Structure: classes and their relationships.
  • Code example in a real language.[1]

This course follows that shape: each lesson gives the intent, a runnable Java example (verified on JDK 21), pros and cons, related patterns, and where you meet it in the JDK.

Prerequisites

Patterns are built from OOP basics: interfaces, polymorphism, composition, encapsulation. If those feel shaky, do the OOP ladder first, especially interfaces, composition and the SOLID lessons.

Try the JDK map first: run PatternsInJdkDemo.java to see twelve patterns you already use.
