Abstract Factory

Design Patterns · Lesson 0005 · step 5 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: create families of related objects that always match, without naming concrete classes.

Intent

Abstract Factory is "a creational design pattern that lets you produce families of related objects without specifying their concrete classes." Use it when code must work with various families of related products, or when a class has several factory methods that blur its main responsibility.[1]

Example

A GuiFactory creates a button and a checkbox. Each factory makes a matching pair, so a dark button can never be combined with a light checkbox through the interface.

java design-patterns/examples/AbstractFactoryDemo.java
dark-button + dark-checkbox
light-button + light-checkbox

Source: AbstractFactoryDemo.java.

Pros and cons

Pros

  • Products from one factory are compatible with each other
  • Client code is decoupled from concrete products
  • Single Responsibility and Open/Closed benefits

Cons

  • Considerable complexity: many interfaces and classes

(From the pattern's page.)[1] Abstract Factory is based on a set of Factory Methods, pairs well with Bridge, and its factories are often Singletons; it is an alternative to Facade when you only want to hide object creation.
