Pattern trong Java hiện đại: lambda, record, sealed type

Design Patterns · Bài 0028 · bước 28/30 · Advanced · ~12 phút · Trang chủ · Lộ trình Design Patterns · Lộ trình tổng · English

Thành quả hôm nay: giải thích được những pattern kinh điển nào co lại hoặc biến mất nhờ lambda, record, enum và sealed type.

Lời chỉ trích đầu tiên nhắm vào pattern là có những pattern chỉ để bù đắp cho giới hạn của ngôn ngữ.[1] Java hiện đại đã dẹp bỏ được khá nhiều thủ tục rườm rà.

PatternKiểu kinh điểnJava hiện đại
Strategyinterface + N classmột lambda hoặc method reference cho interface chỉ có một method (chính trang Strategy cũng ghi rằng ngôn ngữ hàm có thể khiến pattern này trở nên thừa)[1]
Commandmỗi command một classRunnable/lambda (vẫn dùng class khi cần undo)
Template Methodabstract classtruyền function vào cho các bước thay đổi (gợi ý của tôi)
Visitordouble dispatch accept/visitsealed interface + record pattern + switch: compiler kiểm tra tính exhaustive[2][3]
Singletonprivate constructor + staticenum một phần tử, hoặc một bean do container quản lý
Builderfluent builderrecord với compact constructor cho dữ liệu nhỏ; builder vẫn cần khi có nhiều tham số tùy chọn
Statecác state classenum có hành vi, hoặc sealed type + switch

Các ví dụ đã kiểm chứng trong khóa học: strategy bằng lambda (StrategyDemo.java), visitor bằng sealed/pattern switch (VisitorDemo.java), enum singleton và strategy theo từng hằng (SingletonDemo.java, EnumsAsClasses.java). JEP 441 nói rằng pattern switch phải exhaustive và, trên một hệ phân cấp sealed, độ bao phủ được compiler kiểm tra, đôi khi không cần đến default nữa.[2]

Câu nói khi phỏng vấn: "Pattern là vốn từ vựng chung. Với Java 21 tôi thường dùng lambda thay cho một Strategy class, hoặc sealed interface với switch thay cho Visitor, nhưng tôi vẫn gọi tên pattern để cả team hiểu thiết kế."

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Một Strategy chỉ có một method có thể là...?

Functional interface nhận được lambda.[1]

2. Thứ thay thế Visitor trong Java hiện đại?

Pattern matching exhaustive trên một hệ phân cấp sealed.[2]

3. Với sealed switch, compiler kiểm tra gì?

Độ bao phủ được kiểm tra dựa trên các subtype được permit.[2]

4. Pattern có biến mất hoàn toàn không?

Chúng gọn lại nhưng vẫn là vốn từ vựng chung.
