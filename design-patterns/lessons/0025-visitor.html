Visitor

Design Patterns · Lesson 0025 · step 25 of 30 · Advanced · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: add operations to a class hierarchy without changing it, and compare classic double dispatch with JDK 21 pattern matching.

Intent

Visitor is "a behavioral design pattern that lets you separate algorithms from the objects on which they operate." It uses double dispatch to run operations on objects of different classes without modifying them. Use it for operations on complex object structures, to extract auxiliary behavior, or for behavior that only applies to some classes.[1]

Example

java design-patterns/examples/VisitorDemo.java
Circle area=3.14 perimeter=6.28
Rect area=6.00 perimeter=10.00
switch: Circle area=3.14
switch: Rect area=6.00

accept(visitor) calls the right visit overload (double dispatch); AreaVisitor and PerimeterVisitor add operations without editing the shapes. The last two lines do the same with a sealed interface and a pattern-matching switch (JDK 21), where the compiler checks that all cases are covered ("Pattern switches must be exhaustive" for sealed types: JDK 21 lesson). In the JDK, FileVisitor is "a visitor of files ... provided to the Files.walkFileTree methods" with preVisitDirectory, visitFile, visitFileFailed and postVisitDirectory.[2] Source: VisitorDemo.java.

Pros and cons

Pros

  • Open/Closed: add behaviors without changing element classes
  • Single Responsibility: related operations in one visitor
  • Visitors can accumulate state while traversing

Cons

  • Every visitor must be updated when element types change
  • Visitors may lack access to private members

(From the pattern's page.)[1] Visitor works with Composite (operate on a whole tree), Iterator (navigation) and Command.

Retrieval practice

Answer from memory. One attempt each.

2. Double dispatch means...?

accept picks the visit overload from the element's type.

3. Drawback?

4. Modern Java alternative?

The demo's switch over a sealed interface.
