Prototype

Design Patterns · Lesson 0007 · step 7 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: copy an existing configured object, and choose between shallow and deep copies.

Intent

Prototype is "a creational design pattern that lets you copy existing objects without making your code dependent on their classes." Use it when your code should not depend on concrete classes it copies, or to avoid subclasses that differ only in initialization by cloning pre-built configured objects.[1]

Example

java design-patterns/examples/PrototypeDemo.java
template : orc(hp=100, items=[club, shield])
shallow  : orc-2(hp=100, items=[club, shield])   <- shares the SAME list object
deep     : orc-3(hp=100, items=[club])   <- has its own list

The shallow copy shares the template's list, so a later change to the template appears in the copy; the deep copy owns its list. Java's built-in mechanism is Cloneable/Object.clone; copy constructors or copy methods (as here) are usually clearer (my recommendation; the pattern page is language-neutral). Source: PrototypeDemo.java. Link: immutability and defensive copies.

Pros and cons

Pros

  • Clone objects independently of their concrete class
  • Avoid repeated initialization by cloning templates
  • Alternative to inheritance for configuration presets

Cons

  • Copying complex objects with circular references is hard

(From the pattern's page.)[1] It can replace Memento for simple state snapshots, help Command keep history, and speed up Composite/Decorator-heavy designs by cloning structures.
