Choosing between similar patterns

Design Patterns · Lesson 0026 · step 26 of 30 · Advanced · ~12 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: tell apart the pattern pairs that look alike in code but differ in intent.

Many patterns share a class shape (an object holds another object behind an interface). What differs is intent, and interviewers love these comparisons. All statements below come from the patterns' own pages.

PairDifference
Strategy vs StateBoth use composition. "Particular states may be aware of each other and initiate transitions ... whereas strategies almost never know about each other."[2] Strategy is chosen by the client; State changes itself.
Strategy vs Template MethodTemplate Method uses inheritance (static, class level); Strategy uses composition (runtime).[1]
Decorator vs StrategyDecorator changes an object's "skin" (outward behavior), Strategy changes its "guts".[3]
Decorator vs ProxyBoth keep the interface. A Decorator's composition is controlled by the client; a Proxy typically manages its service object's lifecycle.[4] Decorator adds responsibilities, Proxy controls access.
Adapter vs Decorator vs Proxy vs FacadeAdapter changes the interface; Decorator keeps or extends it; Proxy keeps it identical; Facade defines a new simplified interface for a whole subsystem.[3][4]
Mediator vs ObserverMediator removes mutual dependencies by making components depend on one mediator; Observer creates dynamic one-way subscriptions. A mediator can be built with Observer.[5]

Decision questions

  1. Am I creating, assembling or coordinating? (the three categories)
  2. Does the client choose the variation, or does the object change itself over time?
  3. Do I need the same interface (Decorator/Proxy) or a different one (Adapter/Facade)?
  4. Is the variation known at compile time (inheritance) or runtime (composition)?

Run the Strategy and State demos side by side and see which object decides what happens next.

Retrieval practice

Answer from memory. One attempt each.

1. Which pair differs by who initiates change?

States trigger transitions; strategies are independent.[2]

2. Same interface, controls access?

Proxy keeps the interface identical for access control and lifecycle.[4]

3. Changes the interface?

Adapter provides a different interface.[3]

4. Inheritance-based algorithm variation?

Template Method is static and inheritance-based.[1]
