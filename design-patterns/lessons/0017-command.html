Command

Design Patterns · Lesson 0017 · step 17 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: turn a request into an object so it can be queued, logged and undone.

Intent

Command is "a behavioral design pattern that turns a request into a stand-alone object that contains all information about the request." Use it to parameterize objects with operations, to queue, schedule or execute operations remotely, and to implement reversible operations with a history.[1]

Example

java design-patterns/examples/CommandDemo.java
append(Hello) -> "Hello"
append(, world) -> "Hello, world"
upper -> "HELLO, WORLD"
undo upper -> "Hello, world"
undo append(, world) -> "Hello"
undo append(Hello) -> ""
a Runnable is a one-method Command

Each command knows how to execute() and undo(); a Deque of executed commands gives a history that is undone in reverse order. In Java a Runnable is a one-method command. Source: CommandDemo.java. Compare job queues (Kafka/RabbitMQ messages are commands or events in transit: load leveling).

Pros and cons

Pros

  • Separates invokers from performers
  • Open/Closed: add commands freely
  • Undo/redo and deferred execution
  • Compose simple commands into complex ones

Cons

  • An extra layer between senders and receivers

(From the pattern's page.)[1] Command pairs with Memento for undo, differs from Strategy (an operation as an object versus a family of algorithms), and relates to Chain of Responsibility, Mediator and Observer.
