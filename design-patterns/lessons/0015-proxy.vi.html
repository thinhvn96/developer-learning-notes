Proxy

Design Patterns · Bài 0015 · bước 15/30 · Core · ~10 phút · Trang chủ · Lộ trình Design Patterns · Lộ trình tổng · English

Thành quả hôm nay: tạo một object đứng thế có cùng interface (lazy, logging, bảo vệ) và viết được một JDK dynamic proxy.

Mục đích

Proxy là "một structural design pattern cho phép bạn cung cấp một vật thay thế hoặc giữ chỗ cho một object khác." Các loại: khởi tạo lazy (virtual proxy), kiểm soát truy cập (protection proxy), remote proxy, logging proxy, caching proxy, smart reference.[1]

Ví dụ

java design-patterns/examples/ProxyDemo.java
--- virtual (lazy) proxy
proxy created, nothing loaded yet
  loading big.png from disk (expensive)
  showing image
  showing image
--- JDK dynamic proxy adding logging to ANY interface
  -> calling compute[20, 22]
  <- returned 42
proxy class name starts with: $Proxy

Proxy LazyImage chỉ nạp ảnh thật ở lần gọi show() đầu tiên. JDK có thể tạo proxy lúc runtime: theo tài liệu, "proxy class là class được tạo ra lúc runtime, implement một danh sách interface được chỉ định"; mỗi lời gọi được chuyển tới method invoke của một InvocationHandler.[2] Ở đây một handler duy nhất thêm logging cho bất kỳ interface nào. Mã nguồn: ProxyDemo.java.

Bạn đã gặp nó rồi: @Transactional của Spring hoạt động thông qua một proxy, đó là lý do gọi một method transactional qua this sẽ đi vòng qua transaction (đã kiểm chứng trong bài Spring: 2 account được lưu thay vì bị rollback).

Ưu và nhược điểm

Ưu điểm

  • Kiểm soát service object mà client không hề biết
  • Quản lý vòng đời của service
  • Vẫn hoạt động ngay cả khi service chưa sẵn sàng
  • Open/Closed: thêm proxy mới mà không sửa service hay client

Nhược điểm

  • Thêm class và độ phức tạp
  • Có thể làm response chậm hơn

(Theo trang mô tả pattern.)[1] Adapter đưa ra interface khác; Facade bọc cả subsystem; việc ghép Decorator do client điều khiển, còn proxy thường tự quản lý toàn bộ vòng đời của service object.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Một proxy có...?

Nó là vật thay thế cho một object khác.[1]

2. Lazy proxy trì hoãn...?

Khởi tạo lazy tạo service object khi cần đến.[1]

3. Class JDK để tạo proxy lúc runtime?

Proxy.newProxyInstance tạo ra chúng.[2]

4. Vì sao self-invocation bỏ qua @Transactional?

Lời gọi không đi qua proxy object.
