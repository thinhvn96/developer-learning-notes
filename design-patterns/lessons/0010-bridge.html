Bridge

Design Patterns · Lesson 0010 · step 10 of 30 · Advanced · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: split a class with two independent dimensions of variation into two hierarchies connected by composition.

Intent

Bridge is "a structural design pattern that lets you split a large class or a set of closely related classes into two separate hierarchies (abstraction and implementation) which can be developed independently of each other." Use it to divide a monolithic class with several variants, to extend a class in several orthogonal dimensions, or to switch implementations at runtime.[1]

Example

java design-patterns/examples/BridgeDemo.java
Remote toggled TV, on=true
AdvancedRemote toggled Radio, on=true
AdvancedRemote muted Radio
2 remote types x 2 device types = 4 combinations from 4 classes; a third device adds ONE class, not two

Remote (abstraction) holds a Device (implementation). Remote types and device types vary independently: two of each gives four combinations from four classes, and a third device adds one class instead of two. This is composition over inheritance at scale (OOP lesson). Source: BridgeDemo.java.

Pros and cons

Pros

  • Platform-independent classes and applications
  • Client works with high-level abstractions
  • Open/Closed and Single Responsibility benefits

Cons

  • More complicated if applied to a highly cohesive class

(From the pattern's page.)[1] Bridge is usually designed up front while Adapter retrofits; it shares structure with State and Strategy but solves a different problem; it pairs with Abstract Factory.
