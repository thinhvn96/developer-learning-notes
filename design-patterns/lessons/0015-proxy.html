Proxy

Design Patterns · Lesson 0015 · step 15 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: provide a stand-in with the same interface (lazy, logging, protection) and write a JDK dynamic proxy.

Intent

Proxy is "a structural design pattern that lets you provide a substitute or placeholder for another object." Kinds: lazy initialization (virtual proxy), access control (protection proxy), remote proxy, logging proxy, caching proxy, smart reference.[1]

Example

java design-patterns/examples/ProxyDemo.java
--- virtual (lazy) proxy
proxy created, nothing loaded yet
  loading big.png from disk (expensive)
  showing image
  showing image
--- JDK dynamic proxy adding logging to ANY interface
  -> calling compute[20, 22]
  <- returned 42
proxy class name starts with: $Proxy

The LazyImage proxy loads the real image on first show(). The JDK can create proxies at runtime: "A proxy class is a class created at runtime that implements a specified list of interfaces"; each call is dispatched to an InvocationHandler's invoke.[2] Here one handler adds logging to any interface. Source: ProxyDemo.java.

You have already met this: Spring's @Transactional works through a proxy, which is why calling a transactional method on this bypasses the transaction (verified in the Spring lesson: 2 accounts saved instead of rolled back).

Pros and cons

Pros

  • Controls the service object without clients knowing
  • Manages the service's lifecycle
  • Works even when the service is unavailable
  • Open/Closed: new proxies without changing service or clients

Cons

  • More classes and complexity
  • May delay responses

(From the pattern's page.)[1] Adapter gives a different interface; Facade wraps subsystems; Decorator's composition is controlled by the client, while a proxy usually manages its service object's whole lifecycle.

Retrieval practice

Answer from memory. One attempt each.

1. A proxy has...?

It is a substitute for another object.[1]

2. Lazy proxy delays...?

Lazy initialization creates the service object when needed.[1]

3. JDK class for runtime proxies?

Proxy.newProxyInstance creates them.[2]

4. Why did self-invocation skip @Transactional?

The call did not go through the proxy object.
