Chain of Responsibility

Design Patterns · Lesson 0016 · step 16 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: pass a request through handlers that each decide to handle it or pass it on.

Intent

Chain of Responsibility is "a behavioral design pattern that lets you pass requests along a chain of handlers." Use it when requests are processed in different ways and the types and order are unknown beforehand, when several handlers run in a given order, or when handlers and order change at runtime.[1]

Example

java design-patterns/examples/ChainDemo.java
200 did buy for ann
401 not authenticated
429 too many requests
unhandled

Authentication, rate limiting and business logic are separate handlers; each either returns a result (ending the chain) or passes on. The last line shows the drawback: a chain with no handler for the request returns "unhandled". Servlet filters and middleware pipelines have this shape (my general observation; the pattern page describes the idea). Source: ChainDemo.java.

Pros and cons

Pros

  • Control over the order of handling
  • Decouples invokers from performers (Single Responsibility)
  • New handlers without breaking clients (Open/Closed)

Cons

  • Some requests may end up unhandled

(From the pattern's page.)[1] Chain of Responsibility, Command, Mediator and Observer are different ways of connecting senders and receivers; it works well with Composite and shares structure with Decorator (which does not stop the chain).
