Template Method

Design Patterns · Lesson 0024 · step 24 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: fix an algorithm's skeleton in a base class and let subclasses supply steps, and spot the risks.

Intent

Template Method is "a behavioral design pattern that defines the skeleton of an algorithm in the superclass but lets subclasses override specific steps of the algorithm without changing its structure." Use it to let clients extend only particular steps, to share near-identical algorithms, and to pull duplicated code up.[1]

Example

java design-patterns/examples/TemplateMethodDemo.java
a,b|1,2|end
<h1>|<p>1</p>|</html>
AbstractList (template) gives contains/indexOf/iterator for free: [0, 1, 4, 9, 16] contains 9? true

generate() is final, so the order header, body, footer cannot change; header() and body() are abstract steps and footer() is an optional hook. In the JDK, AbstractList works this way: implement get and size and inherit the rest (shown in the run). Source: TemplateMethodDemo.java. It is the abstract-class shape from the OOP lesson; the calling-an-overridable-method-from-constructor hazard applies (initialization order).

Pros and cons

Pros

  • Clients override only chosen steps
  • Duplicate code consolidated in the superclass

Cons

  • The skeleton can be restrictive
  • Risk of violating Liskov if subclasses suppress default steps
  • Harder to maintain as steps accumulate

(From the pattern's page.)[1] Template Method is inheritance-based (static) while Strategy is composition-based; factory methods are often steps in a template method.

Retrieval practice

Answer from memory. One attempt each.

1. Who fixes the algorithm order?

The superclass defines the skeleton.[1]

2. Why make the template method final?

Subclasses override steps, not the structure.

3. Risk?

Subclasses that suppress a default step can break substitutability.[1]

4. JDK template example?

AbstractList needs only get and size.
