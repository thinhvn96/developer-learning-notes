Patterns in modern Java: lambdas, records, sealed types

Design Patterns · Lesson 0028 · step 28 of 30 · Advanced · ~12 minutes · Home · Design Patterns ladder · Roadmap

Today's win: explain which classic patterns shrink or vanish with lambdas, records, enums and sealed types.

The first criticism of patterns is that some compensate for language limits.[1] Modern Java removes much ceremony.

PatternClassicModern Java
Strategyinterface + N classesa lambda or method reference for a one-method interface (the Strategy page itself notes functional languages may make the pattern unnecessary)[1]
Commandclass per commandRunnable/lambdas (still use classes when you need undo)
Template Methodabstract classpass functions for the varying steps (my suggestion)
Visitoraccept/visit double dispatchsealed interface + record patterns + switch: exhaustive checking by the compiler[2][3]
Singletonprivate constructor + staticsingle-element enum, or a container-managed bean
Builderfluent builderrecords with compact constructors for small data; builders remain for many optional parameters
Statestate classesenum with behavior, or sealed types + switch

Verified examples in this course: lambda strategies (StrategyDemo.java), the sealed/pattern-switch visitor (VisitorDemo.java), enum singleton and strategy-per-constant (SingletonDemo.java, EnumsAsClasses.java). JEP 441 says pattern switches must be exhaustive and, over a sealed hierarchy, coverage is checked by the compiler, sometimes removing the need for default.[2]

Interview line: "Patterns are vocabulary. In Java 21 I often reach for a lambda instead of a Strategy class, or a sealed interface with a switch instead of a Visitor, but I still name the pattern so the team understands the design."

Retrieval practice

Answer from memory. One attempt each.

1. A Strategy with one method can be...?

A functional interface accepts a lambda.[1]

2. Modern Visitor replacement?

Exhaustive pattern matching over a sealed hierarchy.[2]

3. Compiler checks what for sealed switches?

Sealed coverage is checked from the permitted subtypes.[2]

4. Do patterns disappear entirely?

They shrink but remain a shared vocabulary.
