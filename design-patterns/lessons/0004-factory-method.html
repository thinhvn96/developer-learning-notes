Factory Method

Design Patterns · Lesson 0004 · step 4 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: explain how a creator delegates the choice of concrete product to subclasses, and recognize static factory methods in the JDK.

Intent

Factory Method is "a creational design pattern that provides an interface for creating objects in a superclass, but allows subclasses to alter the type of objects that will be created." Use it when you do not know beforehand the exact types your code should work with, when you want to let library or framework users extend internal components, or to reuse existing objects.[1]

Example

Dialog.render() is written once against the Button interface; each subclass overrides createButton() to choose the product.

java design-patterns/examples/FactoryMethodDemo.java
WindowsDialog renders [Windows button]
WebDialog renders <button>
List.of(...) returns a List; concrete class chosen by the JDK: List12

Source: FactoryMethodDemo.java. Everyday cousin: static factory methods such as List.of(..) and Integer.valueOf, where the caller gets an interface type and the JDK picks the class (my run showed a List12).

Pros and cons

Pros

  • Loose coupling between the creator and concrete products
  • Single Responsibility: creation code in one place
  • Open/Closed: new product types without changing existing code

Cons

  • Code gets more complicated: many new subclasses

(From the pattern's page.)[1] It often evolves into Abstract Factory, Prototype or Builder, and relates to Template Method (a factory method is often a step in a template method).
