Iterator

Design Patterns · Lesson 0018 · step 18 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: traverse a collection without exposing its internal structure, using independent iterators.

Intent

Iterator is "a behavioral design pattern that lets you traverse elements of a collection without exposing its underlying representation (list, stack, tree, etc.)." Use it to hide complex structure, reduce duplicated traversal code, and traverse different structures uniformly.[1]

Example

java design-patterns/examples/IteratorDemo.java
3 2 1 
a is at 1, b is still at 3
removed evens via iterator: [1, 3]

Implementing Iterable is all it takes for the for-each loop to work. Two iterators over the same collection keep independent positions; Iterator.remove() is the safe way to delete while iterating (compare the ConcurrentModificationException in the list lesson). Source: IteratorDemo.java.

Pros and cons

Pros

  • Traversal extracted into its own class (Single Responsibility)
  • New collections and iterators without changing existing code
  • Parallel iteration: each iterator has its own state
  • Iteration can be paused and resumed

Cons

  • Overkill for simple collections
  • Direct access can be more efficient in specialized collections

(From the pattern's page.)[1] Iterator works with Composite (walking trees), Factory Method (collections returning different iterators), Memento (saving iteration state) and Visitor.

Retrieval practice

Answer from memory. One attempt each.

1. Iterator hides...?

Traversal without exposing the underlying representation.[1]

2. What lets for-each work on your class?

Iterable supplies an iterator to the for-each loop.

3. Two iterators on one collection...?

a and b in the demo were at different positions.[1]

4. Safe removal while iterating?

Iterator.remove removed evens without an exception.
