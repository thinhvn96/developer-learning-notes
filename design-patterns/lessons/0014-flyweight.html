Flyweight

Design Patterns · Lesson 0014 · step 14 of 30 · Advanced · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: separate intrinsic (shared) from extrinsic (contextual) state to save memory, and explain the Integer cache.

Intent

Flyweight is "a structural design pattern that lets you fit more objects into the available amount of RAM by sharing common parts of state between multiple objects instead of keeping all of the data in each object." Intrinsic state is constant data kept in the flyweight; extrinsic state is contextual and stored outside. Apply it only when you have a huge number of similar objects that consume significant RAM.[1]

Example

java design-patterns/examples/FlyweightDemo.java
Integer cache: valueOf(127)==valueOf(127) is true, valueOf(1000)==valueOf(1000) is false
characters placed: 11, distinct glyph objects created: 8

Eleven characters share eight distinct Glyph objects; the position (extrinsic state) lives in Placed. The JDK's Integer.valueOf "will always cache values in the range -128 to 127, inclusive": so valueOf(127) == valueOf(127) but valueOf(1000) != valueOf(1000), and the Integer(int) constructor is deprecated in favor of it.[2] Lesson: compare boxed values with equals (equals/hashCode). Source: FlyweightDemo.java.

Pros and cons

Pros

  • Substantial RAM savings for many similar objects

Cons

  • Trades memory for CPU (recomputing context)
  • More complex code

(From the pattern's page.)[1] Flyweights are immutable and can be many, unlike a Singleton; it complements Composite (shared leaf nodes).

Retrieval practice

Answer from memory. One attempt each.

1. Intrinsic state is...?

It stays in the flyweight, shareable.[1]

2. Integer cache range?

valueOf always caches -128 to 127.[2]

3. Cost of Flyweight?

It trades memory efficiency for CPU cycles.[1]

4. valueOf(1000) == valueOf(1000)?

The demo printed false: outside the guaranteed cache range.
