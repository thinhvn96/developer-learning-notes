Talking about patterns in interviews

Design Patterns · Lesson 0030 · step 30 of 30 · Senior · ~12 minutes · Home · Design Patterns ladder · Roadmap

Today's win: answer 'which pattern would you use and why?' with a problem-first, trade-off-aware structure.

A four-step answer

  1. Name the problem in plain words ("the algorithm varies at runtime").
  2. Name the pattern and its intent in one sentence (the pattern pages' Intent lines are good models).[2]
  3. Show the shape: which interface, which objects hold which.
  4. State the trade-off: every pattern page lists cons (more classes, ordering issues, god-object risk...). Mention the simpler alternative (a lambda, an enum, a plain method).[1]

Traps to avoid

  • Reciting names without a problem: the "hammer and nail" criticism.[1]
  • Implementing "to the letter" without adapting to context.[1]
  • Singleton as the default answer for shared state (testing cost: see the Singleton lesson).
  • Inheritance where composition fits (OOP lesson).

Practice

Use the interview page for questions with detailed answers, and pick two problems from your own code to describe using the four steps. Ask your teacher for a mock interview: "give me a scenario, I'll name the pattern".

Retrieval practice

Answer from memory. One attempt each.

1. First step of a good pattern answer?

Problem first, then pattern.

2. What should every answer include?

Pattern pages list cons; state them.[1]

3. Hammer-and-nail warns against...?

Applying patterns indiscriminately.[1]

4. A simpler alternative to Strategy?

For a one-method interface, a lambda often suffices.
