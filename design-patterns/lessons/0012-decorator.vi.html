Decorator

Design Patterns · Bài 0012 · bước 12/30 · Core · ~10 phút · Trang chủ · Lộ trình Design Patterns · Lộ trình tổng · English

Thành quả hôm nay: thêm hành vi bằng cách bọc một object trong một object khác có cùng interface, và nhận ra các decorator trong JDK.

Mục đích

Decorator là "một structural design pattern cho phép bạn gắn thêm hành vi mới cho object bằng cách đặt object đó vào trong những wrapper object đặc biệt chứa các hành vi này." Hãy dùng nó để gán thêm hành vi lúc runtime mà không làm hỏng code có sẵn, và khi mở rộng bằng kế thừa thì vướng víu hoặc không thể (class final).[1]

Ví dụ

java design-patterns/examples/DecoratorDemo.java
espresso + sugar + milk = 4
espresso + sugar + sugar = 3
BufferedReader: line1 | line2
unmodifiable view reads through: [a, b]
writes rejected by the wrapper

Mỗi decorator implement Coffee và giữ một Coffee, bổ sung vào phần mô tả và giá; các lớp bọc có thể lặp lại. Decorator trong JDK: BufferedReader bọc bất kỳ reader nào ("đọc văn bản từ một character-input stream, có đệm các ký tự"),[2] và Collections.unmodifiableList trả về một wrapper mà thao tác đọc "đọc xuyên qua" tới list phía sau, còn thao tác sửa thì ném UnsupportedOperationException[3] (đây là wrapper/view: tôi xếp nó vào loại wrapper kiểu decorator). Mã nguồn: DecoratorDemo.java.

Ưu và nhược điểm

Ưu điểm

  • Mở rộng hành vi mà không cần subclass mới
  • Thêm hoặc bỏ trách nhiệm lúc runtime
  • Kết hợp hành vi bằng cách chồng nhiều wrapper
  • Class nhỏ, tập trung

Nhược điểm

  • Khó gỡ một wrapper cụ thể ra khỏi chồng
  • Hành vi có thể phụ thuộc vào thứ tự chồng
  • Code cấu hình có thể trở nên lộn xộn

(Theo trang mô tả pattern.)[1] Adapter thay đổi interface, Decorator giữ nguyên hoặc mở rộng nó, Proxy giữ y hệt; Strategy thay đổi "ruột" của object, Decorator thay đổi "vỏ".

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Một decorator implement...?

Nó bọc một object mà vẫn giữ nguyên interface.[1]

2. Decorator so với Strategy?

Strategy đổi phần ruột; Decorator đổi phần vỏ.[1]

3. Decorator trong JDK?

BufferedReader bọc một reader khác.[2]

4. Nhược điểm?

Hành vi có thể phụ thuộc vào thứ tự các wrapper.[1]
