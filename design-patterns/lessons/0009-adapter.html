Adapter

Design Patterns · Lesson 0009 · step 9 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: wrap an incompatible class so it fits the interface your client expects, and recognize Arrays.asList as an adapter.

Intent

Adapter is "a structural design pattern that allows objects with incompatible interfaces to collaborate." Use it when you want to use an existing class whose interface does not match your code, or reuse several subclasses that lack common functionality.[1]

Example

java design-patterns/examples/AdapterDemo.java
legacy printed 5 bytes: hello
array=[x, y, c] view=[x, y, c]
fixed-size: add() unsupported

LegacyAdapter implements the Printer the client expects and translates the call into the legacy class's different method and arguments. In the JDK, Arrays.asList "acts as bridge between array-based and collection-based APIs": a fixed-size list backed by the array, with write-through in both directions (shown above); adding throws UnsupportedOperationException.[2] Source: AdapterDemo.java.

Pros and cons

Pros

  • Separates interface or data conversion from business logic
  • New adapters can be introduced without breaking client code

Cons

  • More interfaces and classes; sometimes simpler to change the service class directly

(From the pattern's page.)[1] Adapter retrofits existing classes (Bridge is designed up front); Decorator keeps or extends the interface while Adapter changes it; Proxy keeps it identical; Facade defines a new interface for a whole subsystem, where an Adapter usually wraps one object.
