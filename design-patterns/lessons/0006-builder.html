Builder

Design Patterns · Lesson 0006 · step 6 of 30 · Core · ~10 minutes · Home · Design Patterns ladder · Roadmap · Tiếng Việt

Today's win: replace a telescoping constructor with a builder and validate in build().

Intent

Builder is "a creational design pattern that lets you construct complex objects step by step." It addresses the telescoping-constructor problem (many optional parameters), constructs different representations with the same steps, and builds composite trees without exposing incomplete products.[1]

Example

java design-patterns/examples/BuilderDemo.java
Pizza(large, cheese=true, pepperoni=false, mushrooms=true, olives=false, extra=2)
Pizza(large, cheese=true, pepperoni=false, mushrooms=true, olives=false, extra=2)
StringBuilder is the JDK's best-known builder: a1!
build() validates: size is required

Compare the constructor call with the fluent builder: only the steps you want are written, and build() is the single place to validate. Source: BuilderDemo.java. The builder is a static nested class (OOP lesson). In the JDK: StringBuilder and HttpRequest.newBuilder(); for simple immutable data, records plus a compact constructor (lesson) are often enough.

Pros and cons

Pros

  • Step-by-step construction, deferrable or recursive
  • Reuses construction code across representations
  • Isolates complex construction logic (Single Responsibility)

Cons

  • More classes and code complexity

(From the pattern's page.)[1] Factory Method is simpler but less flexible; Abstract Factory returns products immediately while Builder allows extra steps; Builder pairs with Composite to build trees.

Retrieval practice

Answer from memory. One attempt each.

1. Builder solves which problem?

Constructors that accumulate many optional parameters.[1]

2. Where do you validate?

The demo threw from build() when size was blank.

3. Builder vs Abstract Factory?

Abstract Factory returns products immediately; Builder allows additional steps.[1]

4. Cost?

It increases code complexity through new classes.[1]
