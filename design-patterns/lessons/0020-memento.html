Memento

Design Patterns · Lesson 0020 · step 20 of 30 · Advanced · ~10 minutes · Home · Design Patterns ladder · Roadmap

Today's win: save and restore an object's state without exposing its internals.

Intent

Memento is "a behavioral design pattern that lets you save and restore the previous state of an object without revealing the details of its implementation." Use it to create snapshots for restoring, to roll back on errors, and to protect encapsulation.[1]

Example

java design-patterns/examples/MementoDemo.java
now      : Hello, world!!!
restore 1: Hello, world
restore 2: Hello

The editor (originator) creates opaque Snapshot objects; the history stack (caretaker) stores them but cannot read their state. Source: MementoDemo.java. Pair with Command for undo.

Pros and cons

Pros

  • Snapshots without violating encapsulation
  • Originator code simplified: the caretaker keeps history

Cons

  • Frequent snapshots use memory
  • Caretakers must track and destroy obsolete mementos

(From the pattern's page.)[1] Memento works with Command (undo) and Iterator (saving iteration state); Prototype can be a simpler alternative for simple objects.

Retrieval practice

Answer from memory. One attempt each.

1. Memento saves...?

It saves and restores previous state.[1]

2. Who stores the snapshots?

The history stack in the demo.

3. Why not expose fields?

Snapshots are created without violating encapsulation.[1]

4. Cost?

Frequent mementos can consume significant memory.[1]
