Command

Design Patterns · Bài 0017 · bước 17/30 · Core · ~10 phút · Trang chủ · Lộ trình Design Patterns · Lộ trình tổng · English

Thành quả hôm nay: biến một request thành object để có thể đưa vào queue, ghi log và undo.

Mục đích

Command là "một behavioral design pattern biến một request thành một object độc lập chứa toàn bộ thông tin về request đó." Hãy dùng nó để tham số hóa object bằng các thao tác, để đưa thao tác vào queue, lên lịch hoặc thực thi từ xa, và để cài đặt các thao tác có thể đảo ngược kèm lịch sử.[1]

Ví dụ

java design-patterns/examples/CommandDemo.java
append(Hello) -> "Hello"
append(, world) -> "Hello, world"
upper -> "HELLO, WORLD"
undo upper -> "Hello, world"
undo append(, world) -> "Hello"
undo append(Hello) -> ""
a Runnable is a one-method Command

Mỗi command biết cách execute() và undo(); một Deque chứa các command đã thực thi tạo thành lịch sử, được undo theo thứ tự ngược lại. Trong Java, một Runnable chính là một command chỉ có một method. Mã nguồn: CommandDemo.java. So sánh với job queue (message trong Kafka/RabbitMQ là các command hoặc event đang trên đường đi: load leveling).

Ưu và nhược điểm

Ưu điểm

  • Tách bên gọi khỏi bên thực hiện
  • Open/Closed: thoải mái thêm command
  • Undo/redo và thực thi trì hoãn
  • Ghép command đơn giản thành command phức tạp

Nhược điểm

  • Thêm một tầng giữa bên gửi và bên nhận

(Theo trang mô tả pattern.)[1] Command đi cùng Memento để làm undo, khác với Strategy (một thao tác dưới dạng object so với một họ thuật toán), và có liên quan tới Chain of Responsibility, Mediator và Observer.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Command biến một request thành...?

Một object độc lập chứa toàn bộ thông tin về request.[1]

2. Nó giúp có được tính năng nào?

Lịch sử command hỗ trợ undo/redo.[1]

3. Ví dụ trong JDK?

Runnable là một request dưới dạng object.

4. Cái giá phải trả?

Nó thêm một tầng giữa bên gửi và bên nhận.[1]
