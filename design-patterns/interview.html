Design-pattern interview questions with detailed answers, each backed by a runnable Java example in the ladder and a Refactoring.Guru intent line.

Try answering out loud first, then open the answer. Superscript links go to the source that backs the claim.

1.What is a design pattern, and when would you NOT use one?

Short answer: a typical, reusable solution blueprint to a commonly occurring design problem; not code you paste and not always warranted.

[1] Criticisms: patterns can be workarounds for weak language abstraction, can be implemented "to the letter" without adapting to context, and get applied by novices to everything ("If all you have is a hammer, everything looks like a nail").[2] Do not use one when a simpler design (a lambda, an enum, a plain method) solves the problem.

Likely follow-up: Name a pattern that modern Java makes almost trivial. (Strategy via lambdas.)

Learn it: Criticism

2.Classify the GoF patterns.

Short answer: creational (5), structural (7), behavioral (10).

[3] Creational: Factory Method, Abstract Factory, Builder, Prototype, Singleton. Structural: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy. Behavioral: Chain of Responsibility, Command, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor.

Likely follow-up: Which category solves 'how do these objects collaborate'? (Behavioral.)

Learn it: Catalog

3.Factory Method versus Abstract Factory versus Builder?

Short answer: Factory Method: a superclass method that subclasses override to choose one product; Abstract Factory: a family of related products from one factory; Builder: step-by-step construction of one complex object.

[4][5][6] Abstract Factory returns products immediately; Builder allows extra steps. Abstract Factory is often built from Factory Methods. In my demos: a dialog choosing a button, a GUI factory producing matching button and checkbox, a pizza builder replacing a 6-argument constructor.

Likely follow-up: Which for 12 optional parameters? (Builder, or a record if data is simple.)

Learn it: Builder

4.Implement a thread-safe Singleton in Java. What are the downsides?

Short answer: single-element enum or a lazy holder class; downsides are hidden global state and hard testing.

[7] My demo confirmed one instance across 8 threads for the holder idiom and showed mutable state leaking between "tests". The pattern violates SRP (two problems at once) and needs care in multithreaded code.[7] The JDK's Runtime is a documented single instance.[8] Spring's singleton scope is per container, not per class loader.[9]

Likely follow-up: Alternative? (Dependency injection with container-managed scope.)

Learn it: Singleton

5.What is the Prototype pattern? Shallow versus deep copy?

Short answer: copy an existing configured object without depending on its class; a shallow copy shares nested objects, a deep copy duplicates them.

[10] My demo: after the template's list changed, the shallow copy showed the change and the deep copy did not.

Likely follow-up: Cloneable pitfalls? (Prefer copy constructors; a general Java caution.)

Learn it: Prototype

6.Adapter versus Decorator versus Proxy versus Facade?

Short answer: Adapter changes the interface, Decorator keeps or extends it to add behavior, Proxy keeps it to control access, Facade offers a new simpler interface to a subsystem.

[12][13][14][15] Adapter usually wraps one object, Facade a whole subsystem; a Decorator's composition is controlled by the client, while a Proxy usually manages its service object's lifecycle. JDK: Arrays.asList (adapter), BufferedReader (decorator), java.lang.reflect.Proxy.[16]

Likely follow-up: Which is @Transactional? (Proxy.[11])

Learn it: Choosing between similar patterns

7.Explain Decorator with an example, and its drawbacks.

Short answer: wrap an object in another with the same interface to add behavior; stack wrappers to combine.

[13] Drawbacks: hard to remove one wrapper, order dependence, messy configuration. My coffee example priced stacked milk and sugar; JDK examples: BufferedReader(new StringReader(..)) and Collections.unmodifiableList (a read-through view).

Likely follow-up: Decorator vs inheritance? (Runtime combination vs compile-time subclass explosion.)

Learn it: Decorator

8.What does the Proxy pattern give you, and where is it used in Spring?

Short answer: a stand-in with the same interface: lazy loading, access control, logging, caching, remote access.

[14] JDK dynamic proxies dispatch calls to an InvocationHandler.[16] Spring's @Transactional uses proxies: only external calls through the proxy are intercepted, so my self-invocation test saved 2 accounts instead of rolling back.[11]

Likely follow-up: How do you fix self-invocation? (Call through another bean, or use AspectJ mode.[11])

Learn it: Proxy

9.What is the Composite pattern and where does it fit?

Short answer: a tree of parts and wholes handled through one interface.

[17] My folder/file example computed sizes recursively through Node. Related: Iterator and Visitor traverse it; Builder constructs it.

Likely follow-up: Composite vs Decorator? (Composite aggregates children; Decorator wraps one object.)

Learn it: Composite

10.Explain Strategy, and when a lambda replaces it.

Short answer: a family of interchangeable algorithms behind one interface, chosen at runtime.

[19] Comparator is the JDK's strategy.[20] For a single-method interface a lambda is enough (the page notes functional languages can make the pattern unnecessary).[19]

Likely follow-up: Strategy vs State? (States know each other and trigger transitions.[18])

Learn it: Strategy

11.State versus Strategy?

Short answer: same shape, different intent: State changes behavior as internal state changes and states trigger transitions; Strategy is chosen from outside and strategies do not know each other.

[18][19] My document example moved Draft to Moderation to Published on repeated publish() calls.

Likely follow-up: State machine with few states? (An enum may be enough.)

Learn it: State

12.Observer: how does it work, why is java.util.Observable deprecated, and what replaces it?

Short answer: a subject notifies dynamically registered subscribers; Observable was deprecated for a limited event model and unspecified notification order.

[22] The Javadoc points to java.beans, concurrent structures, and the Flow API for reactive streams.[23] Flow: Publishers, Subscribers, Subscriptions with request(n) back-pressure.[24]

Likely follow-up: Observer vs Mediator? (One-way subscriptions vs centralized two-way coordination.[21])

Learn it: Observer

13.Command pattern: why turn a request into an object?

Short answer: to queue, log, schedule and undo requests and decouple invokers from receivers.

[25] My editor kept a stack of commands and undid them in reverse; Runnable is a one-method command. Pair with Memento for undo.[26]

Likely follow-up: Command vs Strategy? (An operation as an object vs choosing an algorithm.)

Learn it: Command

14.Template Method versus Strategy?

Short answer: Template Method fixes the algorithm skeleton in a base class and lets subclasses override steps (inheritance, static); Strategy swaps whole algorithms via composition at runtime.

[27][19] Risk: subclasses suppressing default steps can violate Liskov. JDK: AbstractList.

Likely follow-up: Why make the template method final? (To protect the order of steps.)

Learn it: Template Method

15.Chain of Responsibility: give a real-world example and a downside.

Short answer: request handlers in sequence, each handling or passing on (auth, rate limit, business logic).

[28] Downside: some requests may end unhandled (my last demo line). Web filter/middleware pipelines are a common realization (general observation).

Likely follow-up: Chain vs Decorator? (A handler may stop the chain; a decorator always delegates.)

Learn it: Chain of Responsibility

16.Visitor pattern: what is double dispatch, and how does modern Java change it?

Short answer: the element's accept calls the visitor's overload for its concrete type; sealed types with pattern switches now give exhaustive checking without a visitor.

[29] Downside: every visitor changes when element types change. JDK: FileVisitor with Files.walkFileTree. My demo computed areas both ways.

Likely follow-up: When keep Visitor? (Many operations over a stable hierarchy, or when you cannot use sealed types.)

Learn it: Visitor

17.What is the Flyweight pattern? How is it used in the JDK?

Short answer: share intrinsic state among many similar objects to save memory, passing extrinsic state in.

[30] Integer.valueOf always caches -128 to 127, so == works there and fails beyond it (my run: true then false).[31] Always compare boxed values with equals.

Likely follow-up: Cost? (More CPU and complexity for less RAM.)

Learn it: Flyweight

18.How would you talk about patterns in an interview?

Short answer: problem first, then pattern and intent, then the shape, then trade-offs and the simpler alternative.

[2] Avoid name-dropping and letter-perfect implementations; state the cons each pattern page lists.

Likely follow-up: Show one example from your own project. (Prepare one per category.)

Learn it: Interview technique
