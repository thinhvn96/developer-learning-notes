Elasticsearch, Logstash, Kibana and Filebeat questions for Senior backend interviews. Outputs quoted come from the example scripts against throwaway Elasticsearch and Logstash 9.0.0 containers.

Try answering out loud first, then open the answer. Superscript links go to the source that backs the claim.

1.Explain the ELK stack and the path of a log line.

Short answer: Filebeat ships logs, Logstash parses them, Elasticsearch indexes them, Kibana explores them.

Filebeat harvesters read files line by line and inputs manage them.[1] Logstash has three stages, inputs, filters, outputs, with codecs at the edges.[2] Elasticsearch stores JSON documents in indices distributed across shards.[3] Kibana's Discover is the primary tool for exploring the data, with KQL, Lucene or ES|QL.[4] Logstash is optional when logs are already structured.

Likely follow-up: Where would you add Kafka? (As a buffer between shippers and Logstash so an Elasticsearch outage does not lose logs; design choice, not covered by the docs read.)

Learn it: ELK overview

2.What are an index, a document and a mapping? Dynamic vs explicit mapping?

Short answer: index = unit of storage; document = JSON object; mapping = field types and indexing behavior.

An index consists of documents, mappings and settings (shards, replicas, refresh interval). Use dynamic mapping for exploration and explicit mappings for production; use aliases to decouple queries from index names.[3]

Likely follow-up: text vs keyword? (text is analyzed for full-text search; keyword holds exact values for filters and aggregations; see term vs match.)

Learn it: Mappings

3.How do shards and replicas work? What can you change after creation?

Short answer: each document lives in one primary shard; replicas are copies for resilience and read capacity; primary count is fixed, replica count is not.

"Each document in an index belongs to one primary shard. A replica shard is a copy of a primary shard." Replicas protect against hardware failure and increase read capacity. "The number of primary shards in an index is fixed at the time that an index is created, but the number of replica shards can be changed at any time."[5] On a single node my index went yellow: the primary started, the replica stayed unassigned.

Likely follow-up: How would you pick a shard count? (Estimate data volume and growth; the sizing guidance goes beyond the pages read, so check the docs and say so.)

Learn it: Shards and replicas

4.Why is a document not searchable right after indexing?

Short answer: search is near real-time; documents become visible after a refresh.

"A refresh makes all operations performed on an index since the last refresh available for search." By default indices refresh every second, but only those that received a search request in the last 30 seconds.[6] In my run the count was 0 before a manual refresh and 2 after.

Likely follow-up: How do you speed up bulk indexing? (Raise or disable refresh_interval during the load; test it, see the exercise.)

Learn it: Near real-time search

5.term vs match query? What is the difference between must and filter in bool?

Short answer: match analyzes the query for text fields; term is exact and belongs on keyword fields. filter does not score and is cached; must scores.

"Avoid using the term query for text fields": analysis changes the stored tokens, so exact matches are hard; use match.[7] In bool, must and should contribute to score; filter and must_not run in filter context: score ignored, results cached.[8] Put yes/no conditions in filter and relevance text in must.

Likely follow-up: Why did my term query for 'Timeout' return nothing? (The text field was lowercased at index time; my run: term 'Timeout' 0 hits, term 'timeout' 1 hit, match 'Timeout' 1 hit.)

Learn it: Query DSL

6.What does grok do and how do you find parsing failures?

Short answer: it parses unstructured text into fields using named patterns; failures are tagged.

Patterns use %{SYNTAX:SEMANTIC}; unmatched events get the _grokparsefailure tag by default.[9] In my run an access-log line produced client, method, path, status and duration fields, while a non-matching line was tagged. Search Kibana for that tag to find bad patterns.

Likely follow-up: Multi-line stack traces? (Needs a multiline codec or shipper setting; find it in the docs, see the exercise.)

Learn it: Logstash and grok

7.What delivery guarantees do Filebeat and Logstash give?

Short answer: at-least-once for both (Filebeat always; Logstash with persistent queues).

Filebeat keeps each file's state in a registry and "guarantees that events will be delivered to the configured output at least once and with no data loss"; unacknowledged events are resent after restart, possibly duplicating.[1] Logstash persistent queues store in-flight events on disk and deliver "until delivery succeeds at least once", absorbing bursts and applying backpressure when full.[10] So design for duplicates, for example by assigning a document id from the event.

Likely follow-up: What does backpressure mean here? (Inputs are stalled until the queue drains.[10])

Learn it: Filebeat delivery

8.What is text analysis, and how do you see what tokens a field produces?

Short answer: converting text into tokens optimized for search at index and search time; use the _analyze API.

[11] The standard analyzer turned "Connection Timeout to payment-service!" into connection, timeout, to, payment, service; the keyword analyzer kept one token.

Likely follow-up: Why does exact-match search on a text field fail? (Analysis lowercases and splits; use keyword.)

Learn it: Text analysis

9.How do you index large volumes efficiently and detect failures?

Short answer: the bulk API with NDJSON; inspect per-item results.

[12] The response has an errors flag and per-item statuses; my bulk call returned 201s and a 409 version_conflict_engine_exception for a duplicate create. Also tune refresh for bulk loads.[6]

Likely follow-up: Which failures are retriable? (Discuss 429/5xx vs 4xx; exercise.)

Learn it: Bulk API

10.Explain aggregations and give an example.

Short answer: metric, bucket and pipeline aggregations; a terms bucket with average and max metrics gives per-service latency.

[13] Aggregating on a text field fails ("Fielddata is disabled"); use a keyword field.

Likely follow-up: SQL equivalent? (GROUP BY with aggregates.)

Learn it: Aggregations

11.Ingest pipeline versus Logstash?

Short answer: ingest pipelines transform one document at a time inside Elasticsearch; Logstash is a separate pipeline with many inputs/outputs and buffering.

[14] Pipelines cannot split or aggregate across documents; test with simulate. My grok pipeline parsed an access-log line and reported a failure for a non-matching one.

Likely follow-up: When would you keep Logstash? (Multiple sources/sinks, persistent queue, heavier transformations.)

Learn it: Ingest pipelines

12.What is a data stream and how does ILM manage it?

Short answer: an abstraction over hidden backing indices for append-only time series; ILM automates rollover, phases and deletion.

[15] Requires @timestamp; rollover creates a new write index. [16] Phases hot, warm, cold, frozen, delete. My run: a document without @timestamp was rejected, a rollover made ...-000002, and an ILM policy with hot rollover and delete after 30 days was accepted.

Likely follow-up: Need to update documents by id? (Use an alias with a write index, per the docs.)

Learn it: Data streams

13.What does KQL do?

Short answer: filters documents in Kibana; it does not aggregate or sort.

[17] field:value, quoted phrases, AND/OR/NOT, wildcards, ranges.

Likely follow-up: Where do counts come from? (Aggregations and dashboards.)

Learn it: KQL
