Three families

"An aggregation summarizes your data as metrics, statistics, or other analytics." Metric aggregations calculate values such as sum or average; bucket aggregations group documents into buckets by field values or ranges; pipeline aggregations take input from other aggregations.[1]

{ "aggs": { "by_service": { "terms": { "field": "service.keyword" },
    "aggs": { "avg_ms": { "avg": { "field": "ms" } }, "max_ms": { "max": { "field": "ms" } } } } } }
orders   docs=2 avg_ms=75.0  max_ms=120.0
payments docs=2 avg_ms=472.5 max_ms=900.0

Text versus keyword again

Terms on the analyzed field service was refused: "Fielddata is disabled on [service]. Text fields are not optimised for operations that require per-document field data..." (from my run). With dynamic mapping the index had a service.keyword sub-field, which I aggregated on (observed in the run; explicit mappings avoid the guesswork). Retrieval practice

Answer from memory. One attempt each.

1. Which aggregation groups documents into buckets?

Bucket aggregations group documents by values or ranges.[1]

2. Which computes an average?

Metric aggregations compute sums and averages.[1]

3. Terms aggregation on a text field...?

The run returned: Fielddata is disabled on text fields.

4. Pipeline aggregations take input from...?

They consume other aggregations' results.[1]
