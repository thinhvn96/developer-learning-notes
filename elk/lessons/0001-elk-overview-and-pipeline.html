The ELK pipeline: ship, parse, store, explore

Today's win: name the role of each ELK component and draw the path a log line takes from a file to a dashboard.

The four roles

ComponentRole
Filebeat (a Beat)reads log files and ships them: "A harvester is responsible for reading the content of a single file"; an input manages harvesters and finds sources[1]
Logstashprocessing pipeline with three stages: "inputs → filters → outputs"[2]
Elasticsearchstores JSON documents in indices, distributed across shards[3]
KibanaDiscover is "the primary tool for exploring your Elasticsearch data in Kibana"; search and filter with KQL, Lucene or ES|QL[4]

The path

app log file --Filebeat--> Logstash (grok parse) --> Elasticsearch index --> Kibana Discover

Logstash is optional when logs are already well structured; Beats can also send to Elasticsearch directly. Which layout you choose is a design decision (buffering, parsing needs), which the later lessons return to.

Run the two middle pieces

cd elk/examples && ./02-logstash-grok.sh      # parse a log line
cd elk/examples && ./01-elasticsearch-basics.sh   # index, search, shards

Both start throwaway containers (Logstash and Elasticsearch 9.0.0). Elasticsearch runs with security disabled for the demo only.
