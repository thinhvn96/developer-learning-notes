Bulk API và lỗi theo từng item

ELK Stack · Bài 0010 · bước 8/14 · Core · ~10 phút · Trang chủ · Lộ trình ELK Stack · Lộ trình tổng · English

Thành quả hôm nay: index nhiều document trong một request, và đọc kết quả của từng item thay vì tin vào HTTP status.

Vì sao dùng bulk

Bulk API thực hiện nhiều thao tác index hoặc delete trong một lần gọi; nó "giảm overhead và có thể tăng đáng kể tốc độ index". Body có định dạng NDJSON: một dòng action, tiếp theo (với index/create/update) là một dòng source; dòng cuối cùng phải kết thúc bằng ký tự xuống dòng. Các action: index (thêm hoặc thay thế), create (chỉ khi chưa tồn tại), update (cập nhật một phần), delete.[1]

Lỗi tính theo từng item

Response có cờ errors và một status cho từng item, nên cả request có thể thành công trong khi một số item lại thất bại.[1]

POST _bulk   (4 index actions, then create of an existing _id)
errors flag: True
  index 1 201 ... index 4 201
  create 1 409 version_conflict_engine_exception

Luôn kiểm tra từng item; đừng bao giờ coi "HTTP 200" là mọi thứ đã được index. Script: 03-analysis-bulk-aggs.sh. Đi cặp với tinh chỉnh refresh: khi bulk load, người ta thường tăng refresh_interval trong lúc chạy (xem bài tập).

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Định dạng body của bulk request?

API này yêu cầu JSON phân tách bằng dòng mới (newline-delimited JSON).[1]

2. Action nào thất bại nếu document đã tồn tại?

create chỉ index khi document chưa tồn tại (lần chạy trả về 409).[1]

3. Bulk trả về HTTP 200 nghĩa là...?

Status của từng item và cờ errors mới cho biết lỗi.[1]

4. Lợi ích chính của bulk?

Nó giảm overhead và tăng tốc độ index.[1]
