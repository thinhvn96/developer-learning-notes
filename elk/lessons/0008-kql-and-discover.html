Today's win: write KQL to find errors for one service, and say what KQL cannot do.

Discover

"Discover is the primary tool for exploring your Elasticsearch data in Kibana": search and filter documents, analyze field structures, visualize patterns, save findings and reuse them in dashboards. It supports KQL, Lucene or ES|QL.[2]

KQL basics

KQL is "a text-based query language for filtering data"; it "does not aggregate, transform, or sort data".[1]

NeedKQL[1]
field matches valuehttp.request.method: GET
exact phrasehttp.request.body.content: "null pointer"
boolean logicAND, OR, NOT (case-insensitive)
wildcardmachine.os: win*
rangehttp.response.bytes > 10000 and http.response.bytes <= 20000
(http.request.method: GET OR http.request.method: POST) AND http.response.status_code: 400

For a log search: level: ERROR and service: orders and message: "timeout" (assuming level and service are keyword fields and message is text, as in the mapping lesson). KQL is filtering only, so counts and percentiles belong to aggregations and dashboards.

1. Which query language filters but does not aggregate?

KQL does not aggregate, transform or sort data.[1]

2. KQL for exact phrase?

Quoted phrases match the exact term order.[1]

3. Boolean operators in KQL?

AND, OR and NOT, case-insensitive.[1]

4. Discover is for...?

It is the primary tool for exploring Elasticsearch data in Kibana.[2]
