Index lifecycle management (ILM)

ELK Stack · Bài 0014 · bước 14/14 · Senior · ~12 phút · Trang chủ · Lộ trình ELK Stack · Lộ trình tổng · English

Thành quả hôm nay: mô tả được các phase của ILM và rollover, và viết được một policy rollover ở phase hot rồi xoá dữ liệu sau 30 ngày.

ILM tự động hoá những gì

"ILM tự động hoá việc quản lý các index theo thời gian, như log và metric" để cân bằng giữa hiệu năng, khả năng chịu lỗi, thời gian lưu giữ và chi phí. Index lần lượt đi qua các phase hot, warm, cold, frozen và delete. Rollover "tạo một write index mới khi index hiện tại đạt tới một kích thước, số lượng document hoặc độ tuổi nhất định". Các action gồm rollover, shrink, force merge và delete.[1]

Một policy

PUT _ilm/policy/logs-policy
{ "policy": { "phases": {
    "hot":    { "actions": { "rollover": { "max_age": "7d", "max_primary_shard_size": "50gb" } } },
    "delete": { "min_age": "30d", "actions": { "delete": {} } } } } }
GET _ilm/policy/logs-policy  ->  hot 0ms [rollover]   delete 30d [delete]

Trong lần chạy của mình, API đã nhận và trả về đúng policy này. Gắn nó vào settings của một index template và quan sát một lần chuyển phase thật thì cần dữ liệu của nhiều ngày hoặc phải rút ngắn poll interval, việc mà mình chưa demo. Vài ý về sizing nên mang theo khi phỏng vấn: giữ shard ở kích thước dễ quản lý (các điều kiện rollover ở trên giới hạn kích thước đó), và chọn thời gian lưu giữ dựa trên yêu cầu; các con số cụ thể (như 50gb) chỉ là ví dụ, không phải khuyến nghị có trong tài liệu. Script: 04-ingest-datastream-ilm.sh. So sánh với cấu hình retention của Kafka.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Các phase của ILM?

Index đi qua các phase hot, warm, cold, frozen và delete.[1]

2. Rollover được kích hoạt bởi...?

Khi write index đạt tới một kích thước, số document hoặc độ tuổi.[1]

3. ILM quản lý loại index nào?

Nó tự động hoá việc quản lý các index theo thời gian như log và metric.[1]

4. Action nào xoá dữ liệu cũ?

Action delete xoá dữ liệu ở cuối vòng đời.[1]
