Aggregation: bucket và metric

ELK Stack · Bài 0011 · bước 9/14 · Core · ~10 phút · Trang chủ · Lộ trình ELK Stack · Lộ trình tổng · English

Thành quả hôm nay: viết được một terms aggregation có metric lồng bên trong, và giải thích vì sao aggregate trên field text lại thất bại.

Ba nhóm

"Một aggregation tóm tắt dữ liệu của bạn dưới dạng metric, thống kê hoặc các phân tích khác." Aggregation metric tính các giá trị như tổng hay trung bình; aggregation bucket gom document vào các bucket theo giá trị field hoặc theo khoảng; aggregation pipeline lấy đầu vào từ các aggregation khác.[1]

{ "aggs": { "by_service": { "terms": { "field": "service.keyword" },
    "aggs": { "avg_ms": { "avg": { "field": "ms" } }, "max_ms": { "max": { "field": "ms" } } } } } }
orders   docs=2 avg_ms=75.0  max_ms=120.0
payments docs=2 avg_ms=472.5 max_ms=900.0

Lại chuyện text và keyword

Terms trên field đã analyze service bị từ chối: "Fielddata is disabled on [service]. Text fields are not optimised for operations that require per-document field data..." (từ lần chạy của mình). Với dynamic mapping, index có sẵn sub-field service.keyword, và mình aggregate trên field đó (quan sát trong lần chạy; dùng explicit mapping thì khỏi phải đoán). Chuyện này nối với phần text analysis ở bài trước và với field keyword trong bài 5 (trang term query nói giá trị chính xác nên nằm trong field keyword).[2] Script: 03-analysis-bulk-aggs.sh. Tương đương bên SQL: GROUP BY.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Aggregation nào gom document vào bucket?

Bucket aggregation gom document theo giá trị hoặc theo khoảng.[1]

2. Loại nào tính giá trị trung bình?

Metric aggregation tính tổng và trung bình.[1]

3. Terms aggregation trên field text...?

Lần chạy trả về: Fielddata is disabled on text fields.

4. Pipeline aggregation lấy đầu vào từ...?

Chúng dùng kết quả của các aggregation khác.[1]
