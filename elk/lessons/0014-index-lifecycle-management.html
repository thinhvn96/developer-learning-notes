Index lifecycle management (ILM)

ELK Stack · Lesson 0014 · step 14 of 14 · Senior · ~12 minutes · Home · ELK Stack ladder · Roadmap · Tiếng Việt

Today's win: describe ILM phases and rollover, and write a policy that rolls over in hot and deletes after 30 days.

What ILM automates

"ILM automates the management of time-based indices, such as logs and metrics" to balance performance, resilience, retention and cost. Indices move through hot, warm, cold, frozen and delete phases. Rollover "creates a new write index when the current one reaches a certain size, number of docs, or age". Actions include rollover, shrink, force merge and delete.[1]

A policy

PUT _ilm/policy/logs-policy
{ "policy": { "phases": {
    "hot":    { "actions": { "rollover": { "max_age": "7d", "max_primary_shard_size": "50gb" } } },
    "delete": { "min_age": "30d", "actions": { "delete": {} } } } } }
GET _ilm/policy/logs-policy  ->  hot 0ms [rollover]   delete 30d [delete]

The API accepted and returned this policy in my run. Attaching it to an index template's settings and watching a real transition needs days of data or shortened poll intervals, which I did not demonstrate. Sizing thoughts to bring to an interview: keep shards a manageable size (the rollover conditions above bound them), and choose retention from requirements; specific numbers (like 50gb) are examples, not documented recommendations. Script: 04-ingest-datastream-ilm.sh. Compare Kafka's retention settings.

Retrieval practice

Answer from memory. One attempt each.

1. ILM phases?

Indices move through hot, warm, cold, frozen and delete.[1]

2. Rollover triggers on...?

When the write index reaches a size, doc count or age.[1]

3. ILM manages which kind of indices?

It automates management of time-based indices like logs and metrics.[1]

4. Which action removes old data?

The delete action removes data at the end of the lifecycle.[1]
