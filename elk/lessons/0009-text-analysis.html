Text analysis: analyzers and tokens

Today's win: explain what an analyzer does at index and search time, and see the tokens a text field produces.

What analysis is

"Text analysis is the process of converting unstructured text ... into a structured format that's optimized for search." An analyzer controls what happens before tokenization, how text becomes tokens, and how tokens are normalized. Elasticsearch analyzes text fields when indexing and when searching; applying the same rules to the query string makes terms match. The default is the standard analyzer, which "works well for most use cases".[1]

Inspect it with _analyze

POST _analyze {"analyzer":"standard","text":"Connection Timeout to payment-service!"}
['connection', 'timeout', 'to', 'payment', 'service']

POST _analyze {"analyzer":"keyword","text":"Connection Timeout"}
['Connection Timeout']

The standard analyzer lowercased, split on punctuation and dropped the !; the keyword analyzer kept one token. This is exactly why term queries on text fields surprise people (lesson 5) and why keyword fields exist. Script: 03-analysis-bulk-aggs.sh.

Interview line: "Full-text search matches analyzed tokens, exact filtering uses keyword fields, and I check what tokens are produced with _analyze."
