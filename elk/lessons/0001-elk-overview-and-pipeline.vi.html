Pipeline ELK: thu thập, phân tích, lưu trữ, khám phá

ELK Stack · Bài 0001 · bước 1/14 · Foundation · ~10 phút · Trang chủ · Lộ trình ELK Stack · Lộ trình tổng · English

Thành quả hôm nay: nêu được vai trò của từng thành phần ELK và vẽ được đường đi của một dòng log từ file tới dashboard.

Bốn vai trò

Thành phầnVai trò
Filebeat (một Beat)đọc file log và gửi đi: "một harvester chịu trách nhiệm đọc nội dung của một file duy nhất"; một input quản lý các harvester và tìm nguồn dữ liệu[1]
Logstashpipeline xử lý gồm ba giai đoạn: "inputs → filters → outputs"[2]
Elasticsearchlưu các document JSON trong index, phân tán trên các shard[3]
KibanaDiscover là "công cụ chính để khám phá dữ liệu Elasticsearch trong Kibana"; tìm kiếm và lọc bằng KQL, Lucene hoặc ES|QL[4]

Đường đi

app log file --Filebeat--> Logstash (grok parse) --> Elasticsearch index --> Kibana Discover

Logstash là tuỳ chọn nếu log vốn đã có cấu trúc tốt; Beats cũng có thể gửi thẳng vào Elasticsearch. Chọn bố cục nào là một quyết định thiết kế (cần buffer không, cần parse gì), các bài sau sẽ quay lại chuyện này.

Chạy hai mảnh ở giữa

cd elk/examples && ./02-logstash-grok.sh      # parse a log line
cd elk/examples && ./01-elasticsearch-basics.sh   # index, search, shards

Cả hai đều khởi động container dùng xong bỏ (Logstash và Elasticsearch 9.0.0). Elasticsearch chạy với security bị tắt, chỉ để demo.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Thành phần nào đọc từng dòng của một file?

Harvester đọc nội dung của một file duy nhất.[1]

2. Thứ tự các giai đoạn của pipeline Logstash?

Pipeline có ba giai đoạn: inputs, filters, outputs.[2]

3. Document nằm ở đâu?

Index là đơn vị lưu trữ cơ bản trong Elasticsearch.[3]

4. Công cụ chính của Kibana để khám phá dữ liệu?

Discover là công cụ chính để khám phá dữ liệu Elasticsearch của bạn.[4]
