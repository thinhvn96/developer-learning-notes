Logstash: pipeline, grok và persistent queue

Thành quả hôm nay: viết được một pipeline Logstash có grok filter, nhận ra lỗi parse, và giải thích persistent queue đảm bảo được điều gì.

Pipeline

Input (file, syslog, beats...), filter (grok, mutate, drop, geoip...) và output (elasticsearch, file...). Codec đóng vai trò bộ lọc luồng gắn vào input hoặc output, ví dụ json hay multiline.[1]

Grok

Grok là "một cách rất tốt để parse dữ liệu log phi cấu trúc thành thứ có cấu trúc và query được." Pattern dùng cú pháp %{SYNTAX:SEMANTIC}, ví dụ %{NUMBER:duration}. Khi không pattern nào khớp, mặc định event sẽ được gắn tag _grokparsefailure.[2]

grok { match => { "message" => "%{IP:client} %{WORD:method} %{URIPATH:path} %{NUMBER:status:int} %{NUMBER:duration_ms:int}" } }
cd elk/examples && ./02-logstash-grok.sh
"10.0.0.7 GET /orders/42 200 35"  -> client=10.0.0.7 method=GET path=/orders/42 status=200 duration_ms=35
"this is not an access log"       -> tags: [ "_grokparsefailure" ]

File: logstash-grok.conf, 02-logstash-grok.sh.

Persistent queue

Persistent queue "giúp chống mất dữ liệu khi tiến trình bị dừng bất thường bằng cách lưu hàng đợi message đang in-flight xuống đĩa." Sau khi restart, Logstash "cố gắng giao các message đã lưu trong persistent queue cho tới khi giao thành công ít nhất một lần." Nó có thể hấp thụ các đợt tăng đột biến mà không cần buffer bên ngoài như Redis hay Kafka, và tạo backpressure lên input khi đầy.[3]

Để ý chữ "ít nhất một lần": có thể xuất hiện bản trùng, nên hãy gán cho event một id ổn định nếu phía sau quan tâm tới chuyện trùng lặp.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Cú pháp pattern của grok?

Pattern được viết dạng %{SYNTAX:SEMANTIC}.[2]

2. Grok không khớp. Chuyện gì xảy ra?

Mặc định tag _grokparsefailure sẽ được thêm vào.[2]

3. Persistent queue đảm bảo giao nhận kiểu gì?

Logstash giao các event đã lưu cho tới khi giao thành công ít nhất một lần.[3]

4. Queue đầy. Logstash làm gì?

Nó chặn input lại cho tới khi queue vơi bớt.[3]
