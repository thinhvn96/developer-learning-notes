Documents, indices and mappings

ELK Stack · Lesson 0002 · step 3 of 14 · Foundation · ~10 minutes · Home · ELK Stack ladder · Roadmap

Today's win: explain index, document and mapping, and why you choose explicit mappings for production.

Definitions

"An index is the fundamental unit of storage in Elasticsearch, and the level at which you interact with your data." An index consists of documents (JSON objects with key-value fields), mappings (field data types and how fields are indexed and queried), and settings (shards, replicas, refresh interval).[1]

The docs advise dynamic mapping for exploration and explicit mappings for production, and aliases to decouple queries from index names.[1]

An explicit mapping

PUT /logs
{ "mappings": { "properties": {
    "message": { "type": "text" },       // analyzed: full-text search
    "level":   { "type": "keyword" },    // exact value: filters and aggregations
    "service": { "type": "keyword" } } } }

The text versus keyword choice is the one that decides whether your queries work, as lesson 5 shows. Script: 01-elasticsearch-basics.sh.

Interview question: "What happens if I let dynamic mapping guess?" It infers types from the first document it sees, which may not suit your queries; mappings for existing fields cannot simply be changed, so plan them up front (the reindex approach is beyond the excerpts read here; ask your teacher).

Retrieval practice

Answer from memory. One attempt each.

1. A mapping defines what?

Mappings specify field data types and control indexing and querying behavior.[1]

2. What is a document in Elasticsearch?

Documents are JSON objects containing key-value fields.[1]

3. Dynamic or explicit mapping for production?

Use dynamic mapping for exploration, explicit for production.[1]

4. Which index part holds refresh interval?

Settings control shards, replicas and refresh intervals.[1]
