Data streams and rollover

ELK Stack · Lesson 0013 · step 13 of 14 · Advanced · ~12 minutes · Home · ELK Stack ladder · Roadmap

Today's win: explain a data stream, why it needs @timestamp, what rollover does, and when to use an alias instead.

What it is

A data stream is "a layer of abstraction over a set of indices that are optimized for storing append-only time series data": you use one name, and it manages hidden, auto-generated backing indices. Every document needs a @timestamp field (date or date_nanos). The newest backing index is the write index; a rollover creates a new one, automatically through ILM or manually.[1]

Not for: workloads that repeatedly send documents with the same _id expecting last-write-wins; use an index alias with a write index instead.[1]

PUT _index_template/logs-app {"index_patterns":["logs-app*"],"data_stream":{}}
POST logs-app/_doc {"@timestamp":"...","message":"first"}
  -> indexed into backing index .ds-logs-app-2026.09.24-000001
POST logs-app/_doc {"message":"no timestamp"}
  -> failed to parse: data stream timestamp field [@timestamp] is missing
POST logs-app/_rollover
  -> rolled_over true; new index .ds-logs-app-2026.09.24-000002
GET _data_stream/logs-app -> backing indices: [...-000001, ...-000002]

Logs and metrics are the natural fit; Filebeat and Logstash can write to data streams (I did not test that here). Script: 04-ingest-datastream-ilm.sh. Next: automating rollover and deletion with ILM.

Retrieval practice

Answer from memory. One attempt each.

1. Which field must every data stream document have?

Documents must include @timestamp; the run rejected one without it.[1]

2. What is the write index?

The most recent backing index serves as the write index.[1]

3. Rollover does what?

A rollover creates a new backing index that becomes the write index.[1]

4. Poor fit for a data stream?

Same-_id last-write-wins workloads should use an alias instead.[1]
