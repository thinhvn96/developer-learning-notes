Query DSL: term, match and bool

ELK Stack · Lesson 0005 · step 7 of 14 · Core · ~10 minutes · Home · ELK Stack ladder · Roadmap

Today's win: pick match versus term correctly, and structure a bool query with filter for exact conditions.

text versus keyword, term versus match

"Avoid using the term query for text fields." By default Elasticsearch changes text values during analysis, which "can make finding exact matches for text field values difficult"; use match for text fields.[1] Exact values such as ids or usernames belong in keyword fields, searched with term.

term  'Timeout' (exact token):            0 hits
term  'timeout' (lowercased token):       1 hit
match 'Timeout' (query is analyzed too):  1 hit

The message Connection Timeout to payment-service was analyzed into lowercase tokens, so a term for Timeout misses and match finds it (results from the script).

bool

  • must and should contribute to the relevance score.
  • filter and must_not run in filter context: scoring is ignored and they are cached.[2]
{ "query": { "bool": {
    "filter": [ { "term":  { "level": "ERROR" } } ],
    "must":   [ { "match": { "message": "payment" } } ] } } }

Use filter for yes/no conditions (level, service, time range) and must for the full-text relevance part. The script's bool query returns 1 hit for ERROR logs mentioning payment.

Retrieval practice

Answer from memory. One attempt each.

1. Which query suits an analyzed text field?

Use match for text fields; term does no analysis.[1]

2. Which bool clause ignores scoring?

filter ignores the score; must and should contribute.[2]

3. Best field type for a user id?

Exact-value fields are keyword fields searched with term.

4. Which bool clauses are cached?

filter and must_not run in filter context and are cached.[2]
