Ingest pipeline: parse ngay bên trong Elasticsearch

ELK Stack · Bài 0012 · bước 12/14 · Advanced · ~12 phút · Trang chủ · Lộ trình ELK Stack · Lộ trình tổng · English

Thành quả hôm nay: parse nhẹ ngay bên trong Elasticsearch bằng một ingest pipeline, test nó bằng simulate, và biết giới hạn của nó so với Logstash.

Ingest pipeline là gì

Ingest pipeline "cho phép bạn thực hiện các phép biến đổi thông dụng trên dữ liệu trước khi index", như xoá field, tách giá trị text và làm giàu dữ liệu (enrich). Một pipeline là chuỗi các processor chạy tuần tự; sau đó document mới được index. Dùng pipeline qua query parameter pipeline, hoặc đặt làm index.default_pipeline của index; test bằng API simulate.[1]

Giới hạn: pipeline xử lý từng document một tại thời điểm nó được index, nên không thể tách document, aggregate trên nhiều document hay sửa dữ liệu đã index (processor enrich cho phép tra cứu ở mức hạn chế).[1]

PUT _ingest/pipeline/access   {grok, lowercase, set}
simulate "10.0.0.7 GET /orders/42 200"
  -> {client: 10.0.0.7, method: get, path: /orders/42, status: 200, pipeline: access}
simulate "garbage"
  -> Provided Grok expressions do not match field value: [garbage]
PUT weblogs/_doc/1?pipeline=access   then   q=status:200  -> found

Cú pháp grok %{SYNTAX:SEMANTIC} ở đây giống hệt trong Logstash.[2] Chọn cái nào là một bài toán đánh đổi (trade-off) trong thiết kế: ingest pipeline không cần thêm service nào; Logstash có nhiều input/output hơn và có buffer (bài Logstash); các trang tài liệu mình đọc không đưa ra so sánh, nên hãy tự trình bày lập luận của bạn. Script: 04-ingest-datastream-ilm.sh.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Ingest pipeline chạy...?

Chúng biến đổi dữ liệu trước khi index.[1]

2. Một pipeline được tạo từ...?

Pipeline là một chuỗi các processor có thể cấu hình.[1]

3. Test pipeline an toàn bằng cách nào?

API simulate pipeline test với các document mẫu.[1]

4. Pipeline không thể...?

Nó xử lý từng document một.[1]
