Namespaces: isolating groups of resources

Kubernetes · Lesson 0008 · step 3 of 15 · Foundation · ~10 minutes · Home · Kubernetes ladder · Roadmap · Tiếng Việt

Today's win: explain what a namespace isolates, name the four default namespaces, and set a default namespace for kubectl.

What namespaces do

"Namespaces provide a mechanism for isolating groups of resources within a single cluster. Names of resources need to be unique within a namespace, but not across namespaces." Scoping applies to namespaced objects (Deployments, Services...), not cluster-wide ones (StorageClass, Nodes, PersistentVolumes). Namespaces cannot be nested, and each resource lives in exactly one.[1]

Initial namespacePurpose[1]
defaultwhere you land when you specify none
kube-systemobjects created by Kubernetes itself
kube-publicreadable by all clients; reserved for cluster use
kube-node-leaseLease objects for node heartbeats

Not for minor differences: "use labels to distinguish resources within the same namespace" rather than a namespace per software version.[1]

Try it

kubectl apply -f examples/namespace-demo.yaml     # Namespace demo + Pod demo/hello
kubectl -n demo logs hello                 -> hello from hello
kubectl get pod hello                      -> Error: pods "hello" not found     # wrong namespace
kubectl config set-context --current --namespace=demo   # change the default

The "not found" error is the everyday symptom of forgetting -n. File: namespace-demo.yaml.

Retrieval practice

Answer from memory. One attempt each.

1. Names must be unique where?

Names need to be unique within a namespace, not across namespaces.[1]

2. Can namespaces be nested?

Namespaces are not nested.[1]

3. Which object is cluster-scoped?

PersistentVolumes, Nodes and StorageClasses are not namespaced.[1]

4. To tell app versions apart, use...?

Use labels to distinguish slightly different resources in the same namespace.[1]
