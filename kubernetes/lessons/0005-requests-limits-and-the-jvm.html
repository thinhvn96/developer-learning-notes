Requests, limits and the JVM

Kubernetes · Lesson 0005 · step 9 of 15 · Advanced · ~12 minutes · Home · Kubernetes ladder · Roadmap

Today's win: set requests and limits for a JVM container so it schedules correctly, is not OOM-killed, and is not surprised by CPU throttling.

Requests versus limits

Requests are what a container is guaranteed, and "the scheduler uses requests to decide which node can accommodate a Pod." Limits are the maximum it may use, enforced by the kubelet.[1] CPU is measured in cores or millicores (500m = 0.5 CPU); memory in bytes (256Mi).[1]

What happens on breach

  • CPU over limit: throttled by the kernel.[1]
  • Memory over limit: the container can be OOM-killed; enforcement is reactive, when the kernel detects memory pressure.[1]

If you set a limit but no request, Kubernetes uses the limit as the request.[1]

Applying it to Java

env:
- name: JAVA_TOOL_OPTIONS
  value: "-XX:MaxRAMPercentage=70"
resources:
  requests: { memory: "512Mi", cpu: "250m" }
  limits:   { memory: "512Mi", cpu: "1" }

The JVM on Linux detects container limits by default, and MaxRAMPercentage sizes the heap as a percentage of that memory.[2] Setting it to 70 leaves room for non-heap memory. (The Docker lesson measured this with docker run --memory; the same JVM detection applies here because the container runtime enforces the limit.) Choosing 70 is a starting point to measure, not a rule. A full sketch is in java-service.yaml.

Verified: an OOM kill

kubectl apply -f examples/memory-hog.yaml     # limit 20Mi, container runs: tail /dev/zero
NAME         READY   STATUS      RESTARTS   AGE
memory-hog   0/1     OOMKilled   0          12s
reason=OOMKilled exit=137

Exit code 137 is 128 + 9 (SIGKILL). See memory-hog.yaml.

Senior question: "Should memory request equal memory limit?" Equal values make the memory footprint predictable and avoid the node over-committing memory the Pod might need; the docs explain that requests drive scheduling and limits drive enforcement.[1] State the trade-off, not a slogan.

Retrieval practice

Answer from memory. One attempt each.

1. What does the scheduler use to place a Pod?

The scheduler uses requests to decide which node can accommodate a Pod.[1]

2. A container passes its CPU limit. Result?

CPU limits are enforced by throttling.[1]

3. A container passes its memory limit. Result?

Memory limits are enforced with OOM kills.[1]

4. Why MaxRAMPercentage below 100?

The JVM uses memory beyond the heap, and heap plus that must fit under the limit.
