Cluster components: who does what

Kubernetes · Lesson 0001 · step 1 of 15 · Foundation · ~10 minutes · Home · Kubernetes ladder · Roadmap · Tiếng Việt

Today's win: name the six cluster components and say which ones run on the control plane and which on every node.

What Kubernetes is

Kubernetes is "a portable, extensible, open-source platform for managing containerized workloads and services" with "declarative configuration and automation". Its capabilities include service discovery and load balancing, automated rollouts and rollbacks, self-healing, secret and configuration management, and horizontal scaling.[1]

The components, one line each

ComponentRole (from the docs)[2]
kube-apiserver"The core component server that exposes the Kubernetes HTTP API."
etcd"Consistent and highly-available key value store for all API server data."
kube-scheduler"Looks for Pods not yet bound to a node, and assigns each Pod to a suitable node."
kube-controller-manager"Runs controllers to implement Kubernetes API behavior."
kubelet"Ensures that Pods are running, including their containers."
kube-proxy"Maintains network rules on nodes to implement Services." (optional)
Container runtime"Software responsible for running containers."

The first four form the control plane, which manages the overall state of the cluster; kubelet, kube-proxy and the runtime run on nodes.[2] The mental model: you declare desired state to the API server; controllers and the kubelet work to make reality match.

Interview angle: "What happens when you run kubectl apply?" Trace it: API server validates and stores in etcd, controllers create the objects, the scheduler picks a node, the kubelet starts the containers via the runtime.

Retrieval practice

Answer from memory. One attempt each.

1. Which component stores all API data?

etcd is the consistent, highly-available key value store for all API server data.[2]

2. Which component picks a node for a new Pod?

The scheduler assigns unbound Pods to suitable nodes.[2]

3. Which component makes sure Pods run on a node?

The kubelet ensures Pods and their containers are running.[2]

4. Where do you send desired state?

The kube-apiserver exposes the Kubernetes HTTP API.[2]
