Các thành phần của cluster: ai làm việc gì

Kubernetes · Bài 0001 · bước 1/15 · Foundation · ~10 phút · Trang chủ · Lộ trình Kubernetes · Lộ trình tổng · English

Thành quả hôm nay: kể tên sáu thành phần của cluster và nói được thành phần nào chạy trên control plane, thành phần nào chạy trên mọi node.

Kubernetes là gì

Kubernetes là "một nền tảng mã nguồn mở, portable, dễ mở rộng để quản lý các workload và service chạy trong container", với "cấu hình khai báo (declarative) và tự động hoá". Các khả năng của nó gồm service discovery và load balancing, tự động rollout và rollback, tự phục hồi (self-healing), quản lý secret và cấu hình, và mở rộng theo chiều ngang.[1]

Các thành phần, mỗi cái một dòng

Thành phầnVai trò (theo tài liệu)[2]
kube-apiserver"Server thành phần lõi, cung cấp Kubernetes HTTP API."
etcd"Kho key value nhất quán và có tính sẵn sàng cao, chứa toàn bộ dữ liệu của API server."
kube-scheduler"Tìm các Pod chưa được gán vào node nào, và gán mỗi Pod vào một node phù hợp."
kube-controller-manager"Chạy các controller để hiện thực hoá hành vi của Kubernetes API."
kubelet"Đảm bảo các Pod đang chạy, bao gồm cả container của chúng."
kube-proxy"Duy trì các network rule trên node để hiện thực hoá Service." (tuỳ chọn)
Container runtime"Phần mềm chịu trách nhiệm chạy container."

Bốn thành phần đầu tạo thành control plane, nơi quản lý trạng thái tổng thể của cluster; kubelet, kube-proxy và runtime chạy trên các node.[2] Mô hình tư duy: bạn khai báo trạng thái mong muốn (desired state) cho API server; các controller và kubelet làm việc để thực tế khớp với nó.

Góc phỏng vấn: "Chuyện gì xảy ra khi bạn chạy kubectl apply?" Hãy lần theo từng bước: API server validate rồi lưu vào etcd, các controller tạo object, scheduler chọn node, kubelet khởi động container thông qua runtime.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Thành phần nào lưu toàn bộ dữ liệu API?

etcd là kho key value nhất quán, có tính sẵn sàng cao, chứa toàn bộ dữ liệu của API server.[2]

2. Thành phần nào chọn node cho một Pod mới?

Scheduler gán các Pod chưa có node vào node phù hợp.[2]

3. Thành phần nào đảm bảo Pod chạy trên một node?

kubelet đảm bảo các Pod và container của chúng đang chạy.[2]

4. Bạn gửi trạng thái mong muốn đến đâu?

kube-apiserver cung cấp Kubernetes HTTP API.[2]
