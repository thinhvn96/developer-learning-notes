ConfigMaps: configuration outside the image

Kubernetes · Lesson 0009 · step 6 of 15 · Core · ~10 minutes · Home · Kubernetes ladder · Roadmap

Today's win: externalize configuration with a ConfigMap and consume it as environment variables and files, knowing which one updates live.

What it is

A ConfigMap stores non-confidential data as key-value pairs, decoupling environment-specific configuration from container images. It has a 1 MiB limit and no encryption (use a Secret for confidential data).[1] Pods can consume it via command/args, environment variables, read-only volume files, or the API.[1]

env:
- name: LOG_LEVEL
  valueFrom:
    configMapKeyRef: { name: app-config, key: LOG_LEVEL }
volumes:
- name: config
  configMap:
    name: app-config
    items: [ { key: application.properties, path: application.properties } ]

Which updates live?

Environment variables are not updated in running containers (restart needed); files in mounted volumes are eventually updated. Immutable ConfigMaps (v1.19+) prevent accidental changes.[1]

kubectl apply -f examples/configmap-secret.yaml ; kubectl logs config-demo
LOG_LEVEL=debug
--- file:
server.port=8080
feature.x=true

Link to Spring: an application.properties mounted as a file, or env vars like SERVER_PORT, override packaged config (externalized configuration lesson). File: configmap-secret.yaml.

Retrieval practice

Answer from memory. One attempt each.

1. ConfigMaps are meant for what data?

They hold non-confidential data in key-value pairs.[1]

2. A ConfigMap changes. Env-var consumers see?

Environment variables are not updated in running containers.[1]

3. Mounted ConfigMap files after a change?

Volume-mounted files are eventually reflected.[1]

4. Size limit of a ConfigMap?

The limit is 1 MiB.[1]
