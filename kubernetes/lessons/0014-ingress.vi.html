Ingress: định tuyến HTTP vào cluster

Kubernetes · Bài 0014 · bước 14/15 · Advanced · ~10 phút · Trang chủ · Lộ trình Kubernetes · Lộ trình tổng · English

Thành quả hôm nay: giải thích Ingress làm gì, vì sao bạn cần một controller, và vì sao tài liệu giờ khuyên dùng Gateway API.

Ingress là gì

"Ingress expose các route HTTP và HTTPS từ bên ngoài cluster tới các service bên trong cluster." Các rule trên Ingress quyết định việc định tuyến. Nó có thể cung cấp load balancing, TLS termination và virtual hosting theo tên miền.[1] Mỗi rule có một host (tuỳ chọn) và một danh sách path, mỗi path trỏ tới tên và port của một Service backend; cả host lẫn path đều phải khớp.[1]

spec:
  ingressClassName: nginx-example
  rules:
  - http:
      paths:
      - path: /testpath
        pathType: Prefix
        backend: { service: { name: nginx-service, port: { number: 80 } } }

Bắt buộc phải có controller

"Bạn phải có một Ingress controller thì Ingress mới có tác dụng. Chỉ tạo một resource Ingress thôi thì không có hiệu lực gì."[1]

kubectl apply -f examples/ingress.yaml
NAME              CLASS           HOSTS   ADDRESS   PORTS   AGE
minimal-ingress   nginx-example   *                 80      20s      # ADDRESS empty: no controller

Object được chấp nhận nhưng không nhận được địa chỉ nào trên cluster của tôi, vì cluster đó không cài Ingress controller. Thêm một điểm: tài liệu khuyên dùng Gateway API thay thế, và nói rằng Ingress API "đã bị đóng băng kể từ Kubernetes v1.19".[1] So sánh với Service: Ingress định tuyến HTTP tới các Service. File: ingress.yaml.

Đã kiểm chứng: tôi đã apply các manifest trong examples/ lên một cluster kind dùng xong bỏ (Kubernetes v1.37.0, kubectl v1.37.1) và trích output từ lần chạy đó. Bản thân việc cài kind không nằm trong các trang tôi đã đọc; hãy làm theo tài liệu của chính dự án đó.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Ingress định tuyến loại traffic nào?

Nó expose các route HTTP và HTTPS tới Service.[1]

2. Cần gì để một Ingress hoạt động?

Chỉ tạo resource thôi thì không có hiệu lực gì.[1]

3. Để khớp một rule của Ingress cần...?

Cả host lẫn path đều phải khớp với request.[1]

4. Theo tài liệu, thứ được khuyên dùng để thay thế?

Dự án khuyên dùng Gateway API; Ingress đã bị đóng băng kể từ v1.19.[1]
