Deployments, ReplicaSets and labels

Kubernetes · Lesson 0003 · step 4 of 15 · Core · ~10 minutes · Home · Kubernetes ladder · Roadmap

Today's win: write a Deployment, and explain how labels tie the Deployment, its ReplicaSet and its Pods together.

What a Deployment does

A Deployment "manages a set of Pods to run an application workload, usually one that doesn't maintain state." You describe a desired state and the Deployment controller "changes the actual state to the desired state at a controlled rate."[1] It creates and manages ReplicaSets, which keep the requested number of Pods running.[1]

The label contract

spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx          # must match...
  template:
    metadata:
      labels:
        app: nginx        # ...the Pod template labels
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2

".spec.selector.matchLabels must match the labels" in the Pod template.[1] Full file: deployment.yaml. Labels are also what Services select on (next lesson); the docs list labels and selectors among the object-management basics.[2]

Interview angle: "Why did my Pods not get created?" A selector that does not match the template labels is a classic answer, and the API server rejects it.

Retrieval practice

Answer from memory. One attempt each.

1. What does a Deployment manage?

It provides declarative updates for Pods and ReplicaSets.[1]

2. Selector and Pod template labels must...?

The selector's matchLabels must match the Pod template labels.[1]

3. You state replicas: 3. That is...?

You describe desired state; the controller reconciles toward it.[1]

4. Best fit for a Deployment?

Deployments suit workloads that usually do not maintain state; Jobs and StatefulSets fit the others.[1]
