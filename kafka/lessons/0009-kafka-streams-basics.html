Kafka Streams: streams, tables and state

Kafka · Lesson 0009 · step 9 of 10 · Advanced · ~12 minutes · Home · Kafka ladder · Roadmap

Today's win: explain streams versus tables, state stores and event-time processing, and run a word count on Kafka Streams.

What it is

Kafka Streams is "a client library for processing and analyzing data stored in Kafka", embedded in ordinary Java applications with no external dependencies beyond Kafka.[1] You do not deploy a separate cluster: you run more instances of your app.

Core ideas

  • KStream: an unbounded, continuously updating data set of immutable key-value records. KTable: a table snapshot, enabling joins and aggregations. The stream-table duality: a stream is a changelog, a table is a stream at a point in time.[1]
  • Topology: a graph of processors; source processors read topics, sink processors write results back to Kafka or elsewhere.[1]
  • State stores back stateful operations (windowed joins, aggregations) with automatic fault tolerance and recovery.[1]
  • Time: event time (when it occurred), processing time, ingestion time; a TimestampExtractor assigns timestamps.[1]
  • Exactly-once processing since 0.11.0.0: atomic commits across input offsets, state updates and output writes.[1]

Retrieval practice

Answer from memory. One attempt each.

1. Kafka Streams is...?

It is a client library embedded in your application.[1]

2. A KTable represents...?

KTable captures table snapshots; KStream is the record stream.[1]

3. Where does stateful operation data live?

State stores hold data for stateful processing with fault tolerance.[1]

4. Which time is when an event occurred?

Event time is when the event occurred.[1]
