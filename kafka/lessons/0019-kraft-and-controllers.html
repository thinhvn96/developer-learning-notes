KRaft: controllers and the metadata quorum

Kafka · Lesson 0019 · step 19 of 23 · Senior · ~11 minutes · Home · Kafka ladder · Roadmap · Tiếng Việt

Today's win: explain how a Kafka 4.x cluster stores its metadata without ZooKeeper, why controllers come in 3s or 5s, and how to check quorum health.

From ZooKeeper to KRaft

Older Kafka kept cluster metadata (topics, partitions, leaders, configs) in ZooKeeper. Kafka 4.x runs in KRaft mode only: metadata is a Raft-replicated log inside Kafka, in the __cluster_metadata partition. Migration from ZooKeeper needs a bridge release; "The last bridge release is Kafka 3.9."[1]

Roles

"In KRaft mode each Kafka server can be configured as a controller, a broker, or both" via process.roles: broker, controller, or broker,controller (combined).[1] "Combined mode is not recommended in critical deployment environments": a busy broker should not starve the controller.[1]

Why 3 or 5 controllers

Admins "will typically select 3 or 5 servers for this role", because "A majority of the controllers must be alive in order to maintain availability": 3 survive 1 failure, 5 survive 2.[1] Four is no better than three (a majority of 4 is 3). One controller is the active leader; the rest are hot standbys that follow the metadata log, which makes controller failover fast.

Look at it

$ ./07-kraft-quorum.sh
process.roles=broker,controller
controller.quorum.voters=1@localhost:9093
LeaderId:               1
HighWatermark:          18
MaxFollowerLag:         0
CurrentVoters:          [{"id": 1, "endpoints": ["CONTROLLER://localhost:9093"]}]
Feature: group.version     ... FinalizedVersionLevel: 1
Feature: kraft.version     ... FinalizedVersionLevel: 0
Feature: share.version     ... FinalizedVersionLevel: 1

Our learning container is a single combined node with a static voter list. kraft.version 0 means a static quorum; 1 or above means a dynamic quorum where you can add-controller / remove-controller with kafka-metadata-quorum.sh.[1] group.version 1 is what enables the new consumer protocol on the server. Alert on ActiveControllerCount: exactly one node in the cluster should report 1.[2]

Interview answer: "Kafka 4 has no ZooKeeper. Three dedicated controllers form a Raft quorum over the metadata log; a majority must be up. Brokers fetch metadata from the active controller. I'd use dedicated controllers in production and watch ActiveControllerCount."

Retrieval practice

Answer from memory. One attempt each.

1. Five controllers. How many can fail?

A majority must be alive: 5 tolerate 2 failures.[1]

2. process.roles for a combined node?

broker,controller makes the server act as both.[1]

3. Is combined mode recommended for critical prod?

Combined mode is not recommended in critical deployment environments.[1]

4. Healthy ActiveControllerCount across the cluster?

Only one node in the cluster should report 1.[2]
