Kafka Connect: moving data in and out

Kafka · Lesson 0010 · step 18 of 23 · Senior · ~12 minutes · Home · Kafka ladder · Roadmap · Tiếng Việt

Today's win: explain what Kafka Connect is, the source/sink split, tasks and converters, and move data through Kafka with two connectors.

What it is

A framework for "scalably and reliably streaming data between Kafka and other systems". Connectors are plugins that manage data movement and spawn tasks that do the work in parallel. A source connector reads an external system into Kafka topics; a sink connector writes topics to an external system. Converters translate between Connect's internal format and serialized data (JSON, Avro...).[1]

Modes and management

Standalone: one process, no fault tolerance or scaling. Distributed: automatic load balancing, dynamic scaling and fault tolerance; offsets, configs and task statuses are stored in Kafka topics. A REST API (port 8083 by default) creates, updates, monitors and deletes connectors.[1]

Run it

cd kafka/examples && ./03-connect-file.sh
source connector: /tmp/in.txt  -> topic connect-demo
sink connector  : topic connect-demo -> /tmp/out.txt     (line one / line two / line three)
GET :8083/connectors  -> ["demo-file-source","demo-file-sink"]
append "line four" to the source file -> it appears in the sink and in the topic

The FileStream connectors ship with Kafka for demonstration; real pipelines use connectors for databases, object stores and search (for example feeding Elasticsearch, see the ELK ladder). Source: 03-connect-file.sh.
