Consumers, consumer groups and offsets

Kafka · Lesson 0003 · step 5 of 23 · Core · ~10 minutes · Home · Kafka ladder · Roadmap · Tiếng Việt

Today's win: explain consumer groups, partition assignment, offsets and rebalancing, and why more consumers than partitions does not help.

Consumer groups

Consumers that share a group.id divide the work: "each partition is assigned to exactly one consumer in the group."[1] Membership is dynamic; when consumers join or leave, partitions are rebalanced.[1] A consequence (derived from the exactly-one rule, not quoted): with 3 partitions, a 4th consumer in the same group sits idle. Different groups each receive all events.

Offsets

"The position of a consumer in each partition is just a single integer, the offset of the next message to consume."[2] The consumer has a current position (next record to fetch) and a committed position (last offset stored safely).[1] Group state is visible with kafka-consumer-groups.sh --describe: current offset, log-end offset and lag.

GROUP  TOPIC   PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
g1     orders  0          2               2               0
g1     orders  1          4               4               0
g1     orders  2          0               0               0

That output is from 01-topics-keys-groups.sh: group g1 read all six events, so lag is zero.

Config that bites

  • enable.auto.commit defaults to true: offsets are committed periodically in the background.[3]
  • auto.offset.reset (default latest) only applies when there is no valid committed offset.[3]
  • session.timeout.ms: without heartbeats the broker removes the client from the group and starts a rebalance; max.poll.interval.ms bounds the delay between poll() calls.[3]
  • "The consumer is not thread-safe."[1] One consumer instance per thread.

Config sketch: manual-commit-consumer.properties.

Retrieval practice

Answer from memory. One attempt each.

1. Within one group, a partition goes to how many consumers?

Each partition is assigned to exactly one consumer in the group.[1]

2. Consumer offset is what?

It is the offset of the next message to consume.[2]

3. Consumer stops heartbeating. Broker action?

After session.timeout.ms the broker removes the client and initiates a rebalance.[3]

4. Is a KafkaConsumer instance thread-safe?

The Javadoc says the consumer is not thread-safe.[1]
