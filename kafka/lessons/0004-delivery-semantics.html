Delivery semantics: at most, at least, exactly once

Kafka · Lesson 0004 · step 6 of 23 · Core · ~10 minutes · Home · Kafka ladder · Roadmap · Tiếng Việt

Today's win: decide which delivery guarantee you get from the order of 'process' and 'commit offset', and how to make consumers safe under redelivery.

Three guarantees

  • At most once: messages may be lost but are never redelivered.
  • At least once: messages are never lost but may be redelivered.
  • Exactly once: each message is processed once only.[1]

The order decides it

"If the consumer reads messages, then saves its position, and finally processes messages" you get at-most-once: crash after saving but before processing loses the message. Process first, then save the position, and you get at-least-once.[1] The consumer Javadoc says the same about commitSync(): if a process fails after committing but before finishing downstream work, another consumer re-reads from the last committed offset (its own wording is about at-least-once with commit after work).[2]

while (true) {
    var records = consumer.poll(Duration.ofMillis(500));
    for (var r : records) process(r);   // 1. do the work
    consumer.commitSync();              // 2. then commit: at-least-once
}

What that means for your code

At-least-once means duplicates happen, so processing must be idempotent (safe to repeat), for example by using a unique event id as a database key. The exactly-once options inside Kafka (idempotent producer, transactions) are the next lesson.

Retrieval practice

Answer from memory. One attempt each.

1. Commit offset, then process, then crash. Guarantee?

Saving the position before processing gives at-most-once.[1]

2. Process, then commit. Guarantee?

Processing before saving the position gives at-least-once.[1]

3. At-least-once requires consumers to be...?

Duplicates can be redelivered, so repeating work must be safe.

4. After a crash post-commit, pre-work, who reprocesses?

With commit before processing the records are not re-read, so the work is lost (at most once).[1]
