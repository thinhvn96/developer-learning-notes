Log compaction and tombstones

Kafka · Lesson 0008 · step 9 of 23 · Advanced · ~12 minutes · Home · Kafka ladder · Roadmap · Tiếng Việt

Today's win: explain log compaction's guarantees, when to use it instead of time-based retention, and what a tombstone does.

The guarantee

"Log compaction ensures that Kafka will always retain at least the last known value for each message key within the log of data for a single topic partition." Unlike time or size retention, which discard all old data, compaction removes only records that have a newer update for the same key.[1]

Guarantees

  • Consumers that keep up see every message with sequential offsets.
  • Message order is never changed; only removal occurs.
  • Offsets of remaining messages never change.
  • A consumer reading from the start sees the final state of every record, in original write order.[1]

Uses: database change subscriptions, event sourcing, journaling for local state recovery.[1] Tombstones: a message with a null payload deletes prior messages with that key, and is itself cleaned after delete.retention.ms (default 24 hours).[1]

Watch it (aggressive settings so it finishes in a minute)

cleanup.policy=compact  segment.ms=1000  min.cleanable.dirty.ratio=0.01  delete.retention.ms=100
produce u1:v1 u2:a u1:v2 u1:v3 u2:b
before compaction: u1 v1 | u1 v2 | u1 v3 | u2 a | u2 b
after  compaction: u1 v3 | u2 b            (plus later filler keys)
produce u2:<null> (tombstone), more records, wait
after  tombstone : u1 v3                     (u2 is gone)

Compaction runs in the background on closed segments, so it is not instant; the demo forces segment rolls with filler records. Do not use these aggressive values in production. Source: 02-retention-and-compaction.sh.

Retrieval practice

Answer from memory. One attempt each.

1. What does compaction always keep?

At least the last known value for each key.[1]

2. Do offsets change after compaction?

Offsets remain permanently stable identifiers.[1]

3. What is a tombstone?

Null payloads act as deletion markers for their key.[1]

4. Good use of compaction?

Change subscriptions and state restoration need only the latest value per key.[1]
