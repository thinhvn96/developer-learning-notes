Visibility and happens-before

Java (JDK 8, 17, 21) · Lesson 0005 · step 13 of 27 · Advanced · ~12 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: explain why a thread can miss another thread's write, and name three ways to create a happens-before edge.

The problem

If two threads access the same variable and at least one writes, and nothing orders them, you have a data race: "two conflicting accesses that are not ordered by a happens-before relationship".[1] Without that ordering the reader is not guaranteed to see the write, and the JVM is free to reorder.

What creates ordering (happens-before edges)

  • An unlock of a monitor happens-before every later lock of that same monitor (synchronized).[1]
  • A write to a volatile field happens-before every later read of that field.[1]
  • Thread.start() happens-before the started thread's actions; a thread's actions happen-before another thread returns from join() on it.[1]
  • Library edges: putting an object into a concurrent collection, submitting to an Executor, Future.get(), Lock.unlock/lock, CountDownLatch.countDown/await.[2]

The payoff: "If a program is correctly synchronized, then all executions of the program will appear to be sequentially consistent."[1] You reason about interleavings, not reorderings.

Senior detail: a non-volatile long or double write may be treated as two 32-bit writes, so a reader can see a torn value; volatile 64-bit writes are atomic.[1] Also, volatile gives visibility and ordering, not atomicity of count++. That is the next interview follow-up (a later lesson covers atomics).

Retrieval practice

Answer from memory. One attempt each.

1. A data race needs two accesses that are...?

A data race is conflicting accesses not ordered by happens-before.[1]

2. Which action does NOT create a happens-before edge?

Plain accesses give no cross-thread ordering by themselves.[1]

3. What does volatile NOT give you?

volatile orders and publishes writes, but count++ is still read-modify-write, not atomic.[1]

4. Correctly synchronized programs appear...?

That is the JLS guarantee for programs free of data races.[1]
