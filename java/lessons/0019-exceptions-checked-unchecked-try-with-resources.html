Exceptions: checked vs unchecked and try-with-resources

Today's win: say which exceptions you must catch or declare, and use try-with-resources with correct close order and suppressed exceptions.

What an exception is

"An exception is an event, which occurs during the execution of a program, that disrupts the normal flow of the program's instructions." The runtime searches the call stack for a matching handler; if none is found the program terminates.[3]

Three kinds

  • Checked exceptions: must be caught or declared (catch-or-specify).
  • Runtime exceptions and errors are unchecked: no catch or declaration required.[1]

The tutorial's guideline: "If a client can reasonably be expected to recover from an exception, make it a checked exception. If a client cannot do anything to recover from the exception, make it an unchecked exception." Do not use RuntimeException merely to avoid declaring exceptions.[1]

try-with-resources

A resource is an object that must be closed; anything implementing AutoCloseable qualifies. Resources are closed in the opposite order of creation. If the body throws and close() also throws, the body's exception is the one propagated and the others are suppressed, retrievable with getSuppressed(). Any catch/finally runs after the resources are closed.[2]

Retrieval practice

Answer from memory. One attempt each.

1. Which kind must be caught or declared?

Catch-or-specify applies to checked exceptions only.[1]

2. try-with-resources closes resources in what order?

Close methods are called in the opposite order of creation.[2]

3. Body and close() both throw. Which propagates?

The close exception is suppressed; retrieve it with getSuppressed.[2]

4. Interface a resource must implement?

Any object implementing AutoCloseable can be a resource.[2]
