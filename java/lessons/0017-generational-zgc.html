Today's win: say what generational ZGC is, how to enable it on JDK 21, and what workload it targets.

What it is (JDK 21)

JEP 439 aims to "improve application performance by extending the Z Garbage Collector to maintain separate generations for young and old objects."[1] Its goals: lower risk of allocation stalls, lower heap memory overhead, lower GC CPU overhead, pause times under one millisecond, heaps from hundreds of megabytes to multiple terabytes, and little manual tuning.[1]

Enabling it on JDK 21

java -XX:+UseZGC -XX:+ZGenerational -jar app.jar

Both flags together enable the generational mode in JDK 21.[1] Without them the default collector rules apply: G1 on server-class machines, Serial otherwise.[2]

Try it

java -XX:+UseZGC -XX:+ZGenerational -Xmx64m -Xlog:gc java/examples/GcDemo.java

Compare the log with the G1 run from lesson 7. I ran the G1 version there; the ZGC comparison is your exercise.

Interview answer shape: "Default G1 for balanced throughput. If the SLA is sub-millisecond pauses on large heaps, evaluate generational ZGC on JDK 21, measured against my workload's GC logs, not by folklore."

Retrieval practice

Answer from memory. One attempt each.

1. What did JDK 21 add to ZGC?

Generational ZGC maintains separate young and old generations.[1]

2. How is generational ZGC enabled on JDK 21?

Both -XX:+UseZGC and -XX:+ZGenerational are used together.[1]

3. Stated pause-time goal?

The JEP targets pause times under one millisecond.[1]

4. Default collector on a server-class machine?

G1 on server-class machines, Serial otherwise.[2]
