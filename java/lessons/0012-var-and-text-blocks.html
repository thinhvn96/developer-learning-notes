JDK 10 and 15: var and text blocks (in JDK 17)

Java (JDK 8, 17, 21) · Lesson 0012 · step 19 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: use var and text blocks correctly, and state where var is not allowed.

var (delivered in JDK 10, so present in 17 and 21)

JEP 286 "extend[s] type inference to declarations of local variables with initializers."[1] It applies to local variables with initializers and for-loop indexes. It is not available for method parameters, constructor parameters, return types, fields or catch parameters; nor for variables without an initializer.[1] It stays statically typed: var list = new ArrayList<String>(); is still an ArrayList<String>.[1]

Text blocks (final in JDK 15)

"A text block is a multi-line string literal that avoids the need for most escape sequences, automatically formats the string in a predictable way, and gives the developer control over the format when desired."[2] It opens with """ followed by a line terminator. Double quotes inside need no escaping. Leading indentation common to all lines is stripped, and trailing whitespace is removed.[2] Two escapes arrived with the feature: \<line-terminator> suppresses a newline and \s is a space.[2]

var json = """
        {
          "name": "orders",
          "port": 8080
        }
        """;

Run it via Jdk17Features.java (compiled with --release 17).

JDK 8 to 17 migration note: neither feature exists on 8. Code using them compiles only at --release 10+ (var) or 15+ (text blocks).

Retrieval practice

Answer from memory. One attempt each.

1. Where is var NOT allowed?

It is not available for method formals, fields, return types or catch formals.[1]

2. A var-declared list is typed how?

Type safety is kept; the compiler infers the static type.[1]

3. Text blocks open with what?

The opening delimiter must be followed by a line terminator.[2]

4. Release that made text blocks final?

Text blocks became permanent in Java 15 after previews in 13 and 14.[2]
