Helpful NullPointerExceptions (JDK 14+, in 17 and 21)

Java (JDK 8, 17, 21) · Lesson 0027 · step 23 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: read a helpful NullPointerException message and know how to get variable names in it.

What it is

JEP 358 (Java 14) aims to "improve the usability of NullPointerExceptions generated by the JVM by describing precisely which variable was null." Example from the JEP: Cannot read field "c" because "a.b" is null. In JDK 14 it was off by default (-XX:+ShowCodeDetailsInExceptionMessages), with the intent to enable it by default later.[1]

On JDK 21 (my run)

java java/examples/NpeDemo.java
Cannot read field "city" because "<local1>.address" is null
Cannot invoke "String.trim()" because "<local2>[0]" is null

The messages appear without any flag on JDK 21. Local variable names show as <local1> here because the source launcher compiles without debug info; with javac -g the same messages read "u.address" and "names[0]" (I ran both). Fields and method names are always available.

Source: NpeDemo.java. Interview line: "In 17 and 21 the NPE message tells me which expression was null, so I read the message before the stack trace."

Retrieval practice

Answer from memory. One attempt each.

1. What does a helpful NPE message describe?

It describes precisely which variable was null.[1]

2. Release that delivered helpful NPEs?

Delivered in Java 14.[1]

3. JDK 14 flag to enable them?

-XX:+ShowCodeDetailsInExceptionMessages enabled it in JDK 14.[1]

4. Message on JDK 21 in my run needed a flag?

The messages printed with no options on JDK 21.
