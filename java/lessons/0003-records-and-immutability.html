Records and shallow immutability

Java (JDK 8, 17, 21) · Lesson 0003 · step 21 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: say what a record generates, and why record does not automatically mean immutable data.

What a record is

Per the Javadoc: "A record class is a shallowly immutable, transparent carrier for a fixed set of values, called the record components."[1] A record has a canonical constructor, a private final field per component, and a public accessor per component. Its equals, hashCode and toString "are derived from all of the component fields."[1]

That connects to lesson 1: a record honours the equals/hashCode contract[2] for free, which makes it a good HashMap key, as long as its components are themselves safe.

The word that matters: shallow

The fields are final, but a final field pointing at an ArrayList still points at a mutable list. Fix it in a compact constructor with a defensive copy:

record Team(String name, List<String> members) {
    Team {
        if (name == null || name.isBlank()) throw new IllegalArgumentException("name");
        members = List.copyOf(members);
    }
}

Retrieval practice

Answer from memory. One attempt each.

1. What is a record's equals based on?

equals is derived from all components: same record class and each component equal.[1]

2. Fields of a record are which of these?

Mandated members include a private final field for each component.[1]

3. Record holds an ArrayList component. Immutable?

Records are shallowly immutable; the referenced list can still change unless you copy it.[1]

4. Best fix for the leaky list component?

A compact constructor with List.copyOf stores an unmodifiable copy.
