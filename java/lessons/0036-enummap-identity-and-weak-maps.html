EnumMap, EnumSet, IdentityHashMap and WeakHashMap

Four special maps and sets: when each one is the right tool, and the trap hidden in each.

Java (JDK 8, 17, 21) · Lesson 0036 · step 18 of 46 · Advanced · ~22 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? HashMap is the default, but not always the best. Counting orders per status, storing permission flags, tracking visited objects while copying a graph, attaching data to objects you do not own: each has a better tool. Interviewers ask "Do you know any special-purpose maps?" to see how deep your collections knowledge goes.
Today's win: know when EnumMap/EnumSet, IdentityHashMap and WeakHashMap are the right tool, and name the trap in each.
enum
A type with a fixed list of named values, for example enum Status { NEW, PAID, SHIPPED }.
ordinal
The position of an enum value in its declaration, starting at 0: NEW is 0, PAID is 1.
bit vector
A row of on/off switches packed into one number. Switch 3 on means "element 3 is in the set".
identity (==)
Two references point to the very same object in memory, not just two objects that look equal.
reference
The arrow from a variable to an object. A strong reference keeps the object alive; a weak one does not.
garbage collector (GC)
The part of the JVM that frees objects nobody can reach any more (you met it in lesson 0007).

Before you start

Predict: you create two strings with new String("id-1") twice and put both as keys into a HashMap. What is the size? Now the same with an IdentityHashMap. Say both numbers out loud; section 2 has the real run.

1. EnumMap and EnumSet: always use them for enum keys

Picture a hotel with exactly five rooms, numbered 0 to 4. You never need to "search" for a room: the number is the location. Enum values are like that: there are only a few, and each one has a fixed position (its ordinal). So a map keyed by an enum can be a plain array.

That is EnumMap. The Javadoc says enum maps are "represented internally as arrays. This representation is extremely compact and efficient", they iterate in the natural order of the keys, which is the enum declaration order, and they are "likely (though not guaranteed) to be faster than their HashMap counterparts".EnumMap javadoc In the OpenJDK source the slot is simply vals[key.ordinal()]: no hash code, no collision.source

EnumSet goes one step further: enum sets are "represented internally as bit vectors", a "typesafe alternative to traditional int-based 'bit flags'".EnumSet javadoc In OpenJDK, an enum with up to 64 constants uses a single long (RegularEnumSet).source Factories: of, noneOf, allOf, range, complementOf.

enum Status { NEW, PAID, SHIPPED, DELIVERED, CANCELLED }

EnumMap<Status, Integer> counts = new EnumMap<>(Status.class);
counts.put(Status.SHIPPED, 4); counts.put(Status.NEW, 7); counts.put(Status.CANCELLED, 1);
// put order: SHIPPED, NEW, CANCELLED. Print order: declaration order.

EnumSet<Status> open = EnumSet.range(Status.NEW, Status.SHIPPED);
$ java java/examples/collections/SpecialPurposeMaps.java
EnumMap (declaration order): {NEW=7, SHIPPED=4, CANCELLED=1}
EnumSet.range(NEW, SHIPPED): [NEW, PAID, SHIPPED]   complement: [DELIVERED, CANCELLED]
equal strings: HashMap size 1, IdentityHashMap size 2
WeakHashMap before: 1
WeakHashMap after GC: 0  (GC timing is not guaranteed)

Traps: both reject null keys/elements (NullPointerException), and both are not synchronized. Their iterators are weakly consistent: they "will never throw ConcurrentModificationException" and may or may not show changes made during the loop.EnumMap javadocEnumSet javadoc That is different from the fail-fast HashMap iterator of lesson 0029.

2. IdentityHashMap: == instead of equals

Imagine a cloakroom. Two guests hand in identical black coats. A normal map says "same coat" (they are equals) and keeps one ticket. The cloakroom must keep two tickets, because they are two physical coats. That is identity.

In an IdentityHashMap, "two keys k1 and k2 are considered equal if and only if (k1==k2)". It is "not a general-purpose Map implementation" and "intentionally violates Map's general contract, which mandates the use of the equals method".IdentityHashMap javadoc

String k1 = new String("id-1"), k2 = new String("id-1");   // equal, but two objects
hash.put(k1, "v");     hash.put(k2, "v");
identity.put(k1, "v"); identity.put(k2, "v");
Step 1  HashMap: k2.equals(k1) is true → same key → replace → size 1
Step 2  IdentityHashMap: k2 == k1 is false → different keys → size 2

When do you need it? The Javadoc names "topology-preserving object graph transformations, such as serialization or deep-copying": the program keeps a table of objects already processed, and that table "must not equate distinct objects even if they happen to be equal". Another typical use is keeping proxy objects, for example in a debugger.IdentityHashMap javadoc It uses System.identityHashCode and is "a simple linear-probe hash table".IdentityHashMap javadoc

Trap: never use it for normal business keys like IDs or strings. Two equal strings read from a request are usually two different objects, so lookups would silently miss.

3. WeakHashMap: entries that disappear

Think of sticky notes on library books. When the library throws a book away, its sticky note goes in the bin with it. You never need to remove the note yourself, and the note never stops the library from throwing the book away.

"An entry in a WeakHashMap will automatically be removed when its key is no longer in ordinary use."WeakHashMap javadoc The map holds its keys through weak references, which do not keep an object alive. It is good for attaching metadata to objects you do not own without keeping them alive.

The run shows it: size 1 before, size 0 after key = null and a few System.gc() calls. But the GC decides when; the Javadoc warns the map "may behave as though an unknown thread is silently removing entries", so even without any writes size() can shrink over time.WeakHashMap javadoc

Three traps from the Javadoc

  1. Values are strong. "The value objects in a WeakHashMap are held by ordinary strong references", so a value that refers to its own key keeps the key alive forever. One fix the Javadoc suggests: wrap the value in a WeakReference.WeakHashMap javadoc
  2. Identity keys work best. It is "intended primarily for use with key objects whose equals methods test for object identity". With recreatable keys like String it still works, but vanished entries become confusing: you can build an equal key again and find nothing.WeakHashMap javadoc
  3. It is not a cache with a limit. Entries leave when the key is unreachable, not when the map is too big or too old. For a size or time limit use an LRU (lesson 0033) or a cache library.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

How is an EnumSet stored internally?

Enum sets are represented internally as bit vectors: one on/off bit per enum constant.

You put SHIPPED, then NEW, then CANCELLED into an EnumMap. In which order does it print?

Enum maps keep the natural order of their keys, which is the order the constants are declared.

How does IdentityHashMap compare keys?

Keys are equal if and only if k1 == k2. That is why two equal strings gave size 2.

Which task is the textbook use of IdentityHashMap?

Topology-preserving transformations (serialization, deep copy) must not merge distinct objects that happen to be equal.

When does a WeakHashMap remove an entry?

Keys are held weakly. Once nothing else strongly references the key, the GC may collect it and the entry disappears.

In a WeakHashMap, each value holds a field pointing back to its own key. What happens?

Values are held by ordinary strong references, so value → key keeps the key reachable. Wrap the value in a WeakReference or avoid the back-pointer.

An interviewer asks: "Besides HashMap and TreeMap, which Map implementations do you know, and when would you use them?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"For enum keys I always use EnumMap: it's an array indexed by the ordinal, so it's compact, fast, and iterates in declaration order. EnumSet is its partner, stored as a bit vector, so it's the typesafe replacement for int bit flags. Neither accepts nulls. IdentityHashMap compares keys with double equals instead of equals, so it deliberately breaks the Map contract; I'd only use it for object-graph work like serialization or a deep copy, where I must track each physical object even if two are equal. WeakHashMap holds its keys weakly, so an entry disappears once nobody else references the key; it's useful for attaching metadata to objects I don't own. But the values are strong, so a value pointing to its key leaks, and it's not a real cache: for a size limit I'd use an LRU or Caffeine."
