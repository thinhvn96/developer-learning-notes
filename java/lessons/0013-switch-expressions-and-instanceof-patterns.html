switch that returns a value, instanceof that casts for you

Two JDK 14 and JDK 16 features that remove a whole class of copy-paste bugs.

Java (JDK 8, 17, 21) · Lesson 0013 · step 38 of 46 · Core · ~20 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? A forgotten break in a JDK 8 switch and a wrong cast after instanceof are classic production bugs. Interviewers ask "What changed in switch after Java 8?" to check that you know modern Java, and these two features are the base for pattern matching in JDK 21.
Today's win: rewrite a JDK 8 switch statement as a switch expression, and an instanceof-then-cast chain with instanceof patterns, and explain why neither can fall through or cast wrongly.
statement
A line of code that does something, like x = 5; or if (...) {...}. It gives no value back.
expression
Code that produces a value, like 2 + 3 or name.length(). You can put it on the right of =.
fall-through
In an old switch, after one case matches, Java keeps running the next cases until it meets break.
exhaustive
Covers every possible input. Nothing is left without an answer.
cast
Telling Java "treat this object as type X", written (String) obj. If you are wrong, it throws ClassCastException at runtime.
pattern variable
A new variable that instanceof creates for you when the test succeeds, like s in obj instanceof String s.
scope
The part of the code where a variable name can be used.

Before you start

Read this JDK 8 code and say out loud what it prints when day is 1. Then check in section 1.

String r;
switch (day) {
  case 1: r = "one";
  case 2: r = "two"; break;
  default: r = "?";
}
System.out.println(r);

1. The old switch is a slide, not a button

Picture a water slide with several entry doors. You enter at door 1, but nothing stops you there: you slide past door 2, door 3, and so on, until you hit a wall. In an old switch, the case labels are the doors and break is the wall. This is fall-through.

So the code above prints two, not one. I ran it on JDK 21:

Step 1  day is 1, so Java jumps to "case 1"
Step 2  r = "one"
Step 3  no break, so Java falls into "case 2": r = "two"
Step 4  break: leave the switch
$ java Old.java
two

JEP 361 says it plainly: the old switch "supports fall through semantics by default".JEP 361 Forget one break and the bug is silent.

The new switch is a vending machine

A vending machine is different: press B2 and you get exactly one snack. JDK 14 brought arrow labels, case L ->. With them, "there is no fall through": only the code to the right of the arrow runs.JEP 361 And JEP 361 extends switch "so it can be used as either a statement or an expression".JEP 361 An expression gives back a value, so you can return it or assign it directly.

// JDK 8: a statement, a variable declared outside, a break on every line
String kind;
switch (day) {
  case 6: case 7: kind = "weekend"; break;
  case 1: case 2: case 3: case 4: case 5: kind = "weekday"; break;
  default: kind = "invalid: " + day;
}
return kind;

// JDK 14+: a switch expression
return switch (day) {
    case 6, 7 -> "weekend";
    case 1, 2, 3, 4, 5 -> "weekday";
    default -> { String msg = "invalid: " + day; yield msg; }
};

2. Read the new switch, line by line

  1. case 6, 7 ->: several constants in one label, separated by commas. JEP 361 proposes "to allow multiple constants per case, separated by commas".JEP 361
  2. -> "weekend";: the value on the right is the value of the whole switch.
  3. default -> { ... yield msg; }: when you need several lines, use a block { } and give back the value with yield. JEP 361 introduces "a new yield statement to yield a value, which becomes the value of the enclosing switch expression".JEP 361

The real example prints the three cases:

$ java java/examples/jdk17/Jdk17Features.java
{
  "name": "orders",
  "port": 8080
}
weekend, weekday, invalid: 9
3.14 4.00 6.00

The JSON lines come from the text block of lesson 0012; the last line comes from section 4 below.

Rule: a switch expression must cover every value

A switch expression must give a value for every possible input: it must be exhaustive. For an int, that usually means a default.JEP 361 Remove the default above and javac 21 refuses:

error: the switch expression does not cover all possible input values
    return switch (day) { case 6, 7 -> "weekend"; case 1, 2, 3, 4, 5 -> "weekday"; };

For an enum, listing every constant is enough. A default is not needed; instead "a default clause is inserted by the compiler", so a constant added later is caught at runtime.JEP 361

enum Size { S, M, L }
// no default needed: all 3 constants are listed
String label = switch (size) {
    case S -> "small";
    case M -> "medium";
    case L -> "large";
};

Trap: return inside a switch expression

Inside a switch expression you cannot use return, break or continue to jump out. A switch expression must "complete normally with a value, or complete abruptly by throwing an exception".JEP 361 The fix: use yield to give back a value, or throw for an impossible case.

3. instanceof: test and name it in one step

Imagine a security guard checking boxes. In JDK 8 the guard says "Is this a laptop? Yes." Then a second person says "OK, I will now treat it as a laptop." Two steps, and the second person can make a mistake. In JDK 16, the guard says "If this is a laptop, call it lap," and hands it over already labelled.

// JDK 8: test, then cast by hand (type written twice)
if (obj instanceof String) {
    String s = (String) obj;       // the JEP itself comments: "grr..."
    System.out.println(s.length());
}

// JDK 16+: pattern matching for instanceof
if (obj instanceof String s) {     // test + new variable s
    System.out.println(s.length());
}

JEP 394 says "all Java programmers are familiar with the instanceof-and-cast idiom", and replaces it.JEP 394 The old way has a hidden risk: if you copy-paste the block and change the test to Integer but forget the cast, the code still compiles and throws ClassCastException at runtime. With a pattern, the type is written once, so test and cast can never disagree.

Where can you use s? Flow scoping

The pattern variable s exists only where the compiler is sure the test passed: "A pattern variable is only in scope where the compiler can deduce that the pattern has definitely matched."JEP 394 Follow the compiler's reasoning:

In example A, s "is in scope on the right hand side of the && operator, as well as in the true block".JEP 394 Java evaluates && left to right and stops early when the left side is false, so on the right side the test has already passed. Example B is also in the JEP: after if (!(o instanceof String s)) throw ...;, s is in scope for the rest of the code.JEP 394 I ran both on JDK 21; they compile and print the expected values.

With || it is the opposite: in o instanceof String s || s.isEmpty() the right side runs only when the test failed, so s is not available there and the code does not compile.

4. Both together: the shape example

The course example uses instanceof patterns to compute the area of three shapes. Each line tests and names in one go:

static double area(Shape s) {
    if (s instanceof Circle c) return Math.PI * c.r() * c.r();
    if (s instanceof Square q) return q.side() * q.side();
    if (s instanceof Rect r)   return r.w() * r.h();
    throw new IllegalStateException();
}
$ java java/examples/jdk17/Jdk17Features.java
...
3.14 4.00 6.00

Notice the last line, throw new IllegalStateException(). The compiler cannot know that these three shapes are the only ones, so you need a fallback. In lesson 0014 you will close the list of shapes, and in JDK 21 a switch can then check it for you.

Both features are part of what "JDK 17" means for you, since 17 includes everything finalized up to 17: switch expressions became final in JDK 14, instanceof patterns in JDK 16 after previews in 14 and 15.JEP 361JEP 394

Pattern matching for switch (case Circle c ->) is a JDK 21 feature: the JDK 21 example does not compile under --release 17 (verified while writing this lesson; the compiler says patterns in switch are not supported in -source 17). See lesson 15.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

In the JDK 8 code case 1: r = "one"; case 2: r = "two"; break;, what is r when day is 1?

Without break, the old switch keeps running into case 2, which overwrites r with "two".

What happens after a case L -> label matches?

Arrow labels never fall through. One case, one result.

Which keyword gives back a value from a { } block inside a switch expression?

yield sets the value of the switch expression. return and break cannot jump out of a switch expression.

A switch expression on an int has cases 1 to 7 but no default. What happens?

A switch expression must be exhaustive. An int has many more values than 1 to 7, so you need default.

A switch expression on enum Size { S, M, L } lists S, M and L. Is a default required?

Listing every constant makes it exhaustive. The compiler inserts its own default for constants added later.

After if (!(o instanceof String s)) return;, can the next line use s?

Flow scoping: the only way past the if is that the test succeeded, so the compiler knows s is a String.

The final test: say it in 60 seconds

An interviewer asks: "What changed in switch and instanceof between Java 8 and Java 17?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"In Java 8, switch was only a statement, and it falls through: if I forget a break, the next case runs too. Since JDK 14 we have arrow labels, case 6, 7 ->, which never fall through, and switch can be an expression, so I can write return switch (day) {...}. If a case needs several lines, I use a block and yield the value. A switch expression must be exhaustive, so the compiler forces a default, or for an enum, all constants. For instanceof, JDK 16 added pattern matching: if (obj instanceof String s) tests and casts in one step, so the type is written once and the test and cast can't disagree. The variable s uses flow scoping: it's only usable where the match is certain, for example on the right of && or after an early return. Both are the base for pattern matching in switch in JDK 21."
