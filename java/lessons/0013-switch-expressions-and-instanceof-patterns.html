JDK 14 and 16: switch expressions and instanceof patterns (in JDK 17)

Today's win: rewrite an if-else cast chain with instanceof patterns and a switch statement with a switch expression.

Switch expressions (final in JDK 14)

JEP 361 extends switch "so it can be used as either a statement or an expression." Arrow labels (case L ->) do not fall through: "only the code to the right executes". A block inside a switch expression returns a value with yield. A switch expression must be exhaustive, so it needs cases for all values, typically via default.[1]

return switch (day) {
    case 6, 7 -> "weekend";
    case 1, 2, 3, 4, 5 -> "weekday";
    default -> { String msg = "invalid: " + day; yield msg; }
};

Pattern matching for instanceof (final in JDK 16)

JEP 394 replaces the test-then-cast idiom:

if (obj instanceof String s) {   // s is bound only where the match is certain
    ...
}

The binding uses flow scoping: "A pattern variable is in scope where it has definitely matched."[2]

Both are part of what "JDK 17" means for you, since 17 includes everything finalized up to 17. Source: Jdk17Features.java.

Pattern matching for switch is a JDK 21 feature: the JDK 21 example does not compile under --release 17 (verified while writing this lesson; the compiler says patterns in switch are not supported in -source 17). See lesson 15.

Retrieval practice

Answer from memory. One attempt each.

1. Does an arrow-label switch fall through?

Arrow labels prevent fall-through; only the code to the right executes.[1]

2. Keyword that returns a value from a switch block?

yield returns a value from a block in a switch expression.[1]

3. Where is a pattern variable in scope?

A pattern variable is in scope where it has definitely matched.[2]

4. Must a switch expression be exhaustive?

The compiler requires all possible values to be handled.[1]
