JDK 8: CompletableFuture and async pipelines

Java (JDK 8, 17, 21) · Lesson 0010 · step 12 of 27 · Advanced · ~12 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: chain async steps with CompletableFuture, recover from failure, and say which thread pool runs them by default and how join and get report errors differently.

What it is (JDK 8)

A CompletableFuture is a Future "that may be explicitly completed" and can act as a CompletionStage, supporting dependent functions and actions triggered on completion.[1] If several threads try to complete, completeExceptionally or cancel it, only one succeeds.[1]

Which threads run it

"All async methods without an explicit Executor argument ... are performed using the ForkJoinPool.commonPool()."[1] Interview consequence: blocking work in the common pool starves other tasks; pass your own Executor for blocking calls (or, on JDK 21, consider virtual threads, see lesson 6).

Errors

  • exceptionally(fn) recovers from an exception; handle(fn) sees both result and exception.[1]
  • join() throws the unchecked CompletionException; get() throws the checked ExecutionException; both carry the original cause.[1]
  • Cancellation is exceptional completion: cancel() acts like completeExceptionally(new CancellationException()).[1]

Retrieval practice

Answer from memory. One attempt each.

1. Default executor for async methods?

Async methods without an executor use ForkJoinPool.commonPool().[1]

2. Which method throws the unchecked CompletionException?

join() throws CompletionException; get() throws ExecutionException.[1]

3. Which method recovers from an exception?

exceptionally(Function) allows recovery from exceptions.[1]

4. Two threads call complete on one future. Outcome?

Only one of the competing completions succeeds.[1]
