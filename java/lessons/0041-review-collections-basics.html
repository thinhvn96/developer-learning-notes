interface
A list of methods a type promises to have, with no data inside, like List or Map. You write your code against it (lesson 0028).
implementation
A real class that keeps that promise with a real data structure, like ArrayList or HashMap.
amortized O(1)
Usually instant, sometimes slow (the array is copied to a bigger one), but fast on average over many calls (lesson 0002).
fail-fast
An iterator that throws ConcurrentModificationException when it notices the collection changed under it (lesson 0029).
bucket
One "mailbox" inside a HashMap. The key's hash code chooses the bucket (lesson 0001).
contract
A rule a method must follow. Here: equal objects must have the same hash code.

1. The family tree (lesson 0028)

Think of a company chart. The job titles (interfaces) say what someone must do; the people (implementations) do it in their own way. You hire by title: you declare List<Order>, not ArrayList<Order>, so you can change the person later without touching callers.

Three things to keep from lesson 0028:

  1. Map is not a Collection. It exposes keySet(), values() and entrySet() as views.
  2. The name tells the order. Hash*: no order promised. Linked*: insertion order. Tree*: sorted order.
  3. Some operations are optional. An implementation may throw UnsupportedOperationException instead; that is how unmodifiable lists fit the same List interface.

3. Removing while looping (lesson 0029)

Remember the teacher reading the attendance sheet with a version number on top. The list counts structural changes in modCount; the iterator remembers the value as expectedModCount and compares them on every next(). A for-each loop is an iterator, so list.remove(x) inside it makes the numbers differ:

$ java java/examples/collections/IteratorsAndFailFast.java
1. for-each + list.remove        -> ConcurrentModificationException
2. remove 2nd-to-last in for-each -> no exception, list=[ann, cid]  (loop silently skipped 'cid')
3. Iterator.remove()              -> [ann, cid, dan]
4. removeIf (JDK 8)               -> [ann, cid, dan]
5. ListIterator set + add         -> [ANN, ann!, BOB, bob!]
6. entry.setValue while iterating -> {a=10, b=20}
7. map.put new key while iterating -> ConcurrentModificationException

Line 2 is the one to explain in an interview: removing the second-to-last element makes cursor == size, so hasNext() is false before any check runs. It is best-effort, not a guarantee. Fixes: removeIf, Iterator.remove(), ListIterator.

4. How HashMap finds your value (lesson 0001)

The wall of 16 mailboxes: hashCode() picks the mailbox, equals() picks the letter inside it. Equal objects must have the same hash code; the opposite is not required ("Aa" and "BB" share 2112). Break the rule and the map quietly returns null:

$ java java/examples/LostKey.java
BadKey  lookup: null
GoodKey lookup: value

And keys must not change after put: the letter's address changed, so Java looks in a different mailbox. Use immutable keys or a record.

5. Mixed task: find the three bugs

Read this code like a reviewer. There are three bugs, each from a different lesson. Find them, name the lesson, and say the fix before opening the answer.

class Visit {
    final String user, page;
    Visit(String user, String page) {
        this.user = user;
        this.page = page;
    }
    @Override public boolean equals(Object o) {
        return o instanceof Visit v
            && v.user.equals(user) && v.page.equals(page);
    }
}

class Tracker {
    private final Map<Visit, Integer> counts = new HashMap<>();
    private final Deque<String> recentPages = new ArrayDeque<>();
    private final List<String> users = new ArrayList<>();

    // page is null for the home page
    void record(String user, String page) {
        Visit v = new Visit(user, page);
        Integer c = counts.get(v);
        counts.put(v, c == null ? 1 : c + 1);    // (A)
        recentPages.push(page);                  // (B)
        users.add(user);
    }

    void ban(String user) {
        for (String u : users)                   // (C)
            if (u.equals(user)) users.remove(u);
    }
}
Show the three bugs

(A) Lesson 0001. Visit overrides equals() but not hashCode(). Each new Visit gets its own default hash code, so counts.get(v) almost always looks in the wrong bucket and every count stays 1. Fix: record Visit(String user, String page) {}, or add hashCode() with Objects.hash(user, page). (A null page would also break this equals; Objects.equals handles null.)

(B) Lesson 0002. ArrayDeque rejects null, so push(null) for the home page throws NullPointerException. Fix: store a real value such as "/", or skip null pages.

(C) Lesson 0029. users.remove(u) inside a for-each throws ConcurrentModificationException, or, when the match is second-to-last, silently skips the last user. Fix: users.removeIf(user::equals).

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

Why does map.get(key) not have to look through every entry?

Same key → same number → same bucket. Only that bucket is searched. See lesson 0001.

Which statement about Map is true?

Map holds pairs, so it stands outside Collection and exposes keySet(), values(), entrySet(). See lesson 0028.

A for-each loop over [ann, bob, cid, dan] calls list.remove("bob"). What happens?

modCount went up, the iterator's expectedModCount did not, and next() checks them. See lesson 0029.

You need a stack (push and pop). Which class does the Javadoc point you to?

ArrayDeque is "likely to be faster than Stack when used as a stack". It rejects null elements. See lesson 0002.

Point overrides equals() but not hashCode(). What does map.get(new Point(1, 2)) return after map.put(new Point(1, 2), "A")?

The default hash codes differ, so Java searches the wrong bucket. No error, just null. See lesson 0001.

Why should you write List<Order> orders = new ArrayList<>() rather than declaring the type as ArrayList<Order>?

Program against the interface; the structure can change later. See lesson 0028.

The list is [ann, bob, cid]. A for-each loop removes bob. What is the result?

Size shrinks to 2 and the cursor is 2, so hasNext() is false and no check runs. Fail-fast is best-effort. See lesson 0029.

What does linkedList.get(i) do?

"Operations that index into the list will traverse the list from the beginning or the end, whichever is closer." A walk, not a jump. See lesson 0002.

Which sentence is the equals/hashCode contract?

One direction only. "Aa" and "BB" share 2112 and are still different. See lesson 0001.

You need fast contains, no duplicates, and the elements kept in the order you added them. Which class?

Hash* promises no order, Tree* sorts, Linked* keeps insertion order. See lesson 0028.

Inside a loop over map.entrySet(), which call is allowed?

Changing a value is not structural; adding or removing keys is. See lesson 0029.

You put a key in a HashMap and then change one of its fields. Why can get() no longer find it?

The entry still sits in the old bucket, but the lookup goes to the new one. Use immutable keys. See lesson 0001.

The final test: say it in 60 seconds

Three questions an interviewer could ask back to back. Do them one by one, out loud, with a timer.

Question 1: "How does a HashMap work?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"A HashMap is an array of buckets. On put, Java calls hashCode() on the key and uses it to choose a bucket; get does the same calculation and goes straight there, so both are O(1) on average. Two keys can land in the same bucket, and then equals() picks the right one. That's why equal objects must have the same hash code, so I override both or just use a record. And I keep keys immutable, because a changed key sends the lookup to the wrong bucket."

Question 2: "ArrayList or LinkedList? And what would you use for a queue?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"I default to ArrayList. It's a growing array, so get and set are constant time, and add is amortized constant: sometimes it copies the array, but on average it's cheap. LinkedList.get(i) has to walk node by node from the closer end, so I need a specific reason to choose it. For a queue or a stack I use ArrayDeque; the Javadoc says it's likely faster than Stack and LinkedList. One thing to remember: it doesn't accept null. None of these is thread safe, and I declare them as List or Deque so I can change the implementation later."

Question 3: "Can you get a ConcurrentModificationException with one thread? How do you avoid it?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"Yes. The name says concurrent, but one thread is enough: if I call list.remove inside a for-each loop, the loop's hidden iterator notices. The list counts structural changes in modCount, the iterator remembers the old value, and on next() it compares them and throws. It's only best-effort, though: removing the second-to-last element makes hasNext() false, so the last element is silently skipped. I use removeIf, or Iterator.remove(), or a ListIterator. Changing a map value with setValue is fine because it's not structural."
