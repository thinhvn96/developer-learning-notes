Wildcards (extends, super) and type erasure

Java (JDK 8, 17, 21) · Lesson 0021 · step 6 of 27 · Advanced · ~12 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: choose ? extends or ? super by asking whether a parameter is a producer or consumer, and explain type erasure.

In and out variables

  • An "in" variable (provides data to your code): upper bounded wildcard, ? extends.
  • An "out" variable (receives data): lower bounded wildcard, ? super.
  • If the "in" variable is used only through Object methods: unbounded ?.
  • If it is both in and out: no wildcard.[1]

Also: avoid wildcards in return types. And List<? extends X> is not strictly read-only: you can add null, call clear, or remove through an iterator.[1] (Interviewers call the rule "PECS": producer extends, consumer super; the tutorial states it as in/out.)

static double sum(List<? extends Number> in)     // reads Numbers
static void fill(List<? super Integer> out)      // writes Integers

Type erasure

The compiler replaces type parameters with their bounds (or Object), inserts casts where needed, and generates bridge methods to preserve polymorphism.[2] Consequence: parameterized types are not reifiable at runtime, so no instanceof List<String> and no arrays of parameterized types.[2]

java java/examples/GenericsDemo.java
filled Number  : [1, 2, 3]
filled Object  : [1, 2, 3]
same runtime class: true      # List<String> and List<Integer> share one class

Retrieval practice

Answer from memory. One attempt each.

1. A method only reads Numbers from a list. Which type?

An in variable uses an upper bounded wildcard.[1]

2. A method only adds Integers to a list. Which type?

An out variable uses a lower bounded wildcard.[1]

3. What does the compiler do with type parameters?

It replaces type parameters with bounds or Object.[2]

4. Why is instanceof List of String illegal?

Type arguments are erased, so they cannot be checked at runtime.[2]
