A map of Java collections

The interfaces, the classes behind them, and three questions that pick the right one.

Java (JDK 8, 17, 21) · Lesson 0028 · step 6 of 46 · Foundation · ~20 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? Every backend method passes lists, sets and maps around. Interviewers ask "Which collection would you use here, and why?" and "Is Map a Collection?". With one clear map in your head, the next lessons (ArrayList, HashMap, TreeMap, …) each fill in one box.
Today's win: draw the collection interface hierarchy from memory and pick an implementation by asking three questions: duplicates? order? keyed lookup?
interface
A list of methods a class promises to have. List is an interface: it says what you can do, not how.
implementation
A real class that keeps that promise with a real data structure, like ArrayList (an array inside).
element
One item stored in a collection.
duplicate
Two elements that are equals() to each other. A List allows them; a Set does not.
insertion order
Elements come back in the order you added them.
sorted order
Elements come back from smallest to largest, whatever order you added them in.
view
A live window on another object's data, not a copy. Changes in one show in the other.

1. The picture: job titles and people

A restaurant hires a "cashier". That is a job description: take money, give change. Many different people can do that job. The manager writes the schedule with the job title, not with a person's name, so a new person can take the job without rewriting the schedule.

In Java, the interface is the job title (List) and the implementation is the person (ArrayList, LinkedList). The official guide describes the Collections Framework as "a unified architecture for representing and manipulating collections", built from interfaces (what you program against), implementations (the data structures) and algorithms (static methods such as sorting).Java SE 21: Collections Framework

List<Order> orders = new ArrayList<>();   // declare the job title
orders.add(order);
process(orders);

void process(List<Order> orders) { ... }   // accepts ANY List

You declare List<Order>, not ArrayList<Order>, so the structure can change without touching callers. Notice the <Order>: every collection is generic, as you saw in lesson 0020.

2. The family tree (JDK 21)

At the top is Collection, "The root interface in the collection hierarchy". The JDK does not implement it directly: "it provides implementations of more specific subinterfaces like Set and List".Collection javadoc

The package documentation describes the important boxes:java.util package summary

  • List: ordered, access by index, duplicates allowed.
  • Set: no duplicates. A SortedSet provides "a total ordering on its elements"; a NavigableSet adds "navigation methods reporting closest matches".
  • Queue / Deque: a Deque supports "insertion and removal at both ends".
  • Map: keys to values, with SortedMap → NavigableMap for sorted keys.

Is a Map a Collection?

No. This is a favourite trick question. Map is "An object that maps keys to values", and it does not extend Collection.Map javadoc Instead it gives you collections to look through: "The Map interface provides three collection views, which allow a map's contents to be viewed as a set of keys, collection of values, or set of key-value mappings." Those are keySet(), values() and entrySet().

JDK 8 versus 21: sequenced collections

JDK 21 added three interfaces: SequencedCollection, SequencedSet and SequencedMap. A sequenced collection is "A collection that has a well-defined encounter order, that supports operations at both ends, and that is reversible." It brings methods such as getFirst(), getLast() and reversed().SequencedCollection javadoc On JDK 8 and 17 these interfaces do not exist; you write list.get(list.size() - 1) instead of list.getLast().

3. What each class really is

The example program creates one object of each common class and asks Java which interfaces it implements:

$ java java/examples/collections/FrameworkMap.java
ArrayList          List, SequencedCollection, RandomAccess
LinkedList         List, Queue, Deque, SequencedCollection
ArrayDeque         Queue, Deque, SequencedCollection
PriorityQueue      Queue
HashSet            Set
LinkedHashSet      Set, SequencedCollection
TreeSet            Set, SortedSet, NavigableSet, SequencedCollection
HashMap            Map
LinkedHashMap      Map, SequencedMap
TreeMap            Map, NavigableMap, SequencedMap
ConcurrentHashMap  Map

Read it as a decision table, step by step:

  1. The prefix tells you the order. HashSet and HashMap promise no order at all. The Linked* variants keep insertion order. The Tree* ones keep sorted order. That is why only LinkedHashSet, TreeSet, LinkedHashMap and TreeMap are sequenced.
  2. RandomAccess marks fast get(i). Only ArrayList has it: an array can jump to slot i, a linked list must walk.
  3. LinkedList is two things. It is a List and a Deque. Lesson 0002 explains why ArrayDeque is usually the better deque.
  4. PriorityQueue is only a Queue. It is not ordered from first to last; it only promises to hand out the smallest element next.

5. Trap: "optional" operations

Some interface methods are "optional": an implementation may throw UnsupportedOperationException instead of supporting them, and the Javadoc marks each one "(optional operation)".List javadoc That is how unmodifiable collections fit the same interfaces:

List<String> names = List.of("Ann", "Bob");
names.add("Cid");     // UnsupportedOperationException

The type says List, so the code compiles; the object refuses at run time. Lesson 0032 covers this in detail.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

Does Map extend Collection?

Map holds key-value pairs; keySet(), values() and entrySet() are collection views.

Which of these keeps its elements sorted?

TreeSet implements NavigableSet, a SortedSet. LinkedHashSet keeps insertion order, not sorted order.

Which list implements RandomAccess?

Only ArrayList printed RandomAccess in the run above: an array jumps straight to index i.

What happens when you call a mutator that the collection does not support, like List.of("a").add("b")?

Optional operations throw UnsupportedOperationException when not supported.

You must keep page visits in the order they happened and never store the same URL twice. Which class?

Unique → a Set; insertion order → the Linked variant. TreeSet would sort the URLs alphabetically.

Why declare a parameter as List<Order> instead of ArrayList<Order>?

Program against the interface (the job title), not the implementation (the person).

What is new in JDK 21 for List, Deque and LinkedHashMap?

SequencedCollection and SequencedMap (since 21) add operations at both ends and a reversed view.

The final test: say it in 60 seconds

An interviewer asks: "Give me an overview of the Java Collections Framework, and how you choose a collection." Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"The Collections Framework is a set of interfaces, implementations and algorithms. I code against the interfaces, like List or Map, so I can change the implementation later. Collection is the root, with List for ordered sequences with duplicates, Set for unique elements, and Queue and Deque for queues and stacks. Map is separate: it's not a Collection, but it gives me views through keySet, values and entrySet. To choose, I ask: do I look up by key? Then a Map. Must elements be unique? Then a Set. Otherwise a List or Deque. Then the order decides the class: Hash for no order, Linked for insertion order, Tree for sorted. My defaults are ArrayList, HashSet and HashMap. In JDK 21 there are also sequenced interfaces with getFirst and reversed."
