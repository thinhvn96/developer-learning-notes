var và text block: gõ ít hơn, kiểu vẫn y nguyên

Hai tính năng nhỏ của JDK 10 và JDK 15 mà bạn sẽ gặp trong mọi codebase Java hiện đại.

Java (JDK 8, 17, 21) · Bài 0012 · bước 37/46 · Core · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Khi team chuyển từ JDK 8 lên 17 hoặc 21, var và text block xuất hiện trong code review ngay ngày đầu. Interviewer rất hay hỏi "var có làm Java thành ngôn ngữ kiểu động không?" Câu trả lời là không, và bài này cho bạn thấy vì sao.
Thành quả hôm nay: viết lại một biến local kiểu JDK 8 và một chuỗi JSON nhiều dòng kiểu JDK 8 bằng var và text block, và kể ra bốn chỗ không được dùng var.
local variable
Biến khai báo bên trong một method. Nó chỉ tồn tại trong lúc method đó chạy.
initializer
Giá trị sau dấu = khi khai báo biến: trong int n = 5; thì initializer là 5.
type inference (suy luận kiểu)
Compiler tự tìm ra kiểu bằng cách nhìn code xung quanh, nên bạn không cần viết ra.
static typing (kiểu tĩnh)
Mỗi biến có một kiểu cố định, được kiểm tra lúc compile. Java xưa nay vẫn vậy.
compiler (javac)
Chương trình biến file .java thành bytecode trước khi chạy. Nhiều lỗi bị bắt ngay ở bước này.
escape sequence
Mã bắt đầu bằng dấu gạch ngược trong chuỗi, như \n (xuống dòng) hay \" (ký tự dấu nháy).
string literal
Đoạn text viết thẳng trong code giữa hai dấu nháy, như "hello".

Trước khi bắt đầu

Hãy nói to: "Sau var x = "hi";, dòng tiếp theo mình viết x = 42; được không?" Chọn có hoặc không và nêu lý do. Bạn sẽ kiểm tra lại ở mục 2.

1. var: để compiler chép kiểu giúp bạn

Hãy nghĩ tới một tờ khai ở ngân hàng. Một ô ghi "Họ tên", ô kế bên ghi "Họ tên, ghi lại cho biên lai". Viết một thứ hai lần vừa chán vừa chẳng thêm thông tin gì. Nhân viên có thể chép giúp bạn.

Code JDK 8 thường giống tờ khai đó. Kiểu được viết bên trái, rồi lại viết đúng kiểu đó bên phải:

// JDK 8: the type appears twice
ArrayList<String> names = new ArrayList<String>();
Map<String, List<Order>> byCustomer = new HashMap<String, List<Order>>();

// JDK 10+: the compiler copies the type from the right side
var names = new ArrayList<String>();
var byCustomer = new HashMap<String, List<Order>>();

JEP 286, ra mắt ở JDK 10, được viết ra để "mở rộng type inference cho các khai báo biến local có initializer".JEP 286 Nói đơn giản: nếu một local variable có initializer, bạn có thể viết var và compiler tự điền kiểu. JDK 17 và 21 đều có, vì mỗi bản phát hành giữ lại mọi thứ của các bản trước.

2. Đi theo compiler, từng bước

var names = new ArrayList<String>();
Step 1  javac reads the right side: new ArrayList<String>()
Step 2  its type is ArrayList<String>
Step 3  javac gives names that type, for ever: ArrayList<String> names

names.add("ann");   // fine
names.add(42);      // compile error: 42 is not a String
names = "hello";    // compile error: a String is not an ArrayList

Vậy câu trả lời cho "Trước khi bắt đầu" là không. Sau var x = "hi"; biến x là String, và x = 42; không compile được. Ví dụ của chính JEP 286 là var list = new ArrayList<String>();, theo JEP thì nó "suy ra ArrayList<String>".JEP 286 Java vẫn là static typing; var chỉ giúp bạn gõ ít hơn.

Để ý kiểu là ArrayList<String>, không phải List<String>. Compiler chép đúng kiểu ở vế phải.

Những chỗ không được dùng var

var dùng được cho biến local có initializer và cho biến đếm của vòng for. Nó không dùng được cho tham số method, tham số constructor, kiểu trả về, field hay tham số của catch, và cũng không dùng cho biến không có initializer.JEP 286 JEP cũng nói initializer có kiểu null là lỗi, còn array initializer hay lambda sẽ "gây ra lỗi", vì vế phải không có kiểu nào để chép.JEP 286 Mình đã chạy cả bốn trường hợp qua javac 21:

var x = null;
  error: cannot infer type for local variable x
    (variable initializer is 'null')
var y;
    (cannot use 'var' on variable without initializer)
var a = {1, 2};
    (array initializer needs an explicit target-type)
var f = () -> 1;
    (lambda expression needs an explicit target-type)

Một chi tiết thú vị: theo JEP, "định danh var không phải là keyword; nó là một reserved type name (tên kiểu được giữ chỗ)".JEP 286 Vì vậy code cũ có biến tên var vẫn compile được. Từ JDK 11 bạn còn có thể viết var cho tham số lambda, chủ yếu để gắn annotation lên chúng: (@Nonnull var x, @Nullable var y) -> x.process(y).JEP 323

Bẫy: var đi cùng diamond <>

var list = new ArrayList<>();   // ArrayList<Object>, not what you wanted
list.add(1);
list.add("a");                   // compiles: anything goes in

Diamond <> bình thường lấy kiểu từ vế trái. Với var thì vế trái trống, nên compiler không có gì để chép. Style guide của OpenJDK đánh dấu đúng trường hợp này là "NGUY HIỂM: suy ra thành PriorityQueue<Object>".LVTI style guide Guide này cũng cảnh báo về số literal: với var, 17 thành int, dù bạn muốn long.LVTI style guide

Cách sửa: khi dùng var, luôn viết type argument ở vế phải (new ArrayList<String>()), và chỉ dùng var khi vế phải làm kiểu hiện rõ cho người đọc.

3. Text block: dán text đúng như nó hiển thị

Thử tưởng tượng bạn chép tay một bài thơ, nhưng mỗi lần xuống dòng phải viết chữ "XUỐNG_DÒNG" và mỗi dấu nháy phải viết "DẤU_NHÁY". Bạn sẽ chép sai, và chẳng ai đọc nổi kết quả. Đó chính là một chuỗi JSON trong JDK 8:

// JDK 8: escapes and + everywhere
String json = "{\n" +
              "  \"name\": \"orders\",\n" +
              "  \"port\": 8080\n" +
              "}\n";

// JDK 15+: a text block
var json = """
        {
          "name": "orders",
          "port": 8080
        }
        """;

JEP 378 định nghĩa: "Text block là một string literal nhiều dòng, tránh được hầu hết escape sequence, tự động định dạng chuỗi theo cách dễ đoán, và cho lập trình viên quyền kiểm soát định dạng khi cần."JEP 378 Nó chính thức (final) ở JDK 15, sau hai lần preview ở JDK 13 và 14.JEP 378

Các quy tắc bạn cần nhớ:

  1. Mở đầu bằng """ rồi xuống dòng. Không được viết text trên cùng dòng với """ mở.JEP 378
  2. Dấu nháy kép bên trong không cần escape.
  3. Phần thụt lề mà mọi dòng cùng có sẽ bị cắt bỏ, và khoảng trắng thừa ở cuối mỗi dòng bị xoá.JEP 378
  4. Kết quả là một String bình thường: JEP gọi nó là "một constant expression kiểu String, giống hệt string literal".JEP 378

4. Compiler dọn một text block như thế nào

JEP 378 xử lý nội dung theo ba bước.JEP 378 Hãy theo dõi chúng trên ví dụ ở trên:

Step 1  Line breaks become \n, whatever your editor used (Windows \r\n too).
Step 2  Find the smallest indentation of the non-blank lines and of the
        closing """ line: 8 spaces. Remove 8 spaces from every line.
        Remove trailing spaces at the end of each line.
Step 3  Turn escape sequences like \n, \t, \s into real characters.
Result  "{\n  \"name\": \"orders\",\n  \"port\": 8080\n}\n"

Dấu """ mở không ảnh hưởng tới thụt lề, "nhưng vị trí của """ đóng thì có ảnh hưởng nếu nó nằm trên một dòng riêng".JEP 378 Dời nó sang trái thì bạn giữ lại một phần thụt lề. Mình đã chạy cả hai phiên bản:

String t1 = """
        <p>
          hi
        </p>
        """;               // closing """ in line with <p>

String t2 = """
        <p>
          hi
        </p>
    """;                   // closing """ 4 columns further left

t1 prints:
<p>
  hi
</p>
t2 prints:
    <p>
      hi
    </p>

Thêm nữa: khi """ đóng nằm trên dòng riêng, chuỗi kết thúc bằng \n. Đặt nó ngay sau chữ cuối cùng nếu bạn không muốn dấu xuống dòng cuối đó.JEP 378

Hai escape mới và một method mới

Có hai escape đi kèm tính năng này. Theo JEP, \<line-terminator> (dấu gạch ngược ở đúng cuối dòng) "chặn hẳn việc chèn ký tự xuống dòng", còn \s "đơn giản là một khoảng trắng".JEP 378 \s hữu ích vì khoảng trắng cuối dòng bình thường sẽ bị xoá. JEP cũng thêm String::formatted(Object... args) để điền giá trị vào:JEP 378

String sql = """
    SELECT id, name \
    FROM users""";                       // "SELECT id, name FROM users" on one line
String hi = """
    Hello, %s!""".formatted("Ann");       // "Hello, Ann!"

Chạy ví dụ thật

Ví dụ của khoá học dùng var, một text block và một switch expression (bài sau). Nó compile được với --release 17:

$ java java/examples/jdk17/Jdk17Features.java
{
  "name": "orders",
  "port": 8080
}
weekend, weekday, invalid: 9
3.14 4.00 6.00

Bốn dòng đầu đến từ text block: 16 khoảng trắng thụt lề trong source đã biến mất, chỉ còn 2 khoảng trắng bạn thật sự muốn.

Ghi chú khi nâng từ JDK 8 lên 17: JDK 8 không có tính năng nào trong hai cái này. Code dùng chúng chỉ compile được với --release 10+ (var) hoặc --release 15+ (text block). Nếu library của bạn vẫn phải chạy trên JDK 8 thì không dùng được.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Sau var x = "hi";, chuyện gì xảy ra với x = 42;?

Compiler chốt kiểu của x là String từ initializer. Java vẫn là kiểu tĩnh; var chỉ giúp gõ ít hơn.

Chỗ nào được phép dùng var?

var dành cho biến local có initializer và biến đếm vòng for. Không dùng cho tham số, field, kiểu trả về hay tham số catch.

Lỗi trong var ids = new ArrayList<>(); ids.add("x"); là gì, khi bạn muốn một list Long?

Với var không có vế trái để diamond chép kiểu, nên nó lùi về Object. Hãy viết new ArrayList<Long>().

Dòng nào là cách mở đầu hợp lệ của một text block?

""" mở phải đi kèm một dấu xuống dòng; nội dung bắt đầu ở dòng kế tiếp.

Bạn dời """ đóng của text block sang trái bốn cột. Điều gì thay đổi?

Dấu đóng nằm trên dòng riêng được tính khi tìm thụt lề chung. Càng sang trái thì càng ít bị cắt.

Text block trở thành tính năng chính thức (không còn preview) ở bản nào?

Text block là preview ở 13 và 14, chính thức ở 15. var có sớm hơn, từ JDK 10.

Bài kiểm tra cuối: nói trong 60 giây

Interviewer hỏi: "var trong Java là gì, nó có làm Java thành kiểu động không? Còn text block là gì?" Bấm giờ. Trả lời to, thành câu đầy đủ. Rồi bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"var có từ JDK 10, là local-variable type inference: em viết var và compiler lấy kiểu từ vế phải. Nó không làm Java thành dynamic. Nếu em viết var names = new ArrayList<String>() thì names là ArrayList<String> mãi mãi, gán một số vào là không compile. Nó chỉ dùng cho biến local có initializer và biến vòng lặp, không dùng cho field, tham số hay kiểu trả về, và không dùng với null hay lambda vì không có kiểu để chép. Có một cái bẫy: var đi với diamond sẽ ra ArrayList<Object>. Em chỉ dùng khi nhìn vế phải là thấy rõ kiểu. Còn text block thì chính thức từ JDK 15: chuỗi nhiều dòng nằm giữa ba dấu nháy. Không cần \n hay \", compiler tự cắt phần thụt lề chung, và vị trí dấu nháy đóng quyết định cắt bao nhiêu. Rất tiện cho JSON, SQL và test data."
