Default method: thêm vào interface mà không làm hỏng ai

Vì sao JDK 8 cho interface chứa code, và method nào chạy khi hai interface "cãi nhau".

Java (JDK 8, 17, 21) · Bài 0009 · bước 24/46 · Core · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Ngày nào bạn cũng gọi default method (list.forEach, map.getOrDefault, predicate.and). Interviewer thích hỏi "Vì sao có default method?" rồi đưa ra một class implement hai interface có cùng một default: "Cái nào chạy?"
Thành quả hôm nay: giải thích trong một câu vì sao có default method, và đoán đúng move() nào chạy trong ba tình huống: class với interface, hai interface, và một interface extend interface khác.
implement
Một class implement một interface khi nó hứa cung cấp các method của interface đó: class Duck implements Walker.
extend
Một class extend một class cha và thừa hưởng code của nó. Một interface có thể extend các interface khác.
default method
Method trong interface đã có sẵn thân, đánh dấu bằng chữ default.
static method
Method thuộc về chính kiểu đó, không thuộc về object nào. Gọi bằng Type.method().
signature
Tên method cộng với kiểu các tham số, ví dụ move(). Hai method cùng signature sẽ tranh nhau.
abstract class
Class không tạo trực tiếp được; nó có thể chứa field và các method chưa hoàn thiện cho class con.
binary compatibility
Code cũ đã compile vẫn chạy được với phiên bản mới của library, không cần compile lại.

Trước khi bắt đầu

Nói thành tiếng: "Một class extend Base (có move()) và implement Walker (có default move()). Cái nào chạy?" Hãy đoán. Bạn sẽ kiểm tra bằng output thật ở phần 3.

1. Vấn đề: một quy định mới làm mọi thành viên vi phạm

Hãy tưởng tượng một câu lạc bộ thể thao có cuốn nội quy mà mọi thành viên phải theo. Câu lạc bộ thêm quy định mới: "mọi thành viên phải viết báo cáo hằng tháng". Chỉ sau một đêm, ai chưa từng viết báo cáo đều đang vi phạm. Trừ khi câu lạc bộ thêm: "nếu bạn không tự viết, chúng tôi dùng mẫu chuẩn này". Thế là không ai vi phạm cả.

Interface chính là cuốn nội quy đó. Trước JDK 8, thêm một method vào interface sẽ làm hỏng mọi class đang implement nó: class nào cũng bỗng thiếu một method. Vì vậy JDK 8 cần default method để thêm forEach và stream vào collection. Tutorial nói chúng "cho phép bạn thêm chức năng mới vào interface của library và đảm bảo binary compatibility với code viết cho các phiên bản cũ của interface đó."Default methods tutorial

interface Walker {
  String name();                                  // abstract: each class must write it
  default String move() { return "walk"; }       // new rule WITH a standard body
}

class Cat implements Walker {
  public String name() { return "cat"; }         // no move() here, still compiles
}
new Cat().move();                                 // "walk"

Bạn khai báo bằng từ khóa default kèm thân method.Default methods tutorial Đặc tả ngôn ngữ nói phần thân đó "cung cấp cài đặt mặc định cho mọi class implement interface mà không override method này".JLS 9.4

Static method trong interface

JDK 8 cũng cho phép static method trong interface, để các method tiện ích nằm ngay trong interface "thay vì trong một class riêng".Default methods tutorial Bạn gọi chúng qua tên interface, ví dụ Comparator.naturalOrder(). Mọi method trong interface đều ngầm định là public, trừ khi khai báo private.JLS 9.4

2. Quy tắc một: class thắng

Nghĩ về công thức nấu ăn của gia đình. Bố mẹ bạn (superclass) truyền cho bạn công thức nấu canh, và cuốn sách nấu ăn bạn mua (interface) cũng có công thức canh. Ở nhà, bạn nấu theo công thức gia đình. Java cũng vậy: method thật trong class, hoặc trong superclass, luôn thắng default của interface.Default methods tutorial

Đặc tả ngôn ngữ nói chính xác hơn: class không thừa hưởng một default method nếu một method cụ thể nó thừa hưởng từ superclass có cùng signature.JLS 8.4.8

3. Quy tắc hai: hai interface, cùng default → bạn phải chọn

Bây giờ class không có method nào từ superclass, nhưng hai interface đều mang theo default move(). Java không đoán thay bạn. Đặc tả: "Là lỗi compile nếu class C thừa hưởng một default method có signature override-equivalent với một method khác mà C thừa hưởng" (có một ngoại lệ hiếm cho abstract method của superclass).JLS 8.4.8.4 "Override-equivalent" ở đây đơn giản là "cùng signature".

Để sửa, bạn override method trong class. Bên trong, bạn có thể gọi phiên bản của một interface cụ thể bằng cú pháp InterfaceName.super.method().

Lần theo ví dụ từng bước

new Duck().move();
Step 1  Duck has its own move()            → run it
Step 2  Walker.super.move()                → "walk"
Step 3  Swimmer.super.move()               → "swim"
Step 4  "walk" + " and " + "swim"          → "walk and swim"

new Robot().move();
Step 1  Robot has no move() of its own
Step 2  superclass Base has move()         → class wins
Step 3  Walker's default is never used     → "base"
$ java java/examples/jdk8/DefaultMethods.java
walk and swim
base

Dòng đầu là Duck tự giải quyết xung đột; dòng hai là Robot, nơi method của class thắng default của interface.

4. Quy tắc ba: khi một interface extend interface khác

Một interface có thể extend một interface có default. Tutorial liệt kê ba lựa chọn:Default methods tutorial

  1. Không nhắc tới nó. Interface mới cứ thế thừa hưởng default.
  2. Khai báo lại không có thân. Nó trở lại thành abstract, nên mọi class implement phải tự viết.
  3. Định nghĩa lại với thân mới. Nó override default; interface cụ thể hơn thắng.
interface FastWalker extends Walker {
  default String move() { return "run"; }   // choice 3: redefine
}
class Dog implements Walker, FastWalker {}
new Dog().move();                            // "run": FastWalker is more specific

Ở đây không có xung đột: FastWalker đã override Walker.move(), nên chỉ còn một ứng viên.

Lỗi hay gặp

  • Quên override trong hình kim cương. Code không compile. Cách sửa: override và chọn bằng X.super.method().
  • Cố cho equals, hashCode hay toString một default. "Là lỗi compile nếu một default method override-equivalent với một method không private của class Object", vì class nào cũng đã thừa hưởng method đó từ Object.JLS 9.4.1.2
  • Dùng interface làm chỗ giữ state. Interface không có instance field, nên default method chỉ có thể gọi các method khác.
Góc interview: "Default method so với abstract class?" Một interface có thể được nhiều class không liên quan implement và vẫn không có instance state; abstract class có thể giữ field nhưng một class chỉ extend được một class. Default method tồn tại chủ yếu để interface tiến hóa, đúng như động cơ mà tutorial trình bày.

JDK 8 so với 17 và 21

Default và static method trong interface có từ JDK 8. Trong đặc tả ngôn ngữ JDK 21, method của interface còn có thể là private (và private static), giúp nhiều default dùng chung một helper; JDK 8 chưa có điều này.JLS 9.4 Các quy tắc "ai thắng" giống nhau trên 8, 17 và 21.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Lý do chính để thêm default method vào JDK 8 là gì?

Default method cho phép library phát triển interface (như thêm forEach vào collection) mà vẫn giữ binary compatibility với code cũ.

Robot extends Base implements Walker. Cả Base và Walker có move(); của Walker là default. new Robot().move() chạy cái nào?

Method cụ thể từ class hoặc superclass luôn thắng default của interface. Output thật là base.

class Duck implements Walker, Swimmer {}, và cả hai interface đều có default move(). Chuyện gì xảy ra?

Hai default thừa hưởng cùng signature là lỗi compile. Duck phải override và chọn, ví dụ bằng Walker.super.move().

Bên trong Duck, làm sao gọi phiên bản move() của Walker?

Cú pháp là InterfaceName.super.method(). Ép kiểu this vẫn gọi bản override của chính Duck.

Một interface extend Walker và khai báo lại String move(); không có thân. Giờ move() là gì?

Khai báo lại default method làm nó thành abstract, nên mọi class implement interface mới phải tự viết.

interface Named { default String toString() { return "x"; } } sai ở đâu?

Default method override-equivalent với method không private của Object là lỗi compile. Class nào cũng đã thừa hưởng toString từ Object, và class đằng nào cũng thắng.

Bài kiểm tra cuối: nói trong 60 giây

Interviewer hỏi: "Vì sao có default method, và chuyện gì xảy ra khi hai interface định nghĩa cùng một default?" Bấm giờ. Trả lời thành tiếng, nói thành câu đầy đủ. Sau đó bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"Default method có từ JDK 8 để tác giả library thêm method vào interface có sẵn mà không làm hỏng mọi class đang implement nó. Nhờ vậy Collection mới có stream() và Iterable có forEach. Khi có xung đột thì có ba quy tắc. Một, class thắng: nếu class của em hoặc superclass có method đó thì default của interface bị bỏ qua. Hai, interface cụ thể hơn thắng, tức nếu một interface extend interface khác và override default thì dùng bản đó. Ba, nếu hai interface không liên quan cho em cùng một default thì code không compile cho tới khi em override; bên trong em có thể gọi Walker.super.move() để tái sử dụng một bản. So với abstract class: interface không có instance field, nhưng một class implement được nhiều interface còn chỉ extend được một class."

Bây giờ làm bài tập

Bài tập 0009: hình kim cương của default. Gửi dự đoán của bạn cho giáo viên trước, rồi mới chạy code.

Ví dụ chạy được: jdk8/DefaultMethods.java
