Bản đồ các collection trong Java

Các interface, những class đứng sau chúng, và ba câu hỏi giúp chọn đúng.

Java (JDK 8, 17, 21) · Bài 0028 · bước 6/46 · Foundation · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Method backend nào cũng truyền qua lại list, set và map. Interviewer hỏi "Chỗ này bạn dùng collection nào, vì sao?" và "Map có phải là Collection không?". Có sẵn một tấm bản đồ rõ ràng trong đầu, các bài sau (ArrayList, HashMap, TreeMap, …) mỗi bài chỉ cần điền vào một ô.
Thành quả hôm nay: vẽ lại cây interface của collection theo trí nhớ và chọn implementation bằng ba câu hỏi: có trùng lặp không? thứ tự thế nào? có tra theo key không?
interface
Danh sách method mà một class hứa sẽ có. List là interface: nó nói bạn làm được gì, không nói làm thế nào.
implementation
Một class thật giữ lời hứa đó bằng một cấu trúc dữ liệu thật, như ArrayList (bên trong là một mảng).
element
Phần tử: một món được lưu trong collection.
duplicate
Hai phần tử equals() với nhau. List cho phép; Set thì không.
insertion order
Thứ tự chèn: phần tử trả ra theo đúng thứ tự bạn đã thêm vào.
sorted order
Thứ tự sắp xếp: phần tử trả ra từ nhỏ tới lớn, bất kể bạn thêm theo thứ tự nào.
view
Một "cửa sổ" sống nhìn vào dữ liệu của object khác, không phải bản sao. Thay đổi bên này hiện ra bên kia.

Trước khi bắt đầu

Nói thành tiếng: "Kể ba interface collection và mỗi cái một class. Map có phải là một trong các interface collection không?" Trả lời trước khi cuộn xuống. Bạn sẽ đối chiếu với sơ đồ ở phần 2.

1. Hình dung: chức danh và con người

Một nhà hàng tuyển "thu ngân". Đó là mô tả công việc: nhận tiền, thối tiền. Nhiều người khác nhau làm được việc đó. Quản lý xếp lịch theo chức danh, không theo tên người, nên người mới vào thay mà không phải viết lại lịch.

Trong Java, interface là chức danh (List) và implementation là con người (ArrayList, LinkedList). Tài liệu chính thức mô tả Collections Framework là "một kiến trúc thống nhất để biểu diễn và thao tác với collection", gồm các interface (thứ bạn lập trình dựa vào), các implementation (cấu trúc dữ liệu) và các thuật toán (method static như sắp xếp).Java SE 21: Collections Framework

List<Order> orders = new ArrayList<>();   // declare the job title
orders.add(order);
process(orders);

void process(List<Order> orders) { ... }   // accepts ANY List

Bạn khai báo List<Order>, không phải ArrayList<Order>, để có thể đổi cấu trúc mà không đụng tới bên gọi. Để ý <Order>: mọi collection đều là generic, như bạn đã thấy ở bài 0020.

2. Cây gia phả (JDK 21)

Trên cùng là Collection, "interface gốc của cây collection". JDK không implement nó trực tiếp: "nó cung cấp implementation cho các interface con cụ thể hơn như Set và List".Collection javadoc

Tài liệu của package mô tả các ô quan trọng:java.util package summary

  • List: có thứ tự, truy cập theo index, cho phép trùng lặp.
  • Set: không trùng lặp. SortedSet cung cấp "một thứ tự toàn phần trên các phần tử"; NavigableSet thêm "các method điều hướng trả về phần tử gần khớp nhất".
  • Queue / Deque: Deque hỗ trợ "chèn và xóa ở cả hai đầu".
  • Map: từ key tới value, với SortedMap → NavigableMap cho key được sắp xếp.

Map có phải là Collection không?

Không. Đây là câu hỏi mẹo rất được ưa chuộng. Map là "một object ánh xạ key tới value", và nó không kế thừa Collection.Map javadoc Thay vào đó nó cho bạn các collection để nhìn vào: "Interface Map cung cấp ba collection view, cho phép xem nội dung map như một set các key, một collection các value, hoặc một set các cặp key-value." Đó là keySet(), values() và entrySet().

JDK 8 so với 21: sequenced collection

JDK 21 thêm ba interface: SequencedCollection, SequencedSet và SequencedMap. Một sequenced collection là "một collection có thứ tự duyệt xác định rõ, hỗ trợ thao tác ở cả hai đầu, và đảo ngược được." Nó mang theo các method như getFirst(), getLast() và reversed().SequencedCollection javadoc Trên JDK 8 và 17 các interface này chưa có; bạn viết list.get(list.size() - 1) thay cho list.getLast().

3. Mỗi class thật ra là gì

Chương trình ví dụ tạo một object cho mỗi class thông dụng và hỏi Java xem nó implement những interface nào:

$ java java/examples/collections/FrameworkMap.java
ArrayList          List, SequencedCollection, RandomAccess
LinkedList         List, Queue, Deque, SequencedCollection
ArrayDeque         Queue, Deque, SequencedCollection
PriorityQueue      Queue
HashSet            Set
LinkedHashSet      Set, SequencedCollection
TreeSet            Set, SortedSet, NavigableSet, SequencedCollection
HashMap            Map
LinkedHashMap      Map, SequencedMap
TreeMap            Map, NavigableMap, SequencedMap
ConcurrentHashMap  Map

Đọc nó như một bảng quyết định, từng bước:

  1. Tiền tố cho biết thứ tự. HashSet và HashMap không hứa thứ tự nào cả. Các biến thể Linked* giữ thứ tự chèn. Các biến thể Tree* giữ thứ tự sắp xếp. Đó là lý do chỉ LinkedHashSet, TreeSet, LinkedHashMap và TreeMap là sequenced.
  2. RandomAccess đánh dấu get(i) nhanh. Chỉ ArrayList có nó: mảng nhảy thẳng tới ô i, còn linked list phải đi bộ.
  3. LinkedList là hai thứ một lúc. Nó vừa là List vừa là Deque. Bài 0002 giải thích vì sao ArrayDeque thường là deque tốt hơn.
  4. PriorityQueue chỉ là Queue. Nó không có thứ tự từ đầu tới cuối; nó chỉ hứa lần sau đưa ra phần tử nhỏ nhất.

4. Ba câu hỏi chọn ra cấu trúc

Hãy nghĩ tới bác sĩ hỏi vài câu trước khi kê thuốc. Bạn hỏi ba câu: Mình có tra cứu theo key không? Phần tử có phải duy nhất không? Mình cần thứ tự nào?

5. Bẫy: các thao tác "optional"

Một số method của interface là "optional" (tùy chọn): implementation có thể ném UnsupportedOperationException thay vì hỗ trợ chúng, và Javadoc đánh dấu từng method là "(optional operation)".List javadoc Đó là cách các collection không sửa được vẫn khớp vào cùng các interface:

List<String> names = List.of("Ann", "Bob");
names.add("Cid");     // UnsupportedOperationException

Kiểu ghi là List, nên code compile được; object thì từ chối lúc chạy. Bài 0032 nói kỹ về chuyện này.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Map có kế thừa Collection không?

Map chứa các cặp key-value; keySet(), values() và entrySet() là collection view.

Cái nào giữ phần tử theo thứ tự sắp xếp?

TreeSet implement NavigableSet, một SortedSet. LinkedHashSet giữ thứ tự chèn, không phải thứ tự sắp xếp.

List nào implement RandomAccess?

Chỉ ArrayList in ra RandomAccess trong lần chạy ở trên: mảng nhảy thẳng tới index i.

Chuyện gì xảy ra khi bạn gọi một method thay đổi mà collection không hỗ trợ, như List.of("a").add("b")?

Các thao tác optional ném UnsupportedOperationException khi không được hỗ trợ.

Bạn phải giữ các lượt xem trang theo đúng thứ tự xảy ra và không bao giờ lưu cùng một URL hai lần. Dùng class nào?

Duy nhất → một Set; thứ tự chèn → biến thể Linked. TreeSet sẽ sắp các URL theo bảng chữ cái.

Vì sao khai báo tham số là List<Order> thay vì ArrayList<Order>?

Lập trình dựa vào interface (chức danh), không dựa vào implementation (con người).

JDK 21 có gì mới cho List, Deque và LinkedHashMap?

SequencedCollection và SequencedMap (từ bản 21) thêm thao tác ở hai đầu và một view đảo ngược.

Bài kiểm tra cuối: nói trong 60 giây

Interviewer hỏi: "Cho tôi cái nhìn tổng quan về Java Collections Framework, và bạn chọn collection thế nào." Bấm giờ. Trả lời thành tiếng, nói thành câu đầy đủ. Rồi bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"Collections Framework là một bộ gồm interface, implementation và thuật toán. Em code dựa vào interface, như List hay Map, để sau này đổi implementation được. Collection là gốc, có List cho dãy có thứ tự và cho phép trùng, Set cho phần tử duy nhất, và Queue, Deque cho hàng đợi và stack. Map thì tách riêng: nó không phải Collection, nhưng cho em các view qua keySet, values và entrySet. Để chọn, em hỏi: có tra theo key không? Có thì dùng Map. Phần tử phải duy nhất? Thì dùng Set. Còn lại là List hoặc Deque. Sau đó thứ tự quyết định class: Hash là không thứ tự, Linked là thứ tự chèn, Tree là sắp xếp. Mặc định của em là ArrayList, HashSet và HashMap. Từ JDK 21 còn có các interface sequenced với getFirst và reversed."
