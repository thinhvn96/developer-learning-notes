Phần nào bị null? Helpful NullPointerException

Từ JDK 14, thông báo lỗi chỉ đúng vào mắt xích bị thiếu trong chuỗi.

Java (JDK 8, 17, 21) · Bài 0027 · bước 41/46 · Core · ~15 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? NullPointerException (NPE) là lỗi Java phổ biến nhất trong log production. Trên JDK 8, log chỉ cho bạn biết dòng nào. Trên JDK 17 và 21, nó cho biết biểu thức nào bị null, nếu bạn biết cách đọc. Interviewer rất thích hỏi "Bạn debug một NPE thế nào?"; đây là bước đầu tiên theo cách hiện đại.
Thành quả hôm nay: đọc một helpful NPE message và chỉ ra phần bị null, giải thích vì sao đôi khi nó ghi <local1>, và nói được nó xuất hiện ở JDK nào, bật mặc định từ JDK nào.
null
Giá trị đặc biệt nghĩa là "biến này không trỏ tới object nào".
NullPointerException (NPE)
Lỗi Java ném ra khi bạn dùng một null như thể nó là object, ví dụ gọi method trên nó.
exception message
Đoạn text bên trong exception. Bạn đọc nó bằng e.getMessage(); trong log nó được in sau tên exception.
stack trace
Danh sách các lời gọi method dẫn tới lỗi, kèm tên file và số dòng.
JVM
Java Virtual Machine: chương trình chạy bytecode đã compile của bạn. Nó phát hiện null và ném NPE.
debug information
Dữ liệu thêm mà javac có thể lưu vào file .class, như số dòng và tên biến local.
JVM flag
Tuỳ chọn bạn truyền cho java trên dòng lệnh, như -XX:+SomeOption.

Trước khi bắt đầu

Nhìn dòng này và nói to: "Nếu nó ném NPE, những biến nào có thể bị null?" Đếm xem có mấy cái.

System.out.println(order.customer.address.city.toUpperCase());

1. Thông báo của JDK 8: "có gì đó ở dòng 7"

Hình dung chỉ đường tới căn hộ của một người bạn: "tới toà nhà, lên tầng 3, tìm căn B, rồi gõ cửa". Bạn tới nơi và không đi tiếp được. Một người hướng dẫn tệ sẽ nói: "Chỉ đường của bạn hỏng ở đâu đó." Một người hướng dẫn tốt sẽ nói: "Bạn không tìm được căn B, vì tầng 3 không tồn tại."

NPE của JDK 8 là người hướng dẫn tệ. Đây là đoạn code ở trên, chạy với detail message bị tắt, cho ra kết quả giống JDK cũ:

$ java -XX:-ShowCodeDetailsInExceptionMessages -cp g Order
Exception in thread "main" java.lang.NullPointerException
	at Order.main(Order.java:7)

Dòng 7 có bốn chỗ có thể null: order, customer, address và city. JEP 358 nói thẳng: "Tên file và số dòng không chỉ ra chính xác biến nào bị null."JEP 358 Trên JDK 8, bạn phải thêm log hoặc mở debugger để tìm.

2. Thông báo của JDK 14+: đúng mắt xích

JEP 358 (Java 14) nhằm "cải thiện tính dễ dùng của NullPointerException do JVM tạo ra, bằng cách mô tả chính xác biến nào bị null".JEP 358 Cùng chương trình đó trên JDK 21, không flag nào:

$ java -cp g Order
Exception in thread "main" java.lang.NullPointerException: Cannot read field "city" because "order.customer.address" is null
	at Order.main(Order.java:7)

Đọc nó từng bước

Step 1  "order" was evaluated: not null
Step 2  ".customer" was read: not null
Step 3  ".address" was read: it is null
Step 4  the JVM tries to read ".city" from null → NPE
Message = "Cannot read field "city"" (step 4) + "because "order.customer.address" is null" (step 3)

JEP đưa ra ví dụ cùng dạng: Cannot read field "c" because "a.b" is null.JEP 358 Vậy câu trả lời cho "Trước khi bắt đầu" là: bốn thứ có thể null, và message cho bạn biết cái nào đã null.

Nửa đầu thay đổi theo thao tác. Vài message thật từ JDK 21:

// calling a method on a null that a method returned
Cannot invoke "Npe2$User.getName()" because the return value of "Npe2.find(int)" is null
// a chain of method calls
Cannot invoke "String.toUpperCase()" because the return value of "Npe2$User.getName()" is null
// unboxing a null Integer into an int
Cannot invoke "java.lang.Integer.intValue()" because "<local1>" is null

Cái cuối là bẫy kinh điển: int x = map.get(key); ném NPE khi không có key, vì Java tự gọi intValue() trên giá trị null.

3. Vì sao nó ghi <local1>?

Chạy ví dụ của khoá học:

$ java java/examples/NpeDemo.java
Cannot read field "city" because "<local1>.address" is null
Cannot invoke "String.trim()" because "<local2>[0]" is null

Các message xuất hiện mà không cần flag nào trên JDK 21. Nhưng tên biến local hiện ra là <local1> và <local2>. Vì sao? Tên biến local chỉ có trong file .class nếu javac lưu chúng làm debug information. Khi không có, JEP 358 nói message dùng <locali> (một số thứ tự ô nhớ) thay thế; tên chỉ hiện khi "debug information được đưa vào file class (qua javac -g)".JEP 358 Source launcher compile mà không có debug info đó. Với javac -g, cùng các message ấy thành:

$ javac -g -d out java/examples/NpeDemo.java && java -cp out NpeDemo
Cannot read field "city" because "u.address" is null
Cannot invoke "String.trim()" because "names[0]" is null

Mình đã chạy cả hai. Tên field và tên method lúc nào cũng có; chỉ tên biến local mới cần -g. Chỉ chạy javac thường là chưa đủ: theo tài liệu, "mặc định chỉ sinh thông tin số dòng và file source", còn -g "sinh toàn bộ debug information, gồm cả biến local".javac docs

4. JDK nào, flag nào, NPE nào

  1. JDK 8 tới 13: không có detail message. Bạn chỉ có tên exception và stack trace.
  2. JDK 14: tính năng đã có nhưng mặc định tắt. Bạn bật bằng -XX:+ShowCodeDetailsInExceptionMessages; JEP nêu ý định bật nó mặc định ở bản sau.JEP 358
  3. JDK 15 trở đi (tức 17 và 21): bật mặc định. Thay đổi ở JDK 15 ghi rằng "Helpful NullPointerException của JEP 358 được in ra theo mặc định".JDK-8233014 Bạn có thể tắt bằng -XX:-ShowCodeDetailsInExceptionMessages, chính là cách mình tạo ra output "kiểu cũ" ở mục 1.

Hai chi tiết interviewer thích:

  • Theo JEP, "chỉ những NPE được JVM trực tiếp tạo và ném ra mới có null-detail message".JEP 358 Nếu code của bạn throw new NullPointerException(), getMessage() trả về null. Mình đã chạy: nó in ra null.
  • Message được "tính khi cần", chỉ khi getMessage() được gọi, vì rất nhiều NPE bị catch rồi bỏ qua.JEP 358

Bẫy: chỉ log một nửa exception

Có code log "error: " + e.getMessage(). Trên JDK 8, với NPE nó in ra error: null, nên team quen bỏ qua dòng đó. Trên JDK 17 và 21, message lại là phần hữu ích nhất. Cách sửa: log chính object exception (ví dụ log.error("failed", e)), để giữ cả message lẫn stack trace.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Helpful NullPointerException message thêm vào thông tin gì?

JEP 358 mô tả "chính xác biến nào bị null", cộng với việc JVM đang cố làm gì.

Message là Cannot read field "city" because "order.customer.address" is null. Cái gì bị null?

Phần "because" chỉ ra biểu thức bị null. order và customer vẫn ổn; đọc city từ address null thì lỗi.

Vì sao message ghi "<local1>.address" thay vì "u.address"?

Tên biến local chỉ có trong file class khi compile bằng javac -g. Không có thì JVM hiện số thứ tự ô nhớ.

Câu nào về các phiên bản JDK là đúng?

JEP 358 đưa vào JDK 14, bật bằng -XX:+ShowCodeDetailsInExceptionMessages; JDK 15 bật nó mặc định.

Code của bạn chạy throw new NullPointerException();. Trên JDK 21, getMessage() trả về gì?

Chỉ NPE do JVM trực tiếp tạo và ném mới có helpful message.

int count = map.get("x"); ném NPE. Vì sao?

Thiếu key thì nhận null; đổi một Integer null thành int sẽ gọi intValue() trên null. Message nói đúng điều đó.

Bài kiểm tra cuối: nói trong 60 giây

Interviewer hỏi: "Bạn thấy một NullPointerException trong log production. Bạn tìm nguyên nhân thế nào?" Bấm giờ. Trả lời to, thành câu đầy đủ. Rồi bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"Đầu tiên em đọc exception message, chứ không chỉ nhìn stack trace. Từ JDK 14, và bật mặc định từ JDK 15, JVM in ra helpful NPE message, kiểu Cannot read field "city" because "order.customer.address" is null. Phần đầu là JVM đã cố làm gì, phần 'because' là biểu thức bị null, nên em biết ngay là address chứ không phải order hay customer. Trên JDK 8 chỉ có số dòng, với một chuỗi gọi liên tiếp thì rất mơ hồ. Nếu message hiện <local1> thay vì tên biến thì class được compile thiếu debug info của biến local; javac -g sẽ sửa được. Lưu ý là chỉ NPE do JVM ném mới có message này, NPE do code tự tạo thì không. Sau đó em tìm xem vì sao nó null: thiếu dữ liệu, method trả về null, hay unboxing một Integer null, rồi sửa tận gốc."

Bây giờ làm bài tập

Bài tập 0027: đọc NPE. Ghi ra phần nào bị null cho từng message trước khi chạy bất cứ thứ gì.

Ví dụ chạy được: NpeDemo.java

Tiếp theo là gì

Interviewer senior có thể hỏi: "Làm sao để NPE không xảy ra ngay từ đầu?" Các ý hay: kiểm tra đầu vào sớm (như compact constructor của record ở bài 0003), trả về Optional thay vì null (bài 0004), và xử lý case null ngay trong switch của JDK 21 (bài 0015).
