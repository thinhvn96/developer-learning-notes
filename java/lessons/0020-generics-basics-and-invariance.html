Generics: why List of Integer is not List of Number

Java (JDK 8, 17, 21) · Lesson 0020 · step 5 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: explain the benefits of generics and why List<Integer> is not a List<Number>.

Benefits

Three: stronger type checks at compile time, elimination of casts, and the ability to write generic algorithms over different types.[1]

List<String> list = new ArrayList<>();
list.add("hello");
String s = list.get(0);   // no cast

Invariance

"Although Integer is a subtype of Number, List<Integer> is not a subtype of List<Number> and, in fact, these two types are not related."[2] If it were allowed you could add a Double through the List<Number> reference into what is really a List<Integer>, breaking type safety.[2] Wildcards give a legitimate relationship (next lesson).

In GenericsDemo.java the line List<Number> nums = ints; is commented out because it does not compile.

Retrieval practice

Answer from memory. One attempt each.

1. Is List of Integer a subtype of List of Number?

Generic types are invariant.[2]

2. A benefit of generics?

Stronger type checks at compile time.[1]

3. What do generics remove from client code?

Casting is not necessary with generics.[1]

4. Why is the assignment forbidden?

You could add a Double to a list that is really Integers.[2]
