PriorityQueue, heaps and the top-K problem

A queue that always hands you the smallest item first, without ever sorting everything.

Java (JDK 8, 17, 21) · Lesson 0035 · step 17 of 46 · Advanced · ~22 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? Job schedulers, "the 10 slowest requests", "the 5 nearest drivers", merging sorted files: all of them need "give me the most important item next". "Find the top K of N numbers" is also one of the most common coding-interview questions, and the expected answer is a heap.
Today's win: use PriorityQueue correctly (it is not sorted!), solve top-K in O(n log k) with a min-heap, and pick ArrayDeque for stacks and FIFO queues.
queue
A line of items waiting their turn. You add at one end and take from the other.
priority queue
A queue where the next item out is the most important one (in Java: the smallest), not the one that came first.
heap
A tree where every parent is smaller than or equal to its children. The smallest item is always at the top.
head
The item you would get next: peek() looks at it, poll() removes it.
top-K
The K biggest (or smallest) items out of many, for example the 3 highest scores out of a million.
deque
Say "deck": a double-ended queue. You can add and remove at both the front and the back.
O(n log k)
n steps, each costing about log k. With k = 3, log k is tiny, so it is close to one pass over the data.

Before you start

Predict: new PriorityQueue<>(List.of(7, 3, 9, 1, 5, 8)), then System.out.println(pq). What is printed? Say it out loud before you read section 1. Most people say [1, 3, 5, 7, 8, 9].

1. The picture: a hospital emergency room

In a bank, people are served in the order they arrive. In an emergency room, the nurse always calls the most urgent patient next, whoever arrived first. The nurse does not keep a fully sorted list of everybody; she only needs to know who is the most urgent right now.

That is a PriorityQueue: "an unbounded priority queue based on a priority heap". "The head of this queue is the least element" according to its natural order or your comparator.PriorityQueue javadoc Smallest number = most urgent.

A heap is a "half-sorted" tree: every parent is ≤ its children, but brothers and cousins are in no particular order. In OpenJDK the tree is stored in a plain array: "the two children of queue[n] are queue[2*n+1] and queue[2*(n+1)]", and the smallest element is in queue[0].OpenJDK source

Now the "Before you start" answer. Printing a PriorityQueue prints the array, and the array is in heap order, not sorted order:

$ java java/examples/collections/PriorityQueueTopK.java
toString (heap array order): [1, 3, 8, 7, 5, 9]     <- NOT sorted
peek (smallest)            : 1
poll until empty           : [1, 3, 5, 7, 8, 9]     <- sorted only via poll
top 3 of 1,000,000         : [9999989, 9999982, 9999981]
max-heap by length poll    : kubernetes
stack pop: c   queue poll: a

The Javadoc says it plainly: the iterator is "not guaranteed to traverse the elements of the priority queue in any particular order. If you need ordered traversal, consider using Arrays.sort(pq.toArray())".PriorityQueue javadoc A for-each loop, a stream and toString() all use that iterator.

2. Follow one poll and one offer, step by step

Why is the heap cheap? Because each change only walks one path from top to bottom (or bottom to top), and a balanced tree of n items is only about log n levels tall.

pq.poll();             // heap array [1, 3, 8, 7, 5, 9]
Step 1  Take the root, 1. It is the answer.
Step 2  Move the last item, 9, to the root:       [9, 3, 8, 7, 5]
Step 3  9 > its smaller child 3 → swap:            [3, 9, 8, 7, 5]
Step 4  9 > its smaller child 5 → swap:            [3, 5, 8, 7, 9]

pq.offer(2);
Step 1  Put 2 at the end, index 5 (parent: index 2, value 8)
Step 2  2 < 8 → swap; now at index 2 (parent: index 0, value 3)
Step 3  2 < 3 → swap; now at the root:             [2, 5, 3, 7, 9, 8]

The swaps follow the OpenJDK implementation; the Javadoc only promises the costs below, not the exact array layout.

That gives the costs from the Javadoc: "O(log(n)) time for the enqueuing and dequeuing methods (offer, poll, remove() and add); linear time for the remove(Object) and contains(Object) methods; and constant time for the retrieval methods (peek, element, and size)".PriorityQueue javadoc contains is linear because a half-sorted tree cannot tell you which branch to search.

Three more rules: it does not permit null elements; if several elements tie for least, "ties are broken arbitrarily"; and it is not synchronized, so for threads "use the thread-safe PriorityBlockingQueue class".PriorityQueue javadoc

3. Top-K: the interview classic

Picture a VIP room with exactly 3 chairs and a bouncer at the door. The bouncer only remembers the weakest person inside. A newcomer gets in only if they beat that weakest person, who is then thrown out. At the end of the night, the 3 people inside are the top 3.

The "remember the weakest one" part is a min-heap of size K: its head is the smallest of the current top K, so a new item only enters if it beats the head.

PriorityQueue<Integer> heap = new PriorityQueue<>(k);   // min-heap
for (int x : stream) {
    if (heap.size() < k) heap.offer(x);                    // room not full yet
    else if (x > heap.peek()) { heap.poll(); heap.offer(x); } // beats the weakest
}

Cost: O(n log k) time and O(k) memory, versus O(n log n) and O(n) for sorting everything. It also works on a stream you cannot hold in memory. The example runs it on a million random numbers and keeps only three of them: top 3 of 1,000,000 : [9999989, 9999982, 9999981].

For a max-heap (largest first), pass a comparator: new PriorityQueue<>(Comparator.reverseOrder()). The example builds one ordered by string length, and poll() returns kubernetes, the longest word.

Common mistake: the wrong heap

For the K largest, many people reach for a max-heap of everything and poll K times. That works, but it holds all n items: O(n) memory. The trick is the opposite heap: a min-heap of size K for the K largest, a max-heap of size K for the K smallest.

4. ArrayDeque for everything else

Often you do not need priority, only "last in, first out" (a stack of plates) or "first in, first out" (a bank queue). Deque supports "insertion and removal at both ends".java.util summary Use ArrayDeque:

Deque<String> stack = new ArrayDeque<>();
stack.push("a"); stack.push("b"); stack.push("c");
stack.pop();                            // "c": last in, first out

Deque<String> queue = new ArrayDeque<>();
queue.offer("a"); queue.offer("b"); queue.offer("c");
queue.poll();                           // "a": first in, first out

That is the last line of the run: stack pop: c queue poll: a. The ArrayDeque Javadoc says it "is likely to be faster than Stack when used as a stack, and faster than LinkedList when used as a queue"; it prohibits null elements and is not thread-safe.ArrayDeque javadoc So avoid the legacy Stack class (see lesson 0002).

Typical uses: breadth-first search (queue), depth-first search and undo history (stack), sliding window maximum (deque). All of this works the same on JDK 8, 17 and 21.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

What does System.out.println(new PriorityQueue<>(List.of(7, 3, 9, 1, 5, 8))) print?

toString uses the iterator, which walks the heap array. Only the head is guaranteed to be the smallest; the rest is not sorted.

How much does PriorityQueue.contains(x) cost?

remove(Object) and contains(Object) are linear: a heap is only half-sorted, so Java must scan the array.

You want the 10 largest numbers from a huge stream. Which heap do you keep?

The min-heap's head is the weakest of the current top 10, so it is the one to compare against and replace. Memory stays O(k).

Which operations of PriorityQueue run in O(log n)?

Enqueue and dequeue walk one path of the tree: O(log n). peek, element and size are constant; contains and remove(Object) are linear.

How do you make a PriorityQueue return the largest element first?

The head is the least element according to the comparator. Reverse the comparator and the largest becomes "least".

Which class should you use for a plain stack in modern Java?

ArrayDeque is likely to be faster than Stack when used as a stack. Use push and pop.

The final test: say it in 60 seconds

An interviewer asks: "How would you find the top 10 of a billion numbers? Which Java class, and what does it cost?" Start a timer. Answer out loud, in full sentences. Then click the button.

Tick only the points you really said:

Example answer

"I'd stream through the numbers once and keep a PriorityQueue of size 10 as a min-heap. PriorityQueue is a binary heap, so its head is always the smallest element. For each number, if the heap has fewer than 10 items I offer it; otherwise, if the number is bigger than the head, I poll the head and offer the new number. The head is always the weakest of the current top 10, so that's the one to beat. Each step is O(log 10), so the whole thing is O(n log k) time and only O(k) memory, which matters for a billion numbers that don't fit in memory. At the end I sort those 10, because iterating a PriorityQueue doesn't give sorted order. And if several threads fed it, I'd use PriorityBlockingQueue."
