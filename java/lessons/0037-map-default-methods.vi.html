Các method mạnh của Map: merge, compute và cái bẫy

Thay "get, kiểm tra null, put" bằng một lần gọi, và học ba cách nó có thể làm bạn bất ngờ.

Java (JDK 8, 17, 21) · Bài 0037 · bước 19/46 · Advanced · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Đếm từ, nhóm đơn hàng theo khách, xây cache: một nửa code dùng map là "nếu chưa có key thì tạo; có rồi thì cập nhật". Java 8 thêm các method làm việc này trong một lần gọi. Reviewer và người phỏng vấn mong bạn dùng chúng, và biết chỗ chúng cắn: kết quả null, đối số được tính sẵn, và đệ quy.
Thành quả hôm nay: thay code get-kiểm tra-put bằng merge, computeIfAbsent và các method họ hàng, và tránh ba cái bẫy về null và đệ quy của chúng.
default method
Một method có thân nằm trong interface. Java 8 dùng chúng để thêm method mới vào Map mà không làm hỏng mọi class đang implement nó.
lambda
Một hàm nhỏ không tên mà bạn truyền như một giá trị, như k -> new ArrayList<>(). Bài 0008 nói về chúng.
method reference
Cách viết ngắn cho một lambda gọi đúng một method có sẵn: Integer::sum nghĩa là (a, b) -> Integer.sum(a, b).
mapping function
Hàm bạn đưa cho computeIfAbsent: nó nhận key và trả về value mới.
remapping function
Hàm bạn đưa cho merge hoặc compute: nó nhận value cũ và trả về value mới.
multimap
Một map mà một key giữ nhiều value, thường là Map<K, List<V>>.
eager / lazy
Eager: tính ngay, kể cả khi không cần. Lazy: chỉ tính khi thật sự cần.

Trước khi bắt đầu

Viết, trong đầu hoặc ra giấy, đoạn code kiểu JDK 7 kinh điển đếm số lần mỗi từ xuất hiện trong một list, dùng get và put. Đếm số dòng. Phần 1 làm việc đó trong một dòng.

1. Bộ công cụ Map của JDK 8

Hãy nghĩ tới quầy lễ tân khách sạn. Cách cũ: "Có phòng cho anh An chưa? Chưa à? Vậy tạo một phòng. Giờ đưa tôi phòng đó. Giờ để túi vào." Ba lần ra quầy. Cách mới: "Để túi này vào phòng anh An, chưa có phòng thì tạo." Một lần.

Mọi method này đều "Since 1.8", nên có sẵn trên 8, 17 và 21.Map javadoc

Integer c = m.get(w); m.put(w, c == null ? 1 : c + 1);m.merge(w, 1, Integer::sum)

Lần theo: đếm từ bằng merge

merge(key, value, function) đọc như sau: "Nếu key chưa gắn với value nào hoặc đang gắn với null, gắn nó với value khác null được cho."Map javadoc Ngược lại, nó gọi hàm của bạn với value cũ và value mới.

for (String w : List.of("kafka", "java", "kafka", "sql", "java", "kafka"))
    counts.merge(w, 1, Integer::sum);
Step 1  "kafka": absent → store 1
Step 2  "java":  absent → store 1
Step 3  "kafka": old 1 → sum(1, 1) → store 2
...     "sql" → 1, "java" → 2, "kafka" → 3
$ java java/examples/collections/MapPowerMethods.java
merge count         : {java=2, kafka=3, sql=1}
computeIfAbsent list: {j=[java, java], k=[kafka, kafka, kafka], s=[sql]}
getOrDefault        : 0
objects built (putIfAbsent + computeIfAbsent on existing key): 1
null result removes : {}
getOrDefault on null value: null
recursive computeIfAbsent: ConcurrentModificationException
groupingBy+counting : {java=2, kafka=3, sql=1}

Dòng cuối cho thấy cách làm bằng stream từ bài 0004: Collectors.groupingBy(w -> w, TreeMap::new, Collectors.counting()) cho cùng kết quả đếm. Dùng merge khi cập nhật một map đã có; dùng groupingBy khi xây map mới từ một stream.

2. Concurrency: nơi các method này quan trọng nhất

Trên HashMap thường, các method này chỉ là code ngắn hơn. Javadoc nói rõ: "Cài đặt mặc định không đảm bảo gì về synchronization hay tính nguyên tử của method này. Cài đặt nào cung cấp đảm bảo nguyên tử phải override method này và ghi rõ các thuộc tính concurrency của nó."Map javadoc

ConcurrentHashMap có override chúng và làm chúng nguyên tử, vì thế chúng càng quan trọng ở đó (bài 0025). Với hai thread, get rồi put có thể mất cập nhật: cả hai đọc 2, cả hai ghi 3. merge trên ConcurrentHashMap làm việc đọc và ghi như một bước.

3. Các cái bẫy

objects built (putIfAbsent + computeIfAbsent on existing key): 1
null result removes : {}
getOrDefault on null value: null
recursive computeIfAbsent: ConcurrentModificationException

Bẫy 1: putIfAbsent là eager

Java tính các đối số của method trước khi gọi. Nên m.putIfAbsent("x", new ArrayList<>()) tạo một list mới kể cả khi "x" đã có, rồi vứt nó đi. computeIfAbsent nhận một hàm, và chỉ gọi khi key chưa có.

Với value rẻ như 0 thì không sao. Với một lần gọi database hay một object lớn thì có.

Bẫy 2: null nghĩa là "không có mapping"

Nếu mapping function trả về null thì "không mapping nào được ghi lại"; nếu remapping function trả về null thì "mapping bị xóa".Map javadoc Trong ví dụ, computeIfAbsent("pear", k -> null) không thêm gì, và giảm tồn kho của apple về 0 bằng v - 1 == 0 ? null : v - 1 sẽ xóa apple: map in ra {}. Cố ý thì tiện, vô tình thì bất ngờ.

Còn getOrDefault trả về "value mà key được gắn tới, hoặc defaultValue nếu map không có mapping nào cho key đó".Map javadoc Một key gắn với null vẫn có mapping, nên bạn nhận null đã lưu, không phải giá trị mặc định. Lần chạy in ra getOrDefault on null value: null.

Bẫy 3: đừng sửa map bên trong hàm

"Mapping function không nên sửa map này trong lúc tính toán."Map javadoc HashMap "sẽ, theo khả năng tốt nhất, ném ConcurrentModificationException" khi phát hiện việc này.HashMap javadoc Nạn nhân kinh điển là đệ quy có memo:

static int fib(int n, Map<Integer, Integer> memo) {
    if (n < 2) return n;
    return memo.computeIfAbsent(n, k -> fib(k - 1, memo) + fib(k - 2, memo));
}
Step 1  computeIfAbsent(30) starts; HashMap is in the middle of an insert
Step 2  the function calls fib(29) → computeIfAbsent(29) → puts into the same map
Step 3  back in step 1, HashMap sees the map changed under it → ConcurrentModificationException

Cách sửa: dùng get và put thường ở đây: tính value trước, rồi mới lưu.

Integer cached = memo.get(n);
if (cached != null) return cached;
int value = fib(n - 1, memo) + fib(n - 2, memo);
memo.put(n, value);
return value;

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Lời gọi nào đếm từ trong Map<String, Integer> trong một dòng?

merge lưu 1 ở lần đầu và cộng cũ + 1 ở các lần sau. put(w, get(w) + 1) ném NullPointerException ở lần đầu.

Hàm truyền vào computeIfAbsent trả về null. Chuyện gì xảy ra?

Nếu mapping function trả về null, không mapping nào được ghi, và computeIfAbsent trả về null.

Key "x" đã có. Lời gọi nào vẫn tạo object đối số?

putIfAbsent nhận một value, và Java tính đối số trước khi gọi. computeIfAbsent nhận một hàm và chỉ chạy khi cần. (List.of() cũng được tính, nhưng nó là list rỗng dùng chung, không phải object mới bạn yêu cầu.)

Map đang giữ "k" → null. getOrDefault("k", "default") trả về gì?

Key có mapping (tới null), nên giá trị mặc định không được dùng. Ví dụ in ra null.

Một hàm fib có memo tự gọi chính nó bên trong computeIfAbsent trên HashMap. Bug là gì?

Mapping function không nên sửa map. HashMap phát hiện việc này theo khả năng tốt nhất và ném ConcurrentModificationException.

Trên HashMap thường, merge có nguyên tử khi hai thread cùng gọi không?

Chỉ những cài đặt override và ghi rõ điều đó, như ConcurrentHashMap, mới nguyên tử. HashMap thường hoàn toàn không thread-safe.

Bài kiểm tra cuối: nói trong 60 giây

Người phỏng vấn cho bạn xem code get-kiểm tra-put và hỏi: "Bạn sẽ viết lại bằng Java hiện đại thế nào, và cần cẩn thận điều gì?" Bấm giờ. Trả lời thành tiếng, thành câu đầy đủ. Rồi bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"Từ Java 8, Map có default method cho đúng việc này. Để đếm em viết merge với key, 1 và Integer::sum: lần đầu nó lưu 1, các lần sau thì cộng thêm. Với multimap em viết computeIfAbsent với hàm tạo list, rồi gọi add trên kết quả. Có vài cái bẫy. putIfAbsent nhận value, nên value được tạo kể cả khi key đã có, còn computeIfAbsent chỉ gọi hàm khi cần. Nếu hàm của em trả về null thì không có gì được lưu, hoặc với merge và compute thì entry bị xóa. getOrDefault trả về null đã lưu chứ không trả giá trị mặc định. Và hàm không được sửa chính map đó, nên một hàm fib đệ quy có memo bên trong computeIfAbsent có thể ném ConcurrentModificationException trên HashMap. Cuối cùng, các method này chỉ nguyên tử trên ConcurrentHashMap, không phải trên HashMap thường."
