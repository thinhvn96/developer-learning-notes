switch trả về giá trị, instanceof tự cast giúp bạn

Hai tính năng của JDK 14 và JDK 16 xoá sổ cả một nhóm bug do copy-paste.

Java (JDK 8, 17, 21) · Bài 0013 · bước 38/46 · Core · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Quên một break trong switch của JDK 8, hay cast sai sau instanceof, là những bug production kinh điển. Interviewer hỏi "switch thay đổi gì sau Java 8?" để xem bạn có nắm Java hiện đại không, và hai tính năng này là nền tảng cho pattern matching ở JDK 21.
Thành quả hôm nay: viết lại một câu lệnh switch của JDK 8 thành switch expression, và một chuỗi instanceof-rồi-cast thành instanceof pattern, rồi giải thích vì sao cả hai không thể fall through hay cast sai.
statement (câu lệnh)
Một dòng code làm một việc, như x = 5; hay if (...) {...}. Nó không trả lại giá trị.
expression (biểu thức)
Code tạo ra một giá trị, như 2 + 3 hay name.length(). Bạn có thể đặt nó bên phải dấu =.
fall-through (rơi xuyên)
Trong switch kiểu cũ, sau khi một case khớp, Java chạy tiếp các case bên dưới cho tới khi gặp break.
exhaustive (đầy đủ)
Bao hết mọi đầu vào có thể. Không đầu vào nào bị bỏ sót.
cast (ép kiểu)
Bảo Java "coi object này là kiểu X", viết là (String) obj. Nếu bạn sai, nó ném ClassCastException lúc chạy.
pattern variable
Biến mới mà instanceof tạo cho bạn khi phép kiểm tra thành công, như s trong obj instanceof String s.
scope (phạm vi)
Phần code mà tên biến được phép dùng.

Trước khi bắt đầu

Đọc đoạn code JDK 8 này và nói to xem nó in ra gì khi day bằng 1. Rồi kiểm tra ở mục 1.

String r;
switch (day) {
  case 1: r = "one";
  case 2: r = "two"; break;
  default: r = "?";
}
System.out.println(r);

1. switch kiểu cũ là cầu trượt, không phải nút bấm

Hình dung một cầu trượt nước có nhiều cửa vào. Bạn vào ở cửa 1, nhưng không có gì giữ bạn lại: bạn trượt qua cửa 2, cửa 3, cứ thế cho tới khi đụng tường. Trong switch kiểu cũ, các nhãn case là cửa, còn break là bức tường. Đó là fall-through.

Vậy đoạn code trên in ra two, không phải one. Mình đã chạy trên JDK 21:

Step 1  day is 1, so Java jumps to "case 1"
Step 2  r = "one"
Step 3  no break, so Java falls into "case 2": r = "two"
Step 4  break: leave the switch
$ java Old.java
two

JEP 361 nói thẳng: switch cũ "mặc định hỗ trợ ngữ nghĩa fall through".JEP 361 Quên một break là có bug âm thầm.

switch kiểu mới là máy bán hàng tự động

Máy bán hàng tự động thì khác: bấm B2 là nhận đúng một món. JDK 14 mang tới nhãn mũi tên, case L ->. Với chúng, "không có fall through": chỉ code bên phải mũi tên được chạy.JEP 361 Và JEP 361 mở rộng switch "để nó có thể dùng như statement hoặc expression".JEP 361 Một expression trả lại giá trị, nên bạn có thể return hoặc gán nó trực tiếp.

// JDK 8: a statement, a variable declared outside, a break on every line
String kind;
switch (day) {
  case 6: case 7: kind = "weekend"; break;
  case 1: case 2: case 3: case 4: case 5: kind = "weekday"; break;
  default: kind = "invalid: " + day;
}
return kind;

// JDK 14+: a switch expression
return switch (day) {
    case 6, 7 -> "weekend";
    case 1, 2, 3, 4, 5 -> "weekday";
    default -> { String msg = "invalid: " + day; yield msg; }
};

2. Đọc switch mới, từng dòng

  1. case 6, 7 ->: nhiều hằng số trong một nhãn, cách nhau bằng dấu phẩy. JEP 361 đề xuất "cho phép nhiều hằng số trong một case, cách nhau bằng dấu phẩy".JEP 361
  2. -> "weekend";: giá trị bên phải là giá trị của cả switch.
  3. default -> { ... yield msg; }: khi cần nhiều dòng, dùng block { } và trả giá trị bằng yield. JEP 361 giới thiệu "câu lệnh yield mới để trả ra một giá trị, giá trị này trở thành giá trị của switch expression bao quanh".JEP 361

Ví dụ thật in ra ba trường hợp:

$ java java/examples/jdk17/Jdk17Features.java
{
  "name": "orders",
  "port": 8080
}
weekend, weekday, invalid: 9
3.14 4.00 6.00

Mấy dòng JSON đến từ text block ở bài 0012; dòng cuối đến từ mục 4 bên dưới.

Quy tắc: switch expression phải bao hết mọi giá trị

Switch expression phải trả giá trị cho mọi đầu vào có thể: nó phải exhaustive. Với int, thường có nghĩa là phải có default.JEP 361 Bỏ default ở trên đi và javac 21 từ chối:

error: the switch expression does not cover all possible input values
    return switch (day) { case 6, 7 -> "weekend"; case 1, 2, 3, 4, 5 -> "weekday"; };

Với enum, liệt kê hết các hằng là đủ. Không cần default; thay vào đó, theo JEP, "compiler tự chèn một mệnh đề default", nên nếu sau này có hằng mới thì sẽ bị phát hiện lúc chạy.JEP 361

enum Size { S, M, L }
// no default needed: all 3 constants are listed
String label = switch (size) {
    case S -> "small";
    case M -> "medium";
    case L -> "large";
};

Bẫy: return bên trong switch expression

Bên trong switch expression, bạn không thể dùng return, break hay continue để nhảy ra. Theo JEP, switch expression phải "kết thúc bình thường với một giá trị, hoặc kết thúc đột ngột bằng cách ném exception".JEP 361 Cách sửa: dùng yield để trả giá trị, hoặc throw cho trường hợp không thể xảy ra.

3. instanceof: kiểm tra và đặt tên trong một bước

Hình dung một bảo vệ kiểm tra thùng hàng. Ở JDK 8, bảo vệ nói "Đây có phải laptop không? Phải." Rồi người thứ hai nói "OK, giờ tôi sẽ coi nó là laptop." Hai bước, và người thứ hai có thể nhầm. Ở JDK 16, bảo vệ nói "Nếu đây là laptop thì gọi nó là lap", rồi đưa ra món hàng đã dán nhãn sẵn.

// JDK 8: test, then cast by hand (type written twice)
if (obj instanceof String) {
    String s = (String) obj;       // the JEP itself comments: "grr..."
    System.out.println(s.length());
}

// JDK 16+: pattern matching for instanceof
if (obj instanceof String s) {     // test + new variable s
    System.out.println(s.length());
}

JEP 394 viết "mọi lập trình viên Java đều quen với thành ngữ instanceof-rồi-cast", và thay thế nó.JEP 394 Cách cũ có một rủi ro ẩn: nếu bạn copy-paste block, đổi phép kiểm tra thành Integer nhưng quên đổi cast, code vẫn compile và ném ClassCastException lúc chạy. Với pattern, kiểu chỉ viết một lần, nên kiểm tra và cast không bao giờ lệch nhau.

Được dùng s ở đâu? Flow scoping

Pattern variable s chỉ tồn tại ở nơi compiler chắc chắn phép kiểm tra đã thành công. Theo JEP, "pattern variable chỉ nằm trong scope ở nơi compiler suy ra được rằng pattern chắc chắn đã khớp".JEP 394 Hãy đi theo cách compiler suy luận:

Ở ví dụ A, theo JEP, s "nằm trong scope ở vế phải của toán tử &&, và trong nhánh true".JEP 394 Java tính && từ trái sang phải và dừng sớm khi vế trái sai, nên khi tới vế phải thì phép kiểm tra đã qua. Ví dụ B cũng có trong JEP: sau if (!(o instanceof String s)) throw ...;, s nằm trong scope cho phần code còn lại.JEP 394 Mình đã chạy cả hai trên JDK 21; chúng compile và in ra đúng giá trị.

Với || thì ngược lại: trong o instanceof String s || s.isEmpty(), vế phải chỉ chạy khi phép kiểm tra thất bại, nên ở đó không có s và code không compile.

4. Kết hợp cả hai: ví dụ hình học

Ví dụ của khoá học dùng instanceof pattern để tính diện tích ba loại hình. Mỗi dòng vừa kiểm tra vừa đặt tên:

static double area(Shape s) {
    if (s instanceof Circle c) return Math.PI * c.r() * c.r();
    if (s instanceof Square q) return q.side() * q.side();
    if (s instanceof Rect r)   return r.w() * r.h();
    throw new IllegalStateException();
}
$ java java/examples/jdk17/Jdk17Features.java
...
3.14 4.00 6.00

Để ý dòng cuối, throw new IllegalStateException(). Compiler không thể biết ba hình này là tất cả, nên bạn cần một nhánh dự phòng. Ở bài 0014 bạn sẽ đóng danh sách hình lại, và ở JDK 21 một switch có thể kiểm tra giúp bạn.

Cả hai tính năng đều thuộc về "JDK 17" với bạn, vì 17 gồm mọi thứ đã chính thức tới 17: switch expression chính thức ở JDK 14, instanceof pattern ở JDK 16 sau hai lần preview ở 14 và 15.JEP 361JEP 394

Pattern matching cho switch (case Circle c ->) là tính năng của JDK 21: ví dụ JDK 21 không compile với --release 17 (đã kiểm chứng khi viết bài này; compiler báo patterns in switch không được hỗ trợ ở -source 17). Xem bài 15.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Trong code JDK 8 case 1: r = "one"; case 2: r = "two"; break;, r bằng gì khi day là 1?

Không có break, switch cũ chạy tiếp vào case 2, ghi đè r thành "two".

Điều gì xảy ra sau khi một nhãn case L -> khớp?

Nhãn mũi tên không bao giờ fall through. Một case, một kết quả.

Keyword nào trả giá trị từ một block { } bên trong switch expression?

yield đặt giá trị cho switch expression. return và break không nhảy ra khỏi switch expression được.

Một switch expression trên int có case 1 tới 7 nhưng không có default. Chuyện gì xảy ra?

Switch expression phải exhaustive. int có nhiều giá trị hơn 1 tới 7 rất nhiều, nên bạn cần default.

Switch expression trên enum Size { S, M, L } liệt kê S, M và L. Có bắt buộc default không?

Liệt kê hết các hằng là đã exhaustive. Compiler tự chèn default riêng cho các hằng được thêm sau này.

Sau if (!(o instanceof String s)) return;, dòng tiếp theo có dùng được s không?

Flow scoping: cách duy nhất để đi qua if là phép kiểm tra thành công, nên compiler biết s là String.

Bài kiểm tra cuối: nói trong 60 giây

Interviewer hỏi: "switch và instanceof đã thay đổi gì từ Java 8 tới Java 17?" Bấm giờ. Trả lời to, thành câu đầy đủ. Rồi bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"Ở Java 8, switch chỉ là statement, và nó fall through: quên break là case sau cũng chạy. Từ JDK 14 có nhãn mũi tên, case 6, 7 ->, không bao giờ fall through, và switch có thể là expression, nên em viết được return switch (day) {...}. Case nào cần nhiều dòng thì em dùng block và yield giá trị. Switch expression phải exhaustive, nên compiler bắt phải có default, hoặc với enum thì đủ mọi hằng. Còn instanceof, JDK 16 thêm pattern matching: if (obj instanceof String s) kiểm tra và cast trong một bước, kiểu chỉ viết một lần nên kiểm tra và cast không lệch nhau được. Biến s dùng flow scoping: chỉ dùng được ở nơi chắc chắn đã khớp, ví dụ vế phải của && hay sau một return sớm. Hai cái này là nền cho pattern matching trong switch ở JDK 21."
