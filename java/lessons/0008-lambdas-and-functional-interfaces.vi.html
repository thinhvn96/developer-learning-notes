Lambda: truyền một đoạn code như một giá trị

Lambda thật ra là gì, nó biến thành interface nào, và quy tắc "effectively final".

Java (JDK 8, 17, 21) · Bài 0008 · bước 23/46 · Core · ~25 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Từ JDK 8, gần như codebase Java nào cũng truyền các hàm nhỏ đi khắp nơi: list.forEach(...), stream().filter(...), executor.submit(...). Interviewer hay hỏi "Functional interface là gì?" và "Vì sao biến được capture phải effectively final?" Bài này giúp bạn trả lời cả hai.
Thành quả hôm nay: viết được một lambda, chọn đúng functional interface chuẩn cho nó, đổi nó thành method reference, và giải thích quy tắc "effectively final" trong hai câu.
interface
Danh sách các method mà một class hứa sẽ cung cấp. Nó nói làm gì, không nói làm thế nào.
abstract method
Method chỉ có tên, không có thân. Người khác phải viết phần thân.
functional interface
Interface có đúng một abstract method. Một lambda có thể đứng thay cho nó.
lambda
Một hàm ngắn, không tên, viết ngay tại chỗ, ví dụ s -> s.length().
anonymous class
Cách làm trước JDK 8: một class không tên, vừa khai báo vừa tạo object, thường chỉ để cung cấp một method.
generic <T>
Chỗ giữ chỗ cho một kiểu. Predicate<String> nghĩa là "một Predicate làm việc với String".
method reference
Một lambda còn ngắn hơn, chỉ gọi một method đã có sẵn, ví dụ String::length.
effectively final
Biến local không bao giờ bị gán giá trị mới sau lần gán đầu tiên.

Trước khi bắt đầu

Nói thành tiếng: "Kiểu của s -> s.length() <= 3 là gì?" Nó là một method? Một object? Hay thứ gì khác? Cứ đoán trước, dù chưa chắc. Cuối bài bạn sẽ so lại.

1. Hình dung: một tấm thẻ công thức

Hãy tưởng tượng bạn thuê một đầu bếp. Bạn không cần mô tả cả một nhân viên mới; bạn chỉ đưa một tấm thẻ công thức: "nhận một cái tên, trả lời có nếu tên dài tối đa 3 chữ". Lambda chính là tấm thẻ đó. Bạn truyền nó cho một method, và method quyết định khi nào dùng.

Trước JDK 8, Java không có thẻ công thức. Muốn truyền hành vi, bạn viết một anonymous class, nguyên một class chỉ để chứa một method:

// JDK 7 style: an anonymous class
Predicate<String> shortName = new Predicate<String>() {
  @Override public boolean test(String s) {
    return s.length() <= 3;
  }
};

// JDK 8 style: a lambda, same meaning
Predicate<String> shortName = s -> s.length() <= 3;

Tutorial chính thức nói lambda cho phép bạn "coi chức năng như tham số của method, hay coi code như dữ liệu", và biểu diễn instance của các class một method gọn hơn anonymous class.Lambda tutorial

Cú pháp, từng phần một

(a, b) -> a + b              // params -> expression
p -> p.getAge() >= 18        // one param: no ( ) needed
e -> System.out.println(e)   // returns nothing
(a, b) -> { return a + b; }  // block: braces + return

Bên trái mũi tên: các tham số. Bên phải: phần thân, là một biểu thức đơn hoặc một khối trong ngoặc nhọn.Lambda tutorial Thường bạn không cần ghi kiểu của tham số: compiler tự suy ra từ chỗ lambda được dùng.

2. Functional interface: một ô trống duy nhất

Lambda không phải một hàm trôi nổi tự do. Java luôn biến nó thành một object implement một interface nào đó. Interface nào? Interface có đúng một ô trống, tức một abstract method. Đó là functional interface. Nó vẫn có thể có default method hoặc static method; những method đó đã có thân nên không tính.Lambda tutorial

Vậy đáp án cho câu hỏi đầu bài: s -> s.length() <= 3 không có kiểu riêng. Nó nhận kiểu của chỗ bạn đặt nó vào. Gán cho Predicate<String> thì nó thành một object Predicate<String>. JDK nói thẳng: "Functional interface cung cấp target type cho lambda expression và method reference."java.util.function

Nhãn @FunctionalInterface

Bạn có thể đánh dấu interface của mình bằng @FunctionalInterface. Khi đó, nếu ai thêm abstract method thứ hai, compiler "bắt buộc phải sinh ra thông báo lỗi". Nhãn này không bắt buộc: compiler coi mọi interface khớp định nghĩa là functional "bất kể có annotation FunctionalInterface hay không".Javadoc FunctionalInterface

@FunctionalInterface
interface PriceRule {
  int apply(int price);      // the one abstract method
}
PriceRule tenOff = p -> p - 10;
tenOff.apply(100);           // 90

3. Hộp đồ nghề chuẩn: java.util.function

Hiếm khi bạn cần tự viết interface. Package java.util.function có sẵn nhiều cái, như Predicate<T>, Consumer<T> và Function<T,R>.Lambda tutorial Hãy nhớ chúng theo hình dạng: cái gì đi vào, cái gì đi ra.java.util.function

InterfaceMethodVào → raDùng ở đâu
Predicate<T>testT → booleanfilter(...)
Function<T,R>applyT → Rmap(...)
Consumer<T>acceptT → không gìforEach(...)
Supplier<T>getkhông gì → TorElseGet(...), factory

Còn có các bản dành cho số nguyên thủy, như IntPredicate, nhận thẳng int và tránh phải boxing thành Integer.

4. Method reference: lambda ngắn nhất

Nếu lambda chỉ gọi một method đã có, bạn chỉ cần gọi tên method đó. Tutorial gọi method reference là "những lambda expression gọn, dễ đọc cho các method đã có tên".Method references tutorial Có bốn loại:

LoạiCú phápTương đương lambda
Static methodInteger::parseInts -> Integer.parseInt(s)
Method của một object cụ thểSystem.out::printlnx -> System.out.println(x)
Method của một object bất kỳ thuộc một kiểuString::lengths -> s.length()
ConstructorHashSet::new() -> new HashSet<>()

Loại thứ ba hay làm người mới bối rối. String::length không chỉ một string cụ thể nào. Nó nghĩa là "string nào đi vào thì gọi length() trên string đó".

5. Quy tắc interviewer hay hỏi: effectively final

Lambda có thể dùng biến local của method bao quanh. Nhưng có một quy tắc: "Lambda expression chỉ được truy cập biến local và tham số của khối bao quanh nếu chúng là final hoặc effectively final."Lambda tutorial Effectively final nghĩa là bạn không bao giờ gán giá trị mới cho biến sau lần gán đầu. Bạn không cần viết chữ final.

Quay lại tấm thẻ công thức. Bạn ghi "cho base gram muối" rồi đưa thẻ đi với base = 10. Nếu sau đó bạn lén đổi base thành 11, đầu bếp sẽ dùng giá trị nào? Java tránh luôn câu hỏi này: một khi lambda đã đọc một biến local, biến đó không được thay đổi.

Lambda không mở scope mới

Lambda có lexical scope: nó không thừa hưởng tên từ supertype và không tạo thêm một tầng scope, nên tên bên trong lambda mang nghĩa y như ngay bên ngoài.Lambda tutorial Trong thực tế: bạn không thể đặt tên tham số lambda trùng với một biến local của method bao quanh; tutorial đưa ra lỗi compile "Lambda expression's parameter x cannot redeclare another local variable defined in an enclosing scope". Ngược lại, anonymous class là một class thật và có scope riêng.

Lần theo ví dụ từng bước

List<String> names = Arrays.asList("ann", "bob", "cy", "dee");
Predicate<String> shortName = s -> s.length() <= 3;
Function<String, Integer> length = String::length;
names.stream().filter(shortName).map(length).forEach(System.out::println);
Step 1  "ann": test → 3 <= 3 true  → apply → 3 → println
Step 2  "bob": test → true         → 3 → println
Step 3  "cy":  test → true         → 2 → println
Step 4  "dee": test → true         → 3 → println

int base = 10;                                  // effectively final
Function<Integer, Integer> plusBase = x -> x + base;
System.out.println(plusBase.apply(5));          // 15

Tự chạy thử (nó compile được với javac --release 8, nên chỉ dùng tính năng của JDK 8):

$ java java/examples/jdk8/Lambdas.java
3
3

3

Lỗi hay gặp: đếm bên trong lambda

int count = 0;
names.forEach(n -> count++);   // compile error: count is not effectively final

Cách sửa không phải là "lừa" compiler. Hãy hỏi thẳng stream: long count = names.stream().count();. Bài 0004 giải thích vì sao không nên có side effect trong lambda của stream.

JDK 8 so với 17 và 21

Lambda, method reference và java.util.function đều có từ JDK 8 và chạy y như vậy trên 17 và 21. Các JDK mới hơn thêm nhiều method nhận lambda (ví dụ static method Predicate.not, thêm vào ở JDK 11 và có trong sơ đồJavadoc Predicate), nhưng các quy tắc trong bài này không đổi.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Một functional interface có bao nhiêu abstract method?

Một abstract method, chính là "ô trống" mà lambda lấp vào. Default và static method đã có thân nên không tính.

Kiểu của lambda s -> s.isEmpty() là gì?

Lambda lấy kiểu từ target của nó: functional interface "cung cấp target type cho lambda expression và method reference".

Một lambda đọc biến local limit. Ba dòng sau, method chạy limit = 5;. Chuyện gì xảy ra?

Biến local bị capture phải final hoặc effectively final. Gán lại ở bất kỳ đâu trong method là phá quy tắc, nên compiler từ chối.

Interface chuẩn nào nhận một T và trả về boolean?

Predicate<T> có boolean test(T t). Consumer không trả về gì, Supplier không nhận gì, Function trả về R bất kỳ.

Lambda nào tương đương với method reference String::length?

Đây là loại "instance method của một object bất kỳ thuộc một kiểu": string đi vào chính là object được gọi method.

"Lambda có lexical scope." Trong thực tế điều đó nghĩa là gì?

Lambda không thừa hưởng tên từ supertype và không tạo thêm tầng scope. Ngược lại, anonymous class có scope riêng.

Câu trả lời mẫu

"Lambda, có từ JDK 8, là một hàm ngắn không tên, để em truyền behaviour như một giá trị, ví dụ vào filter hay forEach. Trước đó mình phải viết anonymous class chỉ để chứa một method. Lambda luôn trở thành object của một functional interface, tức interface có đúng một abstract method; nó vẫn có thể có default và static method. JDK có sẵn các dạng phổ biến trong java.util.function: Predicate trả về boolean, Function map từ T sang R, Consumer nhận giá trị và không trả gì, Supplier thì tạo ra giá trị. Nếu lambda chỉ gọi một method có sẵn thì em dùng method reference như String::length. Và có một quy tắc: lambda chỉ đọc được biến local final hoặc effectively final, nên không thể tăng biến đếm bên trong lambda."
