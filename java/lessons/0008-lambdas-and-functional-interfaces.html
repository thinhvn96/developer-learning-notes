Lambdas: passing a piece of code as a value

What a lambda really is, which interface it turns into, and the "effectively final" rule.

Java (JDK 8, 17, 21) · Lesson 0008 · step 23 of 46 · Core · ~25 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? Since JDK 8, almost every Java codebase passes small functions around: list.forEach(...), stream().filter(...), executor.submit(...). Interviewers ask "What is a functional interface?" and "Why must a captured variable be effectively final?" This lesson lets you answer both.
Today's win: write a lambda, pick the right standard functional interface for it, turn it into a method reference, and explain the "effectively final" rule in two sentences.
interface
A list of methods that a class promises to provide. It says what, not how.
abstract method
A method with a name but no body. Someone else must write the body.
functional interface
An interface with exactly one abstract method. A lambda can stand in for it.
lambda
A short, nameless function you write inline, like s -> s.length().
anonymous class
The pre-JDK 8 way: a class with no name, written and created in one go, often just to provide one method.
generic <T>
A placeholder for a type. Predicate<String> means "a Predicate that works on Strings".
method reference
An even shorter lambda that just calls an existing method, like String::length.
effectively final
A local variable that is never given a new value after it is first set.

Before you start

Say out loud: "What is the type of s -> s.length() <= 3?" Is it a method? An object? Something else? Guess first, even if you are not sure. You will compare at the end.

1. The picture: a recipe card

Imagine you hire a cook. You don't want to describe a whole new employee; you only want to hand over one recipe card: "take a name, say yes if it has 3 letters or fewer". A lambda is that recipe card. You pass it to a method, and the method decides when to use it.

Before JDK 8, Java had no recipe cards. To pass behaviour you wrote an anonymous class, a whole class just to hold one method:

// JDK 7 style: an anonymous class
Predicate<String> shortName = new Predicate<String>() {
  @Override public boolean test(String s) {
    return s.length() <= 3;
  }
};

// JDK 8 style: a lambda, same meaning
Predicate<String> shortName = s -> s.length() <= 3;

The official tutorial says lambdas let you "treat functionality as method argument, or code as data", and express instances of single-method classes more compactly than anonymous classes.Lambda tutorial

The syntax, piece by piece

(a, b) -> a + b              // params -> expression
p -> p.getAge() >= 18        // one param: no ( ) needed
e -> System.out.println(e)   // returns nothing
(a, b) -> { return a + b; }  // block: braces + return

Left of the arrow: the parameters. Right of the arrow: the body, which is either a single expression or a block in braces.Lambda tutorial You usually don't write the parameter types: the compiler works them out from where the lambda is used.

2. A functional interface: one empty slot

A lambda is not a free-floating function. Java always turns it into an object that implements some interface. Which interface? One with exactly one empty slot, that is, one abstract method. That is a functional interface. It may also have default or static methods; those already have bodies, so they don't count.Lambda tutorial

So the answer to the pre-test: s -> s.length() <= 3 has no type of its own. It takes the type of the place you put it. Assigned to Predicate<String>, it becomes a Predicate<String> object. The JDK says it directly: "Functional interfaces provide target types for lambda expressions and method references."java.util.function

The @FunctionalInterface label

You can mark your own interface with @FunctionalInterface. Then, if someone adds a second abstract method, the compiler is "required to generate an error message". The label is optional: the compiler treats any interface that fits the definition as functional "regardless of whether or not a FunctionalInterface annotation is present".FunctionalInterface javadoc

@FunctionalInterface
interface PriceRule {
  int apply(int price);      // the one abstract method
}
PriceRule tenOff = p -> p - 10;
tenOff.apply(100);           // 90

3. The standard toolbox: java.util.function

You rarely need your own interface. The package java.util.function ships ready-made ones, such as Predicate<T>, Consumer<T> and Function<T,R>.Lambda tutorial Learn them by their shape: what goes in, what comes out.java.util.function

There are also versions for primitive numbers, such as IntPredicate, which take an int directly and avoid boxing it into an Integer.

4. Method references: the shortest lambda

If your lambda only calls one method that already exists, you can just name that method. The tutorial calls method references "compact, easy-to-read lambda expressions for methods that already have a name".Method references tutorial There are four kinds:

KindSyntaxSame as the lambda
Static methodInteger::parseInts -> Integer.parseInt(s)
Method of a particular objectSystem.out::printlnx -> System.out.println(x)
Method of an arbitrary object of a typeString::lengths -> s.length()
ConstructorHashSet::new() -> new HashSet<>()

The third kind confuses beginners. String::length does not name a particular string. It means "whatever string comes in, call length() on it".

5. The rule interviewers ask: effectively final

A lambda can use local variables from the method around it. But there is a rule: "A lambda expression can only access local variables and parameters of the enclosing block that are final or effectively final."Lambda tutorial Effectively final means you never assign it a new value after it is first set. You don't need to write the word final.

Think of the recipe card again. You write "add base grams of salt" and hand the card over with base = 10. If you could secretly change base to 11 later, which value would the cook use? Java avoids the question: once a lambda reads a local variable, that variable may not change.

Lambdas don't open a new scope

Lambdas are lexically scoped: they don't inherit names from a supertype and don't introduce a new level of scoping, so names inside the lambda mean the same as just outside it.Lambda tutorial In practice: you cannot declare a lambda parameter with the same name as a local variable of the method around it; the tutorial shows the compiler error "Lambda expression's parameter x cannot redeclare another local variable defined in an enclosing scope". An anonymous class, in contrast, is a real class and has its own scope.

Trace the example step by step

List<String> names = Arrays.asList("ann", "bob", "cy", "dee");
Predicate<String> shortName = s -> s.length() <= 3;
Function<String, Integer> length = String::length;
names.stream().filter(shortName).map(length).forEach(System.out::println);
Step 1  "ann": test → 3 <= 3 true  → apply → 3 → println
Step 2  "bob": test → true         → 3 → println
Step 3  "cy":  test → true         → 2 → println
Step 4  "dee": test → true         → 3 → println

int base = 10;                                  // effectively final
Function<Integer, Integer> plusBase = x -> x + base;
System.out.println(plusBase.apply(5));          // 15

Common mistake: counting inside a lambda

int count = 0;
names.forEach(n -> count++);   // compile error: count is not effectively final

The fix is not to "trick" the compiler. Ask the stream for the answer instead: long count = names.stream().count();. Lesson 0004 explains why side effects inside stream lambdas are discouraged.

JDK 8 vs 17 vs 21

Lambdas, method references and java.util.function all arrived in JDK 8 and work the same on 17 and 21. Newer JDKs add more methods that take lambdas (for example the static Predicate.not, added in JDK 11 and shown in the diagramPredicate javadoc), but the rules in this lesson have not changed.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

How many abstract methods does a functional interface have?

One abstract method, the "empty slot" the lambda fills. Default and static methods already have bodies, so they don't count.

What is the type of the lambda s -> s.isEmpty()?

A lambda takes its type from its target: functional interfaces "provide target types for lambda expressions and method references".

A lambda reads the local variable limit. Three lines later, the method runs limit = 5;. What happens?

Captured locals must be final or effectively final. A reassignment anywhere in the method breaks that, so the compiler rejects it.

Which standard interface takes a T and returns a boolean?

Predicate<T> has boolean test(T t). Consumer returns nothing, Supplier takes nothing, Function returns any R.

Which lambda is the same as the method reference String::length?

This is "an instance method of an arbitrary object of a type": the incoming string becomes the object the method is called on.

"Lambdas are lexically scoped." What does that mean in practice?

Lambdas don't inherit names from a supertype or introduce a new level of scoping. An anonymous class, by contrast, does have its own scope.

Example answer

"A lambda, added in JDK 8, is a short anonymous function, so I can pass behaviour as a value, for example to filter or forEach. Before that we wrote anonymous classes just to hold one method. A lambda always becomes an object of a functional interface, which is an interface with exactly one abstract method; it can still have default and static methods. The JDK gives the common shapes in java.util.function: Predicate returns a boolean, Function maps T to R, Consumer takes a value and returns nothing, Supplier produces one. If the lambda only calls an existing method, I use a method reference like String::length. And one rule: a lambda can only read local variables that are final or effectively final, so I can't increment a counter inside it."
