Today's win: write a lambda, pick the right functional interface, and explain the 'effectively final' rule.

What a lambda is (JDK 8)

Lambda expressions let you "treat functionality as method argument, or code as data" and express instances of single-method classes more compactly than anonymous classes.[1] They work with functional interfaces: interfaces with exactly one abstract method (they may also have default or static methods).[1] The JDK ships standard ones in java.util.function, such as Predicate<T>, Consumer<T> and Function<T,R>.[1]

Syntax

(a, b) -> a + b                 // parameters -> expression
p -> p.getAge() >= 18           // one parameter: parentheses optional
email -> System.out.println(email)
String::length                  // method reference

A body is a single expression or a block in braces.[1]

The rule interviewers ask

"A lambda expression can only access local variables and parameters of the enclosing block that are final or effectively final."[1] Effectively final means never reassigned after initialization. Lambdas are also lexically scoped: they introduce no new scope level, so a lambda's declarations are interpreted as in the enclosing environment.[1]

Retrieval practice

Answer from memory. One attempt each.

1. A functional interface has exactly how many abstract methods?

It contains only one abstract method, though it may have default or static methods.[1]

2. A lambda reads a local variable that is reassigned later. Result?

Captured locals must be final or effectively final.[1]

3. Which standard interface takes T and returns boolean?

Predicate<T> is the boolean-returning test interface in java.util.function.[1]

4. Lambdas are lexically scoped. Meaning?

They do not inherit names from a supertype or introduce a new level of scoping.[1]
