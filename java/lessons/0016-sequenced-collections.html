First, last and reversed: sequenced collections (JDK 21)

One set of methods for "the first one", "the last one" and "backwards", on every collection that has an order.

Java (JDK 8, 17, 21) · Lesson 0016 · step 43 of 46 · Core · ~20 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? "Give me the latest order", "show the newest message first": you need the first or last element all the time. Before JDK 21, every collection type did it differently. Interviewers ask "What are sequenced collections in Java 21?" to see if you follow the modern API. After this lesson you can answer, and stop writing list.get(list.size() - 1).
Today's win: use getFirst, getLast and reversed on lists, deques and ordered sets and maps, and name the three new interfaces.
collection
An object that holds a group of elements, like a List or a Set.
interface
A list of methods a class promises to have. List is an interface; ArrayList is a class that keeps the promise.
encounter order
The order you meet the elements when you loop over them. A list has one; a HashSet does not promise any.
generic <E>
A placeholder for "the type of the elements". SequencedCollection<String> holds strings.
view
A second "window" onto the same data. It copies nothing; if the data changes, the view shows the change.
deque
Say "deck": a queue you can use from both ends, for example ArrayDeque.

Before you start

Say out loud: "How do I get the last element of an ArrayList? And of a LinkedHashSet?" If the second one feels awkward, good: that awkwardness is the reason this lesson exists.

1. The old way: four types, four answers

Think of a queue at the bank. Everyone understands "the first person" and "the last person". Nobody needs a different word for it depending on whether the queue is inside or outside the building.

Java before 21 did need different words. JEP 431 lists them:JEP 431

TypeFirst elementLast element
Listlist.get(0)list.get(list.size() - 1)
Dequedeque.getFirst()deque.getLast()
SortedSetsortedSet.first()sortedSet.last()
LinkedHashSetlinkedHashSet.iterator().next()missing

The last cell is the worst: "The only way to get the last element of a LinkedHashSet is to iterate the entire set."JEP 431 Reverse iteration was just as uneven. And there was no common type, so you could not write one method that accepts "any collection with an order".

2. The new way: one interface, both ends

JEP 431 introduces "new interfaces to represent collections with a defined encounter order". Such a collection "has a well-defined first element, second element, and so forth, up to the last element."JEP 431 Here is the main one, exactly as the JEP shows it:JEP 431

interface SequencedCollection<E> extends Collection<E> {
    // new method
    SequencedCollection<E> reversed();
    // methods promoted from Deque
    void addFirst(E);
    void addLast(E);
    E getFirst();
    E getLast();
    E removeFirst();
    E removeLast();
}

Notice "promoted from Deque": the names are not new. Deque already had them; JDK 21 moved them up so every ordered collection shares them.

Run the course example on JDK 21:

$ java java/examples/jdk21/Jdk21Features.java
circle r=5.0 at 1,2
huge circle at 0,0
rect width 4 height 3
null handled inside the switch | blank string | string x | int 7
a c [c, b, a]
one=1 two=2 {two=2, one=1}

The first highlighted line is list.getFirst(), list.getLast() and list.reversed() on ["a", "b", "c"]. The second is a map, section 5.

3. reversed() is a view, not a copy

A view is like looking at a street through the rear window of a car: you see the same street, just the other way round. If a new shop opens, you see it in both windows.

JEP 431: "The new reversed() method provides a reverse-ordered view of the original collection." Changes to the original show in the view, and "If permitted, modifications to the view write through to the original collection."JEP 431 I ran these lines on JDK 21:

var list = new ArrayList<>(List.of("a", "b", "c"));
var rev = list.reversed();
list.add("d");
System.out.println(rev);
Step 1  rev is created: it remembers "read list backwards"
Step 2  list becomes [a, b, c, d]
Step 3  printing rev reads list backwards now
[d, c, b, a]

That makes reversed() cheap: no elements are copied. It also means you can loop backwards with a normal for-each: for (var x : list.reversed()). In JDK 8 you needed a ListIterator walking from the end, or Collections.reverse on a copy.

4. Which collections are sequenced?

JDK 21 added three interfaces and fitted them into the existing family. List and Deque now extend SequencedCollection; LinkedHashSet and LinkedHashMap add SequencedSet and SequencedMap; SortedSet and SortedMap now extend them too.JEP 431

Look at what is not in the picture: HashSet and HashMap. They have no defined order, so they are not sequenced. I checked: new HashSet<>() instanceof SequencedCollection prints false.

SequencedSet only adds one thing: "SequencedSet<E> reversed(); // covariant override".JEP 431 "Covariant" means the reversed view of a set is still a set, not just a collection.

A set cannot hold the same element twice, so what does addFirst do with an element that is already there? "If the element is already present in the set then it is moved to the appropriate position."JEP 431 My run:

var set = new LinkedHashSet<>(List.of("x", "y", "z"));
set.addFirst("z");
System.out.println(set + " last=" + set.getLast());
[z, x, y] last=y

One line for the last element of a LinkedHashSet, the cell that was "missing" in the old table.

5. Maps with an order: SequencedMap

Maps are not collections in Java (Map does not extend Collection), so they get their own interface:JEP 431

interface SequencedMap<K,V> extends Map<K,V> {
    // new methods
    SequencedMap<K,V> reversed();
    SequencedSet<K> sequencedKeySet();
    SequencedCollection<V> sequencedValues();
    SequencedSet<Entry<K,V>> sequencedEntrySet();
    V putFirst(K, V);
    V putLast(K, V);
    // methods promoted from NavigableMap
    Entry<K, V> firstEntry();
    Entry<K, V> lastEntry();
    Entry<K, V> pollFirstEntry();
    Entry<K, V> pollLastEntry();
}

From the course example:

var map = new LinkedHashMap<String, Integer>();
map.put("one", 1); map.put("two", 2);
System.out.println(map.firstEntry() + " " + map.lastEntry() + " " + map.reversed());
one=1 two=2 {two=2, one=1}

"Poll" means "get and remove": pollFirstEntry() takes the oldest entry out of a LinkedHashMap. That is handy for a simple cache that drops its oldest item (you will build an LRU cache in lesson 0033).

6. Traps: empty collections and "I can't add there"

Trap 1: empty. "The get*() and remove*() methods throw NoSuchElementException if the collection is empty."JEP 431 Note the exception changes compared with the old way: list.get(0) on an empty list throws IndexOutOfBoundsException, while list.getFirst() throws NoSuchElementException. Check isEmpty() first.

Trap 2: you can't always add at an end. "The add*(E) and remove*() methods are optional, primarily to support the case of unmodifiable collections." For sorted collections the position comes from comparing elements, so "these methods can throw UnsupportedOperationException".JEP 431 My run on JDK 21:

new TreeSet<>(List.of(3, 1, 2)).getFirst()    → 1        (reading is fine)
new TreeSet<>(List.of(3, 1, 2)).reversed()    → [3, 2, 1]
new TreeSet<>(List.of(3, 1, 2)).addFirst(0)   → UnsupportedOperationException
List.of(1).addFirst(0)                        → UnsupportedOperationException
new ArrayList<String>().getFirst()            → NoSuchElementException

JDK 21 also added Collections.unmodifiableSequencedCollection, unmodifiableSequencedSet and unmodifiableSequencedMap, read-only wrappers that keep the sequenced type.JEP 431

JDK 8 vs 17 vs 21

Sequenced collections are final in JDK 21 only. On 8 and 17 you use the old table above: on JDK 17 you write list.get(list.size() - 1). This is why lesson 2 mentions getFirst and getLast in the ArrayList Javadoc: those methods are documented there in the current API.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

Which interface adds putFirst and putLast?

SequencedMap has putFirst, putLast, firstEntry, lastEntry and related methods.

Which method returns a reverse-ordered view?

reversed() returns a reverse-ordered view. (Collections.reverse is the old static method that reorders a list in place.)

rev = list.reversed() on [a, b, c], then list.add("d"). What does rev print?

reversed() is a view, not a copy, so it shows the new element, read backwards.

Is a plain HashSet a SequencedCollection?

Only collections with a defined encounter order are sequenced. HashSet is not; LinkedHashSet is.

What does new ArrayList<String>().getFirst() do?

The get*() and remove*() methods throw NoSuchElementException on an empty collection. The old get(0) throws IndexOutOfBoundsException.

Why does treeSet.addFirst(0) throw UnsupportedOperationException?

In a sorted collection the order comes from comparison, so you cannot choose "first". The add* methods are optional and throw there.

Tick only the points you really said:

Example answer

"Before Java 21, getting the first or last element depended on the type: get(0) and get(size() - 1) for a list, first() and last() for a sorted set, and for a LinkedHashSet there was no way to get the last element without iterating. JEP 431 in JDK 21 added three interfaces, SequencedCollection, SequencedSet and SequencedMap, for every collection with a defined encounter order. They give the same methods everywhere: getFirst, getLast, addFirst, removeLast and so on, plus reversed(), which is a cheap view, not a copy. List, Deque, LinkedHashSet, LinkedHashMap and the sorted types are sequenced; HashSet and HashMap aren't, because they have no order. Two things to watch: on an empty collection getFirst throws NoSuchElementException, and on a sorted or unmodifiable collection addFirst throws UnsupportedOperationException."
