Default methods: adding to an interface without breaking anyone

Why JDK 8 let interfaces carry code, and which method runs when two of them disagree.

Java (JDK 8, 17, 21) · Lesson 0009 · step 24 of 46 · Core · ~20 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap · Tiếng Việt

Why this lesson? You call default methods every day (list.forEach, map.getOrDefault, predicate.and). Interviewers like to ask "Why do default methods exist?" and then show a class that implements two interfaces with the same default: "Which one runs?"
Today's win: explain why default methods exist in one sentence, and predict which move() runs in three situations: class vs interface, two interfaces, and an interface that extends another.
implement
A class implements an interface when it promises to provide its methods: class Duck implements Walker.
extend
A class extends one parent class and inherits its code. An interface can extend other interfaces.
default method
A method inside an interface that already has a body, marked with the word default.
static method
A method that belongs to the type itself, not to an object. You call it as Type.method().
signature
A method's name plus its parameter types, e.g. move(). Two methods with the same signature compete.
abstract class
A class that cannot be created directly; it may hold fields and unfinished methods for its subclasses.
binary compatibility
Old compiled code keeps working with a newer version of a library, without being recompiled.

Before you start

Say out loud: "A class extends Base, which has move(), and implements Walker, which has a default move(). Which one runs?" Make a guess. You will check it with real output in section 3.

1. The problem: one new rule breaks every member

Imagine a sports club with a rulebook that every member must follow. The club adds a new rule: "every member must also write a monthly report". Overnight, every member who has never written a report is breaking the rules. Unless the club adds: "if you don't write your own, we use this standard template". Now nobody breaks.

An interface is that rulebook. Before JDK 8, adding a method to an interface broke every class that implemented it: each one suddenly missed a method. That is why JDK 8 needed default methods to add forEach and stream to collections. The tutorial says they "enable you to add new functionality to the interfaces of your libraries and ensure binary compatibility with code written for older versions of those interfaces."Default methods tutorial

interface Walker {
  String name();                                  // abstract: each class must write it
  default String move() { return "walk"; }       // new rule WITH a standard body
}

class Cat implements Walker {
  public String name() { return "cat"; }         // no move() here, still compiles
}
new Cat().move();                                 // "walk"

You declare one with the default keyword and a body.Default methods tutorial The language spec says the body "provides a default implementation for any class that implements the interface without overriding the method".JLS 9.4

Static methods in interfaces

JDK 8 also allowed static methods in interfaces, so helper methods can live in the interface "rather than in a separate class".Default methods tutorial You call them on the interface name, for example Comparator.naturalOrder(). All interface methods are implicitly public, unless declared private.JLS 9.4

2. Rule one: the class wins

Think of a family recipe. Your parent (the superclass) gave you a recipe for soup, and a cookbook you bought (the interface) also has a soup recipe. At home, you follow the family recipe. Java does the same: a real method in a class, or in a superclass, always beats an interface default.Default methods tutorial

The language spec puts it formally: a class does not inherit a default method if a concrete method it inherits from its superclass has the same signature.JLS 8.4.8

3. Rule two: two interfaces, same default → you must choose

Now the class has no superclass method, but two interfaces both bring a default move(). Java refuses to guess. The spec: "It is a compile-time error if a class C inherits a default method whose signature is override-equivalent with another method inherited by C" (with a rare exception for an abstract superclass method).JLS 8.4.8.4 "Override-equivalent" here simply means "same signature".

To fix it, you override the method in the class. Inside, you can call a specific interface's version with the syntax InterfaceName.super.method().

Trace the example step by step

new Duck().move();
Step 1  Duck has its own move()            → run it
Step 2  Walker.super.move()                → "walk"
Step 3  Swimmer.super.move()               → "swim"
Step 4  "walk" + " and " + "swim"          → "walk and swim"

new Robot().move();
Step 1  Robot has no move() of its own
Step 2  superclass Base has move()         → class wins
Step 3  Walker's default is never used     → "base"
$ java java/examples/jdk8/DefaultMethods.java
walk and swim
base

The first line is Duck resolving the conflict explicitly; the second is Robot, where the class method beat the interface default.

4. Rule three: when an interface extends another

An interface can extend an interface that has a default. The tutorial lists three choices:Default methods tutorial

  1. Don't mention it. The new interface simply inherits the default.
  2. Redeclare it without a body. This makes it abstract again, so every implementing class must write it.
  3. Redefine it with a new body. This overrides the default; the more specific interface wins.
interface FastWalker extends Walker {
  default String move() { return "run"; }   // choice 3: redefine
}
class Dog implements Walker, FastWalker {}
new Dog().move();                            // "run": FastWalker is more specific

No conflict here: FastWalker already overrides Walker.move(), so only one candidate is left.

Common mistakes

  • Forgetting the override in the diamond. The code does not compile. Fix: override and choose with X.super.method().
  • Trying to give equals, hashCode or toString a default. "It is a compile-time error if a default method is override-equivalent with a non-private method of the class Object", because every class already inherits one from Object.JLS 9.4.1.2
  • Using an interface as a place to keep state. Interfaces have no instance fields, so a default method can only call other methods.
Interview angle: "Default methods vs abstract classes?" An interface can be implemented by many unrelated classes and still has no instance state; an abstract class can hold fields but a class can extend only one. Default methods exist mainly for interface evolution, as the tutorial's motivation shows.

JDK 8 vs 17 vs 21

Default and static interface methods arrived in JDK 8. In the JDK 21 language spec an interface method may also be private (and private static), which lets several defaults share a helper; this is not available in JDK 8.JLS 9.4 The "who wins" rules are the same on 8, 17 and 21.

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

What was the main reason for adding default methods in JDK 8?

Default methods let libraries evolve interfaces (like adding forEach to collections) and keep binary compatibility with old code.

Robot extends Base implements Walker. Both Base and Walker have move(); Walker's is a default. What does new Robot().move() run?

A concrete method from the class or its superclass always beats an interface default. The real output is base.

class Duck implements Walker, Swimmer {}, and both interfaces have a default move(). What happens?

Two inherited defaults with the same signature are a compile-time error. Duck must override and choose, e.g. with Walker.super.move().

Inside Duck, how do you call Walker's version of move()?

The syntax is InterfaceName.super.method(). Casting this would still call Duck's own override.

An interface extends Walker and redeclares String move(); with no body. What is move() now?

Redeclaring the default method makes it abstract, so every class that implements the new interface must write it.

What is wrong with interface Named { default String toString() { return "x"; } }?

A default method that is override-equivalent with a non-private Object method is a compile-time error. Every class already inherits toString from Object, and the class would win anyway.

Example answer

"Default methods came in JDK 8 so that library authors could add methods to existing interfaces without breaking every class that implements them. That's how Collection got stream() and Iterable got forEach. When there's a conflict, three rules apply. First, the class wins: if my class or its superclass has the method, the interface default is ignored. Second, the more specific interface wins, so if one interface extends another and overrides the default, that one is used. Third, if two unrelated interfaces give me the same default, the code doesn't compile until I override it; inside I can call Walker.super.move() to reuse one of them. Compared to an abstract class: an interface has no instance fields, but a class can implement many interfaces and extend only one class."
