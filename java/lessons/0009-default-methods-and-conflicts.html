JDK 8: default methods and conflict resolution

Java (JDK 8, 17, 21) · Lesson 0009 · step 8 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: explain why default methods exist and predict which method runs when a class inherits conflicting defaults.

Why they exist (JDK 8)

If a library adds a method to an interface, every implementer breaks. Default methods "enable you to add new functionality to the interfaces of your libraries and ensure binary compatibility with code written for older versions of those interfaces."[1] You declare one with the default keyword and a body.[1]

Who wins

  • Class wins: a concrete method in a class (or superclass) overrides any interface default.[1]
  • More specific interface wins: extending an interface with a default, you may inherit it, redeclare it (making it abstract again), or redefine it.[1]
  • Two unrelated defaults, same signature: the compiler forces the class to override and choose, using Walker.super.move() syntax (shown in the example; the tutorial page describes the general resolution rules).
java java/examples/jdk8/DefaultMethods.java
walk and swim      # Duck resolved the conflict explicitly
base               # Robot: class method beat the interface default

Interview angle: "Default methods vs abstract classes?" An interface can be implemented by many unrelated classes and still has no instance state; an abstract class can hold fields but a class can extend only one. Default methods exist mainly for interface evolution, as the tutorial's motivation shows.

Retrieval practice

Answer from memory. One attempt each.

1. Main motivation for default methods?

They let libraries add interface methods without breaking older implementers.[1]

2. Class and interface both supply the method. Which runs?

Class wins over an interface default.[1]

3. Two interfaces give the same default. What must you do?

The class must override and pick, for example with Walker.super.move().

4. Extending interface redeclares a default without body. Effect?

Redeclaring the default method makes it abstract.[1]
