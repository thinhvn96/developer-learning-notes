Collectors: groupingBy, partitioningBy and toMap

Java (JDK 8, 17, 21) · Lesson 0022 · step 10 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: write groupingBy, partitioningBy, joining and toMap pipelines, and know when toMap throws.

The four you need

  • groupingBy(classifier[, downstream]): a "group by" into a Map; downstream collectors like summingInt, counting, mapping aggregate each group.[1]
  • partitioningBy(predicate): a Map<Boolean, List<T>> that "always contains mappings for both false and true keys".[1]
  • joining(delimiter, prefix, suffix): concatenates into one String.[1]
  • toMap(keyMapper, valueMapper[, merge]): "If the mapped keys contain duplicates ... an IllegalStateException is thrown"; supply a merge function to combine them.[1]

Also: toList()/toSet() give "no guarantees on the type, mutability, serializability, or thread-safety"; use toCollection(Supplier) for control. Java 10 added toUnmodifiableList/Set/Map.[1]

java java/examples/CollectorsDemo.java
groupingBy      : {ops=[cy, dee], dev=[ann, bob]}
sum by dept     : {ops=9600, dev=9400}
partitioningBy : {false=3, true=1}
toMap duplicate: IllegalStateException
toMap w/ merge  : {4200=bob, 4800=cy+dee, 5200=ann}

Retrieval practice

Answer from memory. One attempt each.

1. toMap sees two equal keys and no merge function. Result?

Duplicate keys throw IllegalStateException unless you pass a merge function.[1]

2. Which collector always yields true and false keys?

partitioningBy's map contains both keys.[1]

3. Which collector builds a delimited String?

joining concatenates elements with optional delimiter.[1]

4. Does toList guarantee a mutable list?

No guarantees on type or mutability.[1]
