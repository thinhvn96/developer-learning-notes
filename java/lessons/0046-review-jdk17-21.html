Review 7: what JDK 17 and 21 added

Nine lessons, one timeline: the language features you write every day since 17, and the four big changes of 21.

LTS
"Long-term support": a release that vendors keep patching for years. JDK 8, 17 and 21 are the ones companies run in production.
final (feature)
A feature that is finished and permanent in a release, not a "preview" you must switch on.
record
A class that is just a carrier of values; Java writes the constructor, accessors, equals, hashCode and toString (lesson 0003).
sealed type
A class or interface that lists every allowed subtype with permits (lesson 0014).
pattern
A test in instanceof or case that checks a shape and names the parts, like String s or Point(int x, int y).
virtual thread
A cheap Java thread that borrows a real OS thread only while it runs code (lesson 0006).
generation
A part of the heap for young or old objects; generational ZGC keeps them apart (lesson 0017).

1. One timeline for everything

Think of a house that was renovated room by room. If you only visit on the opening days, you miss the work in between. Companies jump from one LTS to the next (8, then 17, then 21), so "JDK 17" means every feature finalized up to 17, not only what 17 itself added (lesson 0013).

2. The modelling trio: record + sealed + pattern switch

Three lessons are really one idea. A record says what data a variant holds. A sealed interface says which variants exist. A pattern switch handles each variant, and the compiler checks you covered them all. Think of a menu with a fixed list of dishes, each with its own recipe card: the kitchen can check that every dish has a cook.

Old way next to new way, for the same job:

// JDK 8: open class hierarchy, test and cast, a default "just in case"
if (s instanceof Circle) { Circle c = (Circle) s; return Math.PI * c.r() * c.r(); }
else if (s instanceof Rect) { Rect r = (Rect) s; return ...; }
else throw new IllegalStateException("unknown shape");

// JDK 17: sealed + records + instanceof patterns
//         (switching on types is not allowed yet)
if (s instanceof Circle c) return Math.PI * c.r() * c.r();

// JDK 21: pattern switch, exhaustive, no default
return switch (s) {
    case Circle(var c, var r) -> Math.PI * r * r;
    case Rect(var a, var b)   -> ...;
};

Two traps tie the lessons together. A record is only shallowly immutable, so a List component needs List.copyOf in a compact constructor (0003). And a switch without case null still throws NullPointerException; on 17 and 21 its message tells you which expression was null (0015, 0027).

4. Mixed task: find the three bugs

Read this JDK 21 code like a reviewer. There are three bugs, each from a different lesson. Find them, name the lesson, and say the fix before opening the answer.

sealed interface Payment permits Card, Transfer {}

// (A) a card is a value object: nobody may change it after creation
record Card(String number, List<String> tags) implements Payment {}
record Transfer(String iban) implements Payment {}

// (B) label every payment
static String label(Payment p) {
    return switch (p) {
        case Payment x  -> "payment";
        case Card c     -> "card " + c.number();
        case Transfer t -> "transfer " + t.iban();
    };
}

// (C) the bank API allows at most 10 calls at once
ExecutorService calls = Executors.newFixedThreadPool(10, Thread.ofVirtual().factory());
Show the three bugs

(B) Lesson 0015. Cases are tried top to bottom, and case Payment x matches everything, so the next cases are dominated. It does not even compile; I checked on JDK 21: "this case label is dominated by a preceding case label". Fix: delete the general case. Because Payment is sealed, Card and Transfer already cover it, with no default.

(A) Lesson 0003. A record is only shallowly immutable. The caller still holds the tags list and can add to it, and the card "changes". Fix: a compact constructor Card { tags = List.copyOf(tags); }.

(C) Lesson 0006. That is a pool of virtual threads, used to limit concurrency. "Never pool virtual threads"; limit with a Semaphore instead: new Semaphore(10), acquire() before the call, release() in finally, and run each task on newVirtualThreadPerTaskExecutor().

Practice

Answer from memory, don't scroll up. The options are in a different order every time you open the page.

Where is var NOT allowed?

var is only for local variables with an initializer and loop indexes; not parameters, fields, return types or catch parameters. See lesson 0012.

A switch on a sealed Shape has a case for every permitted record. On JDK 21, do you need default?

Pattern switches must be exhaustive, and for sealed types the check uses the permits clause. See lessons 0015 and 0014.

record Team(String name, List<String> members). The caller keeps the list it passed in and adds a name. What does the team see?

The field is final, but it points to the same mutable list. Fix with List.copyOf in a compact constructor. See lesson 0003.

Your service runs 10,000 blocking HTTP calls on virtual threads, but the partner allows only 20 at once. What do you add?

Never pool virtual threads; limit concurrency with a Semaphore. A synchronized block would allow only one call and pin the carrier on 21. See lesson 0006.

Which keyword reopens one branch of a sealed hierarchy so anyone may extend it?

Each permitted subtype must be final, sealed or non-sealed; non-sealed opens that branch again. See lesson 0014.

You start a JDK 21 service with -XX:+UseZGC only. Which collector runs?

On JDK 21 you need -XX:+UseZGC -XX:+ZGenerational for the generational mode. See lesson 0017.

What does an arrow label case 6, 7 -> "weekend"; do after it runs?

With -> only the code to the right runs. yield is for returning a value from a block. See lesson 0013.

rev = list.reversed() on [1, 2, 3], then list.add(4). What is rev?

reversed() returns a view, not a copy, so it sees the new element. See lesson 0016.

On JDK 21 you see Cannot invoke "String.trim()" because "<local2>[0]" is null. Why <local2> and not the variable name?

Local names need debug info; with javac -g the message reads "names[0]". The messages themselves need no flag on 21. See lesson 0027.

Which task gains the most from virtual threads?

Virtual threads give scale for blocking work, not speed for CPU work. See lesson 0006.

The selector of a JDK 21 switch is null; the switch has default but no case null. Result?

Without case null the switch throws NPE "as before"; default does not catch null. See lesson 0015.

After if (!(obj instanceof String s)) return;, can you use s on the next line?

Flow scoping: a pattern variable is in scope where it has definitely matched, including after a negated early return. See lesson 0013.

Why does generational ZGC collect the young generation more often?

The weak generational hypothesis: young objects tend to die young. Old-to-young pointers exist; the remembered set tracks them. See lesson 0017.

The final test: say it in 60 seconds

Recall 1. An interviewer asks: "What changed in Java between 8 and 17 that you use every day?" Start a timer. Answer out loud, then click.

Tick only the points you really said:

Example answer

"Moving from 8 to 17 mostly changed how much code I write. I use var for locals when the right side makes the type obvious; it's still static typing. Text blocks let me paste JSON or SQL without escaping. Switch became an expression with arrow labels, so no more forgotten break, and it must be exhaustive. instanceof now tests and casts in one step. Records replaced most of my DTO boilerplate, with equals and hashCode from all components, but they're only shallowly immutable, so I copy lists in the compact constructor. Sealed classes let me close a hierarchy with permits. And in production, NullPointerExceptions now say exactly which expression was null, which saves a lot of debugging time."

Recall 2. An interviewer asks: "How do records, sealed types and pattern matching work together in Java 21?" Start a timer. Answer out loud, then click.

Tick only the points you really said:

Example answer

"Together they give Java algebraic data types. I declare a sealed interface, say Payment permits Card, Transfer, and each variant is a record that holds its own data. Then I process them with a pattern switch: case Card(var number, var tags) checks the type and unpacks the fields in one step, and patterns can nest. Because the interface is sealed, the compiler knows every variant, so the switch is exhaustive without a default, and if someone adds a third variant every switch that doesn't handle it stops compiling. Cases are tried top to bottom, a case that's dominated by an earlier one is a compile error, and I can add guards with when. Null still throws unless I write case null. Sealed types and records are in 17, but switching on patterns needs 21."

Recall 3. An interviewer asks: "Why upgrade a backend from 17 to 21? What would you watch out for?" Start a timer. Answer out loud, then click.

Tick only the points you really said:

Example answer

"21 is the next LTS and it brings four real wins. First, virtual threads: I can keep simple blocking code, one thread per request, and handle far more concurrent requests, because a virtual thread unmounts from its carrier while it waits. It's throughput, not speed. I'd watch three things: never pool them, use a Semaphore to protect downstream services, and look for pinning, since on 21 long I/O inside synchronized blocks the carrier. Second, generational ZGC gives sub-millisecond pauses with less overhead than the old ZGC, but on 21 you must add -XX:+ZGenerational, and I'd only switch from G1 after comparing GC logs. Third, pattern matching for switch and record patterns make domain code with sealed types much cleaner. And sequenced collections finally give one API for first, last and reversed."
