JDK 8: java.time, the date and time API

Java (JDK 8, 17, 21) · Lesson 0011 · step 11 of 27 · Core · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: pick the right java.time class for a requirement (birth date, meeting time, timestamp, elapsed time).

The classes (JDK 8, package java.time)

NeedClass[1]
Date only, no zone (a birth date)LocalDate
Time of day onlyLocalTime
Date and time, no zoneLocalDateTime
Date, time and zone (a meeting)ZonedDateTime (or OffsetDateTime for a fixed offset)
Machine timestamp on the timelineInstant (nanosecond resolution from the epoch)
Amount of time in seconds and nanosDuration
Amount of time in years, months, daysPeriod

The tutorial's guidance: human time uses the Local classes, machine time uses Instant, and zone-aware needs use ZonedDateTime or OffsetDateTime.[1]

Run it

java java/examples/jdk8/JavaTime.java
1990-05-17 -> 1990-06-16 (original unchanged)
Duration: PT3H30M
Period:   P36Y3D
Same instant in Tokyo: 2026-01-01T09:00+09:00[Asia/Tokyo]

The example shows that plusDays returns a new object: these types are immutable (observed in the run; the overview page lists the classes but the immutability point is best confirmed in the class Javadoc). Source: JavaTime.java.

Senior rule: store and transmit timestamps as Instant (UTC), convert to a zone only for display, and keep Duration and Period distinct: a "month" is not a fixed number of seconds.

Retrieval practice

Answer from memory. One attempt each.

1. Best type for a machine timestamp?

Instant measures a continuous timeline from the epoch in nanoseconds.[1]

2. Best type for a birthday without a zone?

The tutorial's example for a birth date ignoring timezone is LocalDate.[1]

3. Which measures years, months and days?

Period is date-based; Duration is seconds and nanoseconds.[1]

4. Which carries date, time and a zone ID?

ZonedDateTime holds date, time, offset and zone ID.[1]
