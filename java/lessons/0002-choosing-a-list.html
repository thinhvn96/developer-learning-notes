Choosing between ArrayList, LinkedList and ArrayDeque

Java (JDK 8, 17, 21) · Lesson 0002 · step 4 of 27 · Foundation · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: answer 'ArrayList or LinkedList?' with the documented facts instead of folklore, and name the better queue/stack.

What the Javadoc actually promises

ArrayList is backed by an array with a capacity that grows automatically. size, isEmpty, get, set and iterator run in constant time; add runs in amortized constant time; "all of the other operations run in linear time". The Javadoc adds: "The constant factor is low compared to that for the LinkedList implementation."[1]

LinkedList: "Operations that index into the list will traverse the list from the beginning or the end, whichever is closer to the specified index."[2] So get(i) is a walk, not a jump.

ArrayDeque: "likely to be faster than Stack when used as a stack, and faster than LinkedList when used as a queue." Null elements are prohibited.[3]

Interview shape: default to ArrayList. For a stack or queue, reach for ArrayDeque. A LinkedList answer needs a specific reason. Note the docs claim "amortized" for add: one add occasionally copies the array, but n adds cost O(n) overall.

Three pitfalls, one run

java java/examples/ListPitfalls.java
ArrayDeque rejects null: NullPointerException
for-each + list.remove: ConcurrentModificationException
removeIf result: [1, 3]

None of the three is synchronized[1][2][3], and ArrayList's iterators are fail-fast[1]. Use removeIf or the iterator's own remove to delete while looping.

Retrieval practice

Answer from memory. One attempt each.

1. What does the ArrayList Javadoc say about get(i)?

get, set, size, isEmpty and iterator are constant time.[1]

2. Best default class for a FIFO queue or a stack?

The ArrayDeque Javadoc says it is likely faster than Stack as a stack and than LinkedList as a queue.[3]

3. What happens on arrayDeque.addFirst(null)?

Null elements are prohibited in ArrayDeque.[3]

4. You need thread-safe access to a plain ArrayList. What do the docs say?

Implementations are not synchronized; concurrent structural modification requires external synchronization, e.g. Collections.synchronizedList.[1]
