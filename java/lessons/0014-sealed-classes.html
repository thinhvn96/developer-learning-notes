JDK 17: sealed classes and interfaces

Java (JDK 8, 17, 21) · Lesson 0014 · step 22 of 27 · Advanced · ~10 minutes · Home · Java (JDK 8, 17, 21) ladder · Roadmap

Today's win: declare a sealed hierarchy and explain what the three modifiers on permitted subclasses mean and why sealing helps exhaustive checks.

What sealing does (final in JDK 17)

Sealed classes and interfaces restrict which other classes may extend or implement them. JEP 409's goals: let the author control which code implements a type, offer "a more declarative way than access modifiers to restrict the use of a superclass", and lay the foundation for exhaustive pattern analysis.[1]

public sealed interface Shape permits Circle, Square, Rect {}
record Circle(double r) implements Shape {}     // records are implicitly final
record Square(double side) implements Shape {}
record Rect(double w, double h) implements Shape {}

The three modifiers

Each permitted subclass must use exactly one of: final (no further extension), sealed (further restricted extension through its own permits), or non-sealed (open again).[1]

Records are a natural fit: a record is a shallowly immutable, transparent carrier of values.[2] Sealed interface plus records gives you algebraic data types (a closed set of variants), and on JDK 21 a switch over the interface needs no default because the compiler knows the full set (lesson 15).

Source: Jdk17Features.java defines exactly this hierarchy.

Interview angle: "Sealed versus enum versus final?" Enum: a closed set of instances of one type. Sealed: a closed set of types, each with its own shape of data. Final: no subclasses at all.

Retrieval practice

Answer from memory. One attempt each.

1. Keyword listing the allowed subtypes?

A sealed class uses a permits clause naming allowed subclasses.[1]

2. A permitted subclass must be which of these?

Exactly one of final, sealed and non-sealed is required.[1]

3. Which modifier reopens a branch for extension?

non-sealed reverts that branch to open extension.[1]

4. Release where sealed classes became final?

Finalized in Java 17 after previews in 15 and 16.[1]
