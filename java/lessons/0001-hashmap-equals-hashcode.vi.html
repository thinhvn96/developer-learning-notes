HashMap tìm value của bạn như thế nào

Và vì sao equals() và hashCode() phải đi cùng nhau.

Java (JDK 8, 17, 21) · Bài 0001 · bước 9/46 · Foundation · ~20 phút · Trang chủ · Lộ trình Java (JDK 8, 17, 21) · Lộ trình tổng · English

Vì sao có bài này? Người phỏng vấn rất hay mở đầu bằng câu "HashMap hoạt động thế nào?" Bạn dùng HashMap mỗi ngày. Bài này giúp bạn giải thích được nó bằng lời đơn giản, và tránh được bug phổ biến nhất.
Thành quả hôm nay: giải thích HashMap thành lời trong khoảng 60 giây, kể cả vì sao override equals() mà quên hashCode() sẽ làm nó hỏng một cách âm thầm.
key, value
Map lưu các cặp. Bạn tra value bằng key của nó, giống như tra một từ để ra nghĩa trong từ điển.
entry
Một key và value của nó, được lưu cùng nhau. Ví dụ "cat" → 1.
bucket
Một "ô" bên trong HashMap. HashMap có nhiều bucket, mỗi bucket chứa một phần các entry.
hash code
Một số nguyên (int) được tính từ một object. Bạn lấy nó bằng cách gọi hashCode(). HashMap dùng nó để chọn bucket.
collision
Hai key khác nhau rơi vào cùng một bucket (va chạm). Chuyện này bình thường.
override
Viết phiên bản riêng của một method mà class bạn được thừa kế, ở đây là equals() và hashCode() từ Object.
O(1)
Đọc là "O một": thời gian gần như không đổi, kể cả khi map lớn lên.

Trước khi bắt đầu

Thử trước đã. Hãy nói thành lời: "map.get(key) tìm ra value bằng cách nào?" Đừng tra cứu gì cả. Không biết cũng không sao. Thử trước giúp bạn nhớ bài lâu hơn; cuối bài bạn sẽ so sánh lại.

1. Hình dung: một bức tường hộp thư

Hãy tưởng tượng một bức tường có 16 hộp thư, đánh số từ 0 đến 15. Mỗi hộp thư là một bucket. Một HashMap mới bắt đầu với 16 hộp như vậy.mã nguồn

Khi bạn put, Java không đi tìm chỗ trống. Nó tính ra hộp thư đúng từ key. Khi bạn get, Java làm đúng phép tính đó và đi thẳng tới cùng hộp thư.

Đây là lý do get() nhanh. Java không nhìn vào cả 16 hộp thư; nó chỉ nhìn vào một. Tài liệu gọi đó là "hiệu năng thời gian hằng số cho các thao tác cơ bản (get và put), với giả định hàm hash phân tán các phần tử đều giữa các bucket".HashMap javadoc Đó là điều người phỏng vấn muốn nói khi bảo O(1) trung bình.

2. Theo dõi một key, từng bước một

map.put("cat", 1);
Step 1  Java calls "cat".hashCode()          → 98262
Step 2  Java turns 98262 into a box number   → 7
Step 3  Java stores the entry "cat" → 1 in box 7

map.get("cat");
        Same steps → box 7 → found → returns 1

Java biến 98262 thành 7 bằng cách nào? Bằng một mẹo bit rất nhanh mà bạn sẽ học ở bài 0030. Giờ chỉ cần nhớ: cùng key → cùng số → cùng hộp.

3. Hai key trong cùng một hộp

Chỉ có 16 hộp mà có hàng triệu key có thể có, nên đôi khi hai key khác nhau rơi vào cùng một hộp. Đó là collision, và nó bình thường.

Một ví dụ thật: hai chuỗi "Aa" và "BB" có cùng hash code là 2112. Vì vậy chúng vào cùng một hộp.

map.put("Aa", 1);
map.put("BB", 2);   // same box as "Aa"
map.get("BB");      // returns 2

Vậy Java tìm đúng entry bằng cách nào? Bên trong hộp, các entry tạo thành một chuỗi nhỏ. Java đi dọc chuỗi và hỏi hai câu với mỗi entry:

  1. Hash code có giống không? Nếu không, bỏ qua. So sánh hai con số rất nhanh.
  2. Key có bằng nhau không? Java gọi equals(). Nếu trả về true, đây là entry đúng.mã nguồn

Tóm lại, hashCode() tìm ra hộp, còn equals() tìm ra entry đúng bên trong hộp.

4. Quy tắc: object bằng nhau thì cùng hash code

Chính vì vậy, Java có một quy tắc trong tài liệu của Object.hashCode:Object javadoc

Nếu hai object bằng nhau (equals() trả về true), chúng bắt buộc phải có cùng hash code.

Chiều ngược lại thì không bắt buộc. Hai object khác nhau có thể có chung hash code, như "Aa" và "BB". Điều đó được phép; nó chỉ làm map chậm đi một chút.

Người phỏng vấn gọi đây là equals/hashCode contract. "Contract" (hợp đồng) đơn giản là "một quy tắc bạn phải tuân theo".

Chuyện gì xảy ra nếu bạn phá quy tắc?

Ở đây class override equals() nhưng quên hashCode():

class Point {
  final int x, y;
  Point(int x, int y) { this.x = x; this.y = y; }

  @Override public boolean equals(Object o) {
    return o instanceof Point p && p.x == x && p.y == y;
  }
  // hashCode() is missing!
}

map.put(new Point(1, 2), "A");
map.get(new Point(1, 2));   // almost always null!

Vì sao? Khi bạn không tự viết hashCode(), Java dùng bản mặc định từ Object, bản này cho mỗi object mới một con số riêng. Hai object Point bằng nhau nhưng có số khác nhau, nên Java tìm sai hộp và không thấy gì. Không có thông báo lỗi nào: chỉ là null. Bạn tự chạy thử:

$ java java/examples/LostKey.java
BadKey  lookup: null
GoodKey lookup: value

Cách sửa: luôn override cả hai method cùng lúc. Hoặc dễ hơn, dùng record (JDK 16+, nên dùng được trên 17 và 21): nó tự viết equals() và hashCode() cho bạn từ các field.Record javadoc

@Override public int hashCode() { return Objects.hash(x, y); }   // JDK 8 style

record Point(int x, int y) {}                                     // JDK 17 / 21 style

5. Đừng sửa key sau khi đã put vào

Quay lại các hộp thư. Bạn ghi địa chỉ lên lá thư và bỏ nó vào hộp thư 7. Sau đó bạn lén sửa địa chỉ trên lá thư. Lát sau bạn hỏi "thư của tôi đâu?". Java đọc địa chỉ mới, đi tới một hộp thư khác, và không thấy gì. Lá thư vẫn nằm ở hộp 7, nhưng sẽ không ai tìm ra nó.

Đó chính là điều xảy ra khi bạn sửa field của key sau put(): hash code của nó đổi, nên Java tìm sai hộp. Tài liệu của Map cảnh báo: "Phải hết sức cẩn thận nếu dùng object có thể thay đổi (mutable) làm key của map."Map javadoc

Cách sửa: dùng key immutable (bất biến), tức là key không thể thay đổi: String, Integer, List.of(...), record có các field immutable. Bài tập 0001 cho bạn tận mắt thấy bug này xảy ra.

Luyện tập

Trả lời theo trí nhớ, đừng cuộn lên. Thứ tự đáp án thay đổi mỗi lần bạn mở trang.

Vì sao map.get(key) nhanh?

Hash code cho Java biết dùng bucket nào. Java chỉ nhìn vào một bucket, không phải tất cả.

"Aa" và "BB" có cùng hash code. Sau map.put("Aa", 1) và map.put("BB", 2), map.get("BB") trả về gì?

Cả hai key ở cùng bucket (collision). Bên trong bucket, equals() tìm ra đúng key "BB", nên bạn nhận được 2.

Câu nào là quy tắc của Java?

Quy tắc chỉ đi một chiều: bằng nhau → cùng hash code. Object khác nhau có thể chung hash code ("Aa" và "BB").

Point override equals() nhưng không override hashCode(). Sau map.put(new Point(1, 2), "A"), map.get(new Point(1, 2)) trả về gì?

hashCode() mặc định cho mỗi object mới một số riêng, nên Java tìm sai bucket. Không lỗi gì cả, chỉ là null.

Giờ Point là record Point(int x, int y) {}. Cùng put, cùng get. Kết quả?

Record tạo cả equals() và hashCode() từ các field. Hai point có cùng x và y thì bằng nhau và có chung hash code.

Bạn put một key vào HashMap, rồi sửa field của key. Giờ get() không tìm thấy nó. Cách tốt nhất để tránh chuyện này?

Sửa key làm đổi hash code, nên Java tìm sai bucket. Hãy dùng key immutable: String, record, List.of(...).

Bài kiểm tra cuối: nói trong 60 giây

Người phỏng vấn hỏi: "HashMap hoạt động thế nào?" Bấm giờ. Trả lời thành lời, bằng câu đầy đủ. Sau đó bấm nút.

Chỉ tick những ý bạn thật sự đã nói:

Câu trả lời mẫu

"HashMap lưu các entry trong một mảng bucket. Khi em gọi put, Java gọi hashCode() trên key và dùng con số đó để chọn bucket. Khi em gọi get, nó làm lại đúng phép tính đó nên đi thẳng tới bucket đúng. Vì vậy get và put là O(1) trung bình. Đôi khi hai key rơi vào cùng một bucket, gọi là collision; lúc đó Java dùng equals() để tìm đúng key trong bucket. Đó là lý do object bằng nhau phải có cùng hash code: nếu không, Java sẽ tìm sai bucket. Và key nên immutable, vì nếu key bị sửa sau khi put vào thì map không tìm lại được nữa."

Bây giờ làm bài tập
