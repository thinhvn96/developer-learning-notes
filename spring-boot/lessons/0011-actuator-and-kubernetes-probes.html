Actuator and Kubernetes probes

Spring Boot · Lesson 0011 · step 11 of 13 · Advanced · ~12 minutes · Home · Spring Boot ladder · Roadmap

Today's win: expose health endpoints safely, and wire Spring's liveness and readiness groups into Kubernetes probes without creating cascading restarts.

Endpoints and exposure

Actuator endpoints let you monitor and interact with the application. "By default, only the health endpoint is exposed over HTTP and JMX", at /actuator/health; widen it with management.endpoints.web.exposure.include. Before exposing more, ensure they hold no sensitive information or are secured (firewall or Spring Security).[1]

Kubernetes probes

Two health groups are provided: /actuator/health/liveness and /actuator/health/readiness; point the Kubernetes livenessProbe/readinessProbe at them. The docs' key warning: liveness "should not depend on health checks for external systems": if a database fails, Kubernetes "might restart all application instances and create cascading failures". Readiness may include shared essential dependencies.[1]

RESULT GET /actuator/health/liveness  -> 200 {"status":"UP"}
RESULT GET /actuator/health/readiness -> 200 {"status":"UP"}
RESULT GET /actuator/env              -> 404          # not exposed
RESULT GET /actuator/beans            -> 404          # not exposed
livenessProbe:
  httpGet: { path: /actuator/health/liveness, port: 8080 }
readinessProbe:
  httpGet: { path: /actuator/health/readiness, port: 8080 }

The demo enables the groups with management.endpoint.health.probes.enabled=true (the docs say they are automatic on Kubernetes; I set it explicitly to run outside a cluster). Code: ActuatorProbesTest.java. Pair with the Kubernetes probes lesson.

Verified: the project in examples/demo-app (Spring Boot 4.1.1, JDK 21, generated with Spring Initializr) was built and its tests run in a Maven container; lines marked RESULT come from those tests. Run them yourself: cd spring-boot/examples/demo-app && ./mvnw test (or use the maven:3-eclipse-temurin-21 image).
