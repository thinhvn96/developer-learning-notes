Constructor versus setter injection

Spring Boot · Lesson 0002 · step 2 of 13 · Foundation · ~10 minutes · Home · Spring Boot ladder · Roadmap

Today's win: justify constructor injection for mandatory dependencies using the Spring team's own reasons.

Two variants

Constructor-based DI: the container calls a constructor whose arguments are the dependencies. Setter-based DI: the container calls setters after a no-argument constructor.[1]

The recommendation

"Use constructors for mandatory dependencies and setter methods or configuration methods for optional dependencies." The Spring team generally advocates constructor injection because it lets you build components as immutable objects, ensures required dependencies are not null, and returns components in a fully initialized state.[1]

@Service
public class OrderService {
    private final PaymentGateway payments;
    public OrderService(PaymentGateway payments) { this.payments = payments; }
}

File: OrderService.java. Setter injection is for optional dependencies with sensible defaults, or third-party classes you cannot constrain.[1]

Circular dependencies

They are possible with constructor injection and raise BeanCurrentlyInCreationException; using setter injection for one of the beans can resolve it.[1] Prefer redesigning to remove the cycle.

Retrieval practice

Answer from memory. One attempt each.

1. Which injection style is advised for mandatory dependencies?

Use constructors for mandatory dependencies.[1]

2. What does constructor injection let you do?

It lets you implement components as immutable objects.[1]

3. Circular constructor dependency raises what?

Circular dependencies with constructor injection throw BeanCurrentlyInCreationException.[1]

4. Setter injection suits which case?

Setters are for optional dependencies that can have reasonable defaults.[1]
