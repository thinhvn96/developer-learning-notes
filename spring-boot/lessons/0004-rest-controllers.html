REST controllers and request mapping

Today's win: write a REST controller with path variables and correct HTTP method mappings, and explain why the composed annotations are preferred.

Mapping shortcuts

Spring MVC maps requests to controller methods with @RequestMapping, and provides the composed annotations @GetMapping, @PostMapping, @PutMapping, @DeleteMapping and @PatchMapping. They are preferred because most controller methods should map to a specific HTTP method, while a bare @RequestMapping "by default matches all HTTP methods".[1]

@RestController
@RequestMapping("/persons")
class PersonController {

    @GetMapping("/{id}")
    public Person getPerson(@PathVariable Long id) { ... }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public void add(@RequestBody Person person) { ... }
}

File: PersonController.java. @PathVariable binds the {id} segment; @RequestBody binds the request body to an object; @ResponseStatus(HttpStatus.CREATED) answers 201.[1]

Interview angle: "PUT versus PATCH, and which are idempotent?" is HTTP semantics, not Spring. Tie it to the retry lesson: retries need idempotent operations.

Retrieval practice

Answer from memory. One attempt each.

1. Which annotation maps only HTTP GET?

@GetMapping is a composed annotation for GET.[1]

2. Bare @RequestMapping matches which methods?

By default it matches all HTTP methods.[1]

3. Which binds the {id} URL segment?

@PathVariable binds a URI template variable.[1]

4. Which sets a 201 response on POST?

@ResponseStatus(HttpStatus.CREATED) sets the status.[1]
