Bean Validation and 400 responses

Spring Boot · Lesson 0010 · step 8 of 13 · Core · ~10 minutes · Home · Spring Boot ladder · Roadmap · Tiếng Việt

Today's win: validate a request body with Bean Validation and know which status the client receives.

Constraints on the model

Bean Validation lets you declare constraints on the model and enforce them at runtime: @NotNull, @Size(max = 64), @Min(0) and so on.[1]

public record PersonRequest(@NotBlank String name, @Min(0) int age) { }

@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public PersonRequest add(@Valid @RequestBody PersonRequest person) { return person; }

What the client sees

In Spring MVC, "validation failures are reported as MethodArgumentNotValidException", which typically results in an HTTP 400 Bad Request. Method-level validation uses @Validated on the class.[1]

RESULT POST valid body -> 201 Created
RESULT POST invalid body (blank name, age -1) -> 400 Bad Request

Code: PersonRequest.java, PersonController.java, PersonControllerTest.java. The body of the 400 response and custom error formats are beyond the pages read; the linked MVC error-response docs cover them.

Validate at the boundary (controller) and also in the database with constraints: the database is the last line of defense.

Retrieval practice

Answer from memory. One attempt each.

1. Annotation to trigger validation of a body?

@Valid on the parameter enables validation.[1]

2. Exception on failure in Spring MVC?

Validation failures are reported as MethodArgumentNotValidException.[1]

3. Typical status for invalid input?

It typically results in HTTP 400 (the test returned 400).[1]

4. Which constraint forbids null?

@NotNull is a built-in constraint annotation.[1]
