Inversion of control and beans

Spring Boot · Lesson 0001 · step 1 of 13 · Foundation · ~10 minutes · Home · Spring Boot ladder · Roadmap

Today's win: define IoC, DI, bean and ApplicationContext precisely, the way an interviewer expects.

Definitions from the reference

Dependency injection is "a specialized form of IoC, whereby objects define their dependencies ... only through constructor arguments, arguments to a factory method, or properties that are set on the object instance". The container then injects them when it creates the bean. It is the inverse of the bean controlling construction of its dependencies itself, hence inversion of control.[1]

Bean: "an object that is instantiated, assembled, and managed by a Spring IoC container."[1]

BeanFactory "provides an advanced configuration mechanism capable of managing any type of object". ApplicationContext is a sub-interface that adds AOP integration, message resource handling, event publication and application-layer contexts such as WebApplicationContext; it "is a complete superset of the BeanFactory".[1]

One-sentence answer: "In Spring, I declare what a class needs; the container creates and wires the objects, so my code depends on abstractions and is easy to test."

Retrieval practice

Answer from memory. One attempt each.

1. What does the IoC container do?

The container instantiates, assembles and manages beans and injects dependencies.[1]

2. What is a Spring bean?

A bean is an object instantiated, assembled and managed by the IoC container.[1]

3. ApplicationContext relative to BeanFactory?

ApplicationContext is a sub-interface and complete superset.[1]

4. Why is it called inversion of control?

The bean no longer controls instantiation of its dependencies; the container does.[1]
