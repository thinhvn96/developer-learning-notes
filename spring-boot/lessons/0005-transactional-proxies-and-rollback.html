Three traps

  1. Checked exceptions commit. Throwing a checked Exception does not roll back by default. Use @Transactional(rollbackFor = Exception.class).[1]
  2. Self-invocation is ignored. In the default proxy mode only external calls through the proxy are intercepted; a method calling another method on the same object does not trigger transaction handling.[1]
  3. Visibility. Private methods are never transactional; with interface-based proxies only public methods are.[1]

The reference names AspectJ mode as the alternative if you need self-invocation to work.[1] Snippets: TransactionalPitfalls.java.

Verified

Retrieval practice

Answer from memory. One attempt each.

1. Default rollback triggers?

RuntimeException and Error trigger rollback; checked exceptions do not.[1]

2. Method calls another method on this. Transaction applied?

Self-invocation does not trigger transaction management in proxy mode.[1]

3. Make checked exceptions roll back with?

rollbackFor = Exception.class makes all exceptions trigger rollback.[1]

4. Default propagation?

PROPAGATION_REQUIRED is the default.[1]
