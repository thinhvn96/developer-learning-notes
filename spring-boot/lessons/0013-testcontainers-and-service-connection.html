Testcontainers and @ServiceConnection

Spring Boot · Lesson 0013 · step 13 of 13 · Senior · ~10 minutes · Home · Spring Boot ladder · Roadmap

Today's win: explain how Testcontainers and @ServiceConnection let integration tests use a real database container.

Idea

"The Testcontainers library provides a way to manage services running inside Docker containers. It integrates with JUnit, allowing you to write a test class that can start up a container before any of the tests run. Testcontainers is especially useful for writing integration tests that talk to a real backend service."[1]

@ServiceConnection

"A service connection is a connection to any remote service." Annotating a container field with @ServiceConnection defines the connection details automatically, and they "take precedence over any connection-related configuration properties".[1]

@Testcontainers
@SpringBootTest
class MyIntegrationTests {
    @Container
    @ServiceConnection
    static Neo4jContainer neo4j = new Neo4jContainer("neo4j:5");
    ...
}

(The docs' example uses Neo4j; the same shape applies to a PostgreSQL container. I did not run this lesson's pattern: the demo project uses in-memory H2, and running Testcontainers inside my Maven container would need Docker access I did not set up.) Why it matters: H2 can behave differently from PostgreSQL (isolation, locking, SQL dialect), so Senior teams test persistence against the real engine; see the PostgreSQL isolation lesson.

Retrieval practice

Answer from memory. One attempt each.

1. Testcontainers manages what?

It manages services running inside Docker containers.[1]

2. What does @ServiceConnection provide?

It defines ConnectionDetails for the container's service.[1]

3. Which wins: connection details or properties?

Connection details take precedence over connection properties.[1]

4. Best use of Testcontainers?

It is especially useful for integration tests against real services.[1]
