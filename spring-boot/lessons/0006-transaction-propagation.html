Transaction propagation: REQUIRED, REQUIRES_NEW, NESTED

Spring Boot · Lesson 0006 · step 10 of 13 · Senior · ~12 minutes · Home · Spring Boot ladder · Roadmap · Tiếng Việt

Today's win: pick between REQUIRED, REQUIRES_NEW and NESTED for a given scenario and name the risk of each.

The three modes

ModeBehavior[1]Watch for
REQUIRED (default)one physical transaction; joins an existing outer onean inner rollback-only marker affects the outer; may raise UnexpectedRollbackException
REQUIRES_NEWalways a new, independent physical transactioncan exhaust the connection pool and deadlock if the pool is too small
NESTEDone physical transaction with savepoints; inner can roll back without the outerworks only with JDBC resource transactions (for example DataSourceTransactionManager)

Choosing

REQUIRED suits the common call stack of a service delegating to repositories.[1] Use REQUIRES_NEW when work must commit or roll back independently of the caller, for example an audit record that must persist even if the business transaction fails. Because the outer transaction still holds its connection while the inner runs, the reference advises that the pool must exceed the number of concurrent threads by at least one.[1] NESTED gives partial rollback via savepoints.[1]

Verified

RESULT REQUIRES_NEW audit            -> accounts: 0, audit rows: 1
RESULT REQUIRED audit (joins caller) -> accounts: 0, audit rows: 0

Both scenarios fail the order after the audit call. The independent transaction committed its audit row; the joined one rolled back with the order. Code: AuditService.java.

Remember the proxy rule from the previous lesson: propagation set on a self-invoked method is ignored, so a REQUIRES_NEW method called from the same class does not start a new transaction.

Retrieval practice

Answer from memory. One attempt each.

1. Independent commit regardless of caller's outcome?

REQUIRES_NEW always creates an independent physical transaction.[1]

2. Which mode uses savepoints?

NESTED uses one physical transaction with savepoints.[1]

3. Main operational risk of REQUIRES_NEW?

It can exhaust the pool and deadlock if not properly sized.[1]

4. Default mode joins an existing transaction?

REQUIRED participates in an existing outer transaction.[1]
