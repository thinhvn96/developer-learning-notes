Bean scopes: singleton vs prototype

Spring Boot · Lesson 0007 · step 3 of 13 · Core · ~10 minutes · Home · Spring Boot ladder · Roadmap

Today's win: state the six bean scopes, the default, and why a prototype injected into a singleton stops being 'new'.

Scopes

ScopeMeaning[1]
singleton (default)one shared instance per container
prototypea new instance each time it is requested
request, session, application, websocketweb-aware scopes

Spring's singleton "differs from the GoF singleton": it is per container and per bean, not per class loader. Use prototype for stateful beans, singleton for stateless ones. For prototypes the container does not call destruction callbacks; the client must clean up.[1]

The trap

"When a singleton bean has a dependency on a prototype bean, the prototype bean is injected only once at singleton instantiation time." To get a new instance at runtime you need something like method injection, or an ObjectProvider.[1]

Retrieval practice

Answer from memory. One attempt each.

1. Default bean scope?

Singleton is the default scope.[1]

2. Prototype injected into a singleton. New instance per call?

It is injected only once at singleton instantiation (the test showed ids 1 and 1).[1]

3. Spring singleton means...?

It is per-container and per-bean, not per class loader.[1]

4. Who cleans up prototype beans?

Destruction callbacks are not called for prototypes; the client cleans up.[1]
