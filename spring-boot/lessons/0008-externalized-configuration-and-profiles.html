Externalized configuration, precedence and profiles

Spring Boot · Lesson 0008 · step 5 of 13 · Core · ~10 minutes · Home · Spring Boot ladder · Roadmap

Today's win: predict which value wins when the same property is set in a file, a profile file, and a higher-precedence source.

Precedence (later overrides earlier)

  1. default properties
  2. @PropertySource
  3. config data files (application.properties/.yaml)
  4. random values
  5. OS environment variables
  6. Java system properties
  7. JNDI, servlet init params
  8. SPRING_APPLICATION_JSON
  9. command-line arguments (highest)[1]

That is why the same JAR runs in every environment: files hold defaults, and Kubernetes ConfigMaps/env vars or command-line args override them (ConfigMap lesson).

Profiles

Profiles "segregate parts of your application configuration and make it be available only in certain environments". Mark beans with @Profile("production"); activate with spring.profiles.active=dev (property or command line). With none active, the default profile is enabled.[2] A profile file such as application-dev.properties adds or overrides values when active (the naming convention is used in the demo project and worked in the run).

RESULT default profile: name=demo-app greeting=hello bean=default-profile bean
RESULT dev profile:     name=demo-app greeting=hello from the dev profile bean=dev-profile bean
RESULT dev profile + test property: greeting=from a higher-precedence source

Code: ConfigAndProfileTest.java, application-dev.properties, GreetingConfig.java. The last case sets the property in the test annotation (a higher-precedence source than the profile file) and it wins.

Verified: the project in examples/demo-app (Spring Boot 4.1.1, JDK 21, generated with Spring Initializr) was built and its tests run in a Maven container; lines marked RESULT come from those tests. Run them yourself: cd spring-boot/examples/demo-app && ./mvnw test (or use the maven:3-eclipse-temurin-21 image).

Retrieval practice

Answer from memory. One attempt each.

1. Highest-precedence source?

Command-line arguments override everything listed before them.[1]

2. Env var vs application.properties. Winner?

OS environment variables come later in the order.[1]

3. Property to activate a profile?

spring.profiles.active activates profiles.[2]

4. No profile active. Which is enabled?

A profile named default is enabled.[2]
