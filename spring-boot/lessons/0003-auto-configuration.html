Auto-configuration and how to see it

Spring Boot · Lesson 0003 · step 4 of 13 · Core · ~10 minutes · Home · Spring Boot ladder · Roadmap · Tiếng Việt

Today's win: explain what Spring Boot auto-configuration does, how to override it, and how to ask Boot why it configured something.

What it does

"Spring Boot auto-configuration attempts to automatically configure your Spring application based on the jar dependencies that you have added." For example, with HSQLDB on the classpath and no database connection beans of your own, Boot configures an in-memory database.[1] You opt in with @EnableAutoConfiguration or @SpringBootApplication, added once, on your primary configuration class.[1]

Non-invasive

"Auto-configuration is non-invasive. At any point, you can start to define your own configuration to replace specific parts of the auto-configuration." Define your own DataSource bean and the embedded database backs away.[1]

See it, exclude it

  • Start with --debug to log a conditions report showing what was applied and why.[1]
  • Exclude a class: @SpringBootApplication(exclude = { DataSourceAutoConfiguration.class }), or set spring.autoconfigure.exclude.[1]
Interview line: "Boot's magic is conditional beans driven by the classpath and existing beans. When behavior surprises me I read the --debug conditions report."

Verified: the project in examples/demo-app (Spring Boot 4.1.1, JDK 21, generated with Spring Initializr) was built and its tests run in a Maven container; lines marked RESULT come from those tests. Run them yourself: cd spring-boot/examples/demo-app && ./mvnw test (or use the maven:3-eclipse-temurin-21 image).

Retrieval practice

Answer from memory. One attempt each.

1. What drives auto-configuration decisions?

It configures the app based on the jar dependencies you added.[1]

2. You define your own DataSource bean. Result?

Auto-configuration is non-invasive and backs away from parts you define.[1]

3. How do you see what was applied and why?

--debug logs a conditions report.[1]

4. How do you turn one auto-configuration off?

Use the exclude attribute of @SpringBootApplication or the property.[1]
