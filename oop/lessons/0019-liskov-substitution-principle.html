SOLID 3: Liskov Substitution Principle

OOP (Object-Oriented Programming) · Lesson 0019 · step 19 of 22 · Advanced · ~12 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: state LSP, spot a violating subclass, and repair the design.

The principle

"If S is a subtype of T, then objects of type T in a program may be replaced with objects of type S without altering any of the desirable properties of that program." In Martin's wording: functions using base-class references must work with derived classes without knowing it.[2] Behavioral subtyping rules: preconditions cannot be strengthened, postconditions cannot be weakened, invariants cannot be weakened, and the history constraint (a subtype cannot allow state changes the parent forbids).[1]

The classic violation

java oop/examples/LspDemo.java
Rectangle: area = 20 (expected 20)
Square: area = 16 (expected 20)
fixed design areas: 20, 16

Code written against Rectangle sets width 5 and height 4 and expects 20. A Square that overrides the setters to keep sides equal produces 16: it changed the behavior callers depended on, so it is not substitutable even though "a square is a rectangle" mathematically.[1] The fix separates the types under a common abstraction (Shape2) with immutable Rect2 and Sq2. Source: LspDemo.java.

Tests for substitutability: does the subclass throw for inputs the parent accepts (stronger preconditions), return less than the parent promised, or surprise callers? A subclass throwing UnsupportedOperationException for an inherited method is a red flag (see the next lesson).

Retrieval practice

Answer from memory. One attempt each.

1. LSP says a subtype must be...?

Objects of T may be replaced with S without altering desirable properties.[1]

2. Square extends Rectangle demo area?

The Square's setters changed both sides.

3. Which change violates LSP?

Preconditions cannot be strengthened in a subtype.[1]

4. A fix used in the demo?

Rect2 and Sq2 implement Shape2 independently.
