Today's win: define object, state, behavior and encapsulation, and show encapsulation protecting an invariant.

State and behavior

"Real-world objects share two characteristics: They all have state and behavior." A software object stores its state in fields and exposes its behavior through methods.[1]

Encapsulation

"Hiding internal state and requiring all interaction to be performed through an object's methods is known as data encapsulation": a fundamental principle of OOP.[1] The tutorial lists the payoffs of bundling code into objects: modularity, information hiding, code re-use, and pluggability and debugging ease.[1]

See it protect an invariant

1. What two things does every object have?

Objects have state (fields) and behavior (methods).[1]

2. What is data encapsulation?

Hiding internal state and requiring interaction through methods.[1]

3. Where is the balance rule enforced in the demo?

The private field can only change through deposit and withdraw.

4. A benefit of bundling code into objects?

Modularity, information-hiding, re-use and pluggability.[1]
