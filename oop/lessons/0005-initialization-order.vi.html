Thứ tự khởi tạo: static block, field, constructor

OOP (Lập trình hướng đối tượng) · Bài 0005 · bước 6/22 · Core · ~12 phút · Trang chủ · Lộ trình OOP · Lộ trình tổng · English

Thành quả hôm nay: dự đoán chính xác thứ tự chạy của static block, field initializer, instance block và constructor trong một hệ thống class kế thừa.

Các thành phần

  • Static initialization block chạy theo thứ tự trong mã nguồn khi class được khởi tạo.[1]
  • Instance initializer block "trông y hệt static initializer block, chỉ là không có từ khoá static"; compiler sẽ chép chúng vào mọi constructor.[1]

Thứ tự (quan sát thực tế)

java oop/examples/InitializationOrder.java
main starts
1 Parent static block
2 Child static block
3 Parent field initializer
4 Parent instance block
5 Parent constructor
6 Child field initializer
7 Child instance block
8 Child constructor
--- second object: static parts do not run again
3 Parent field initializer
4 Parent instance block
5 Parent constructor
6 Child field initializer
7 Child instance block
8 Child constructor

Đọc output: phần static của class cha, rồi tới của class con (mỗi class một lần); sau đó, với mỗi lần new Child(): field initializer và instance block của class cha, constructor của class cha, rồi tới field initializer, instance block và constructor của class con. Tutorial chỉ mô tả các block; thứ tự đầy đủ ở trên là những gì chương trình này in ra trên JDK 21. Mã nguồn: InitializationOrder.java.

Bẫy phỏng vấn: gọi một method có thể override từ trong constructor. Constructor của class cha chạy trước khi các field của class con được khởi tạo, nên bản override có thể nhìn thấy giá trị mặc định (một rủi ro ai cũng biết; hãy tự tái hiện nó trong bài tập).

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Với một new Child, cái gì chạy đầu tiên?

Khởi tạo class diễn ra trước; class cha trước class con.

2. Một static block chạy bao nhiêu lần?

Object thứ hai trong demo không chạy lại static block.

3. Compiler chép instance initializer block vào...?

Đó là cách chúng được dùng chung giữa các constructor.[1]

4. Constructor của Parent so với field initializer của Child?

Output cho thấy bước 5 (ctor cha) chạy trước bước 6 (field con).
