SOLID 2: Open/Closed Principle

OOP (Object-Oriented Programming) · Lesson 0018 · step 18 of 22 · Advanced · ~10 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: extend behavior by adding a class instead of editing a switch.

The principle

"Software entities should be open for extension, but closed for modification."[1] New behavior arrives by adding code, not editing tested code.

java oop/examples/OcpDemo.java
switch version: 90
NoDiscount -> 100
StudentDiscount -> 90
VipDiscount -> 80

priceWithSwitch must be edited to add a "vip" case, risking the existing ones. With the Discount interface, VipDiscount was added without touching anything else: polymorphism (lesson) does the dispatch. Source: OcpDemo.java. This is the Strategy pattern in disguise; Refactoring.Guru lists "adheres to the Open/Closed Principle" as a benefit of Factory Method, Strategy, Decorator, Observer and others.

Do not abstract prematurely: introduce the extension point when the second or third variant appears (a pragmatic rule, not from the sources).

Retrieval practice

Answer from memory. One attempt each.

1. Open for extension means...?

Extension by addition.[1]

2. Closed for modification means...?

You do not edit tested code to add features.[1]

3. Which design needed no edit for vip?

VipDiscount was a new class.

4. Mechanism that makes it work?

Callers use the interface; the object supplies behavior.
