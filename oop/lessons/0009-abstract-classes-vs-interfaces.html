Abstract classes versus interfaces

Abstract classes

An abstract class "cannot be instantiated" but can be subclassed, and may contain both abstract and non-abstract methods. A class with an abstract method must itself be abstract; a subclass usually implements them, otherwise it must also be abstract.[1]

Abstract classInterface[1]
Fieldsnon-static, non-final allowedpublic static final only
Methodspublic, protected, private concrete methodsall public
Inheritanceextend only one classimplement many

When to use which (tutorial guidance)

  • Abstract class: share code among closely related classes; need non-public members or non-static, non-final fields.
  • Interface: unrelated classes will implement it; specify behavior without dictating implementation; want multiple inheritance of type.[1]

Retrieval practice

Answer from memory. One attempt each.

1. Can you instantiate an abstract class?

Abstract classes cannot be instantiated.[1]

2. How many classes can one class extend?

Only one, but many interfaces can be implemented.[1]

3. Need shared state fields. Which?

Interfaces allow only public static final fields.[1]

4. Unrelated classes must share a capability. Which?

Use an interface when unrelated classes implement it.[1]
