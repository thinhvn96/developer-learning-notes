Initialization order: static blocks, fields, constructors

OOP (Object-Oriented Programming) · Lesson 0005 · step 6 of 22 · Core · ~12 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: predict the exact order in which static blocks, field initializers, instance blocks and constructors run in a class hierarchy.

The building blocks

  • Static initialization blocks run in source order when the class is initialized.[1]
  • Instance initializer blocks "look just like static initializer blocks, but without the static keyword"; the compiler copies them into every constructor.[1]

The order (observed)

java oop/examples/InitializationOrder.java
main starts
1 Parent static block
2 Child static block
3 Parent field initializer
4 Parent instance block
5 Parent constructor
6 Child field initializer
7 Child instance block
8 Child constructor
--- second object: static parts do not run again
3 Parent field initializer
4 Parent instance block
5 Parent constructor
6 Child field initializer
7 Child instance block
8 Child constructor

Reading the output: statics of the parent, then of the child (once per class); then, for each new Child(): the parent's field initializers and instance blocks, the parent constructor, then the child's field initializers, instance blocks and constructor. The tutorial documents the blocks; the full ordering above is what this program prints on JDK 21. Source: InitializationOrder.java.

Interview trap: calling an overridable method from a constructor. The parent constructor runs before the child's fields are initialized, so an override can see default values (a well-known hazard; reproduce it in the exercise).

Retrieval practice

Answer from memory. One attempt each.

1. Which runs first for a new Child?

Class initialization comes first; parents before children.

2. How many times does a static block run?

The second object in the demo did not rerun static blocks.

3. The compiler copies instance initializer blocks into...?

That is how they are shared between constructors.[1]

4. Parent constructor vs Child field initializers?

Output shows step 5 (parent ctor) before step 6 (child fields).
