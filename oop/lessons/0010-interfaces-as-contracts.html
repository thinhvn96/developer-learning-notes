Interfaces as contracts

OOP (Object-Oriented Programming) · Lesson 0010 · step 10 of 22 · Core · ~10 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: explain an interface as a contract enforced by the compiler, and swap implementations behind it.

The contract

An interface is a group of related methods "that defines a contract between a class and the outside world". "Implementing an interface allows a class to become more formal about the behavior it promises to provide", and "this contract is enforced at build time by the compiler": if a class claims to implement the interface, all its methods must appear before the class compiles.[1]

java oop/examples/InterfaceContracts.java
card ****4242 charged 100
wallet declined 100
gift card paid 30
PaymentMethod: pay(int) -> receipt

checkout(PaymentMethod, int) knows only the contract; three different implementations (two classes and a lambda) work unchanged. Interfaces can also carry default and static methods since JDK 8 (lesson). Source: InterfaceContracts.java.

Design rule reused everywhere later: "program to an interface, not an implementation". It is the seed of Strategy, Factory, Adapter and the Dependency Inversion Principle.

It defines a contract between a class and the outside world.[1]

2. Who enforces the contract?

3. Missing an interface method in the class?

All methods must appear before the class compiles.[1]

4. A lambda can implement...?
