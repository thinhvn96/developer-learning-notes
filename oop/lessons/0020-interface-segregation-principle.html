SOLID 4: Interface Segregation Principle

OOP (Object-Oriented Programming) · Lesson 0020 · step 20 of 22 · Advanced · ~10 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap · Tiếng Việt

Today's win: split a fat interface into role interfaces so no class implements methods it cannot support.

The principle

"Clients should not depend upon interface methods they do not use."[1]

java oop/examples/IspDemo.java
fat interface: Robot forced to implement eat() -> robots do not eat
robot works
human eats
human works

FatWorker forces FatRobot to implement eat(), and it can only throw UnsupportedOperationException (also an LSP smell). Splitting into Workable and Feedable lets each class implement just its roles and each client depend on only what it calls. Source: IspDemo.java.

Java has both faces: Comparator is a tiny single-purpose interface (Strategy), and the java.util.function package is a catalog of role interfaces (lambdas lesson).
