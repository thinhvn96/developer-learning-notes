Overriding versus hiding

OOP (Object-Oriented Programming) · Lesson 0007 · step 7 of 22 · Core · ~12 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: say which of instance methods, static methods and fields override and which hide, and why @Override matters.

The rules

  • An instance method with the same signature and return type as a superclass instance method overrides it; it may return a subtype (a covariant return type).
  • @Override makes the compiler error if nothing is actually overridden.
  • A static method with the same signature hides the superclass's; which version runs depends on whether it is invoked from the superclass or subclass.
  • The overriding method may allow more, but not less access; changing instance to static or back is a compile error.[1]
