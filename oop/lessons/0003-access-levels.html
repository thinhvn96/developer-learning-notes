[1] The tutorial's tips: "Use the most restrictive access level that makes sense for a particular member. Use private unless you have a good reason not to." and "Avoid public fields except for constants": public fields "tend to link you to a particular implementation and limit your flexibility in changing your code."[1]

Why it matters

java oop/examples/AccessLevels.java
celsius=25.0 fahrenheit=77.0
rejected: below absolute zero: -300.0

Because celsius is private, the rule "not below absolute zero" lives in one setter, and fahrenheit() is computed rather than stored, so it can never go stale. Source: AccessLevels.java. (Package-level access needs multiple packages to demonstrate; the table is from the tutorial.)

Retrieval practice

Answer from memory. One attempt each.

1. Which level is visible only inside the class?

private: class only.[1]

2. Does protected allow subclasses outside the package?

The table shows Y for subclass under protected.[1]

3. Guideline for choosing a modifier?

Use private unless you have a good reason not to.[1]

4. Public fields are okay for...?

Avoid public fields except for constants.[1]
