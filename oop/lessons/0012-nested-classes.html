Nested, inner, local and anonymous classes

OOP (Object-Oriented Programming) · Lesson 0012 · step 12 of 22 · Advanced · ~10 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap · Tiếng Việt

Today's win: choose between static nested, inner, local and anonymous classes and state what each can access.

Two categories

Inner classes (non-static) are tied to an instance of the enclosing class and "have access to other members of the enclosing class, even if they are declared private". Static nested classes have no access to the enclosing instance's members and behave like top-level classes nested for packaging convenience.[1]

Reasons to nest: logical grouping of classes used in one place, increased encapsulation ("by hiding class B within class A, A's members can be declared private and B can access them"), and more readable code near where it is used.[1]

Local and anonymous classes may capture local variables that are final or effectively final (same rule as lambdas: lesson). Prefer a lambda over an anonymous class for one-method interfaces; the Builder pattern uses a static nested class (lesson). Source: NestedClasses.java.
