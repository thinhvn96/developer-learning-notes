Today's win: explain the class/instance distinction, references versus objects, and constructor chaining with this(...).

Blueprint and instances

"A class is the blueprint from which individual objects are created." Your bicycle is an instance of the class of bicycles: each instance has its own field values (its state) while the methods come from the class.[1]

References

A variable holds a reference to an object, not the object. Two variables can point at the same object (an alias), so changing state through one is visible through the other.

java oop/examples/ClassAndInstances.java
gear=1 speed=10
gear=3 speed=25
a after alias.speedUp(1): 11   b unchanged: 25
a == alias: true, a == b: false

a and b are separate objects with separate state; alias is a second reference to a's object (a == alias is true). The no-arg constructor delegates with this(1, 0), so initialization logic lives in one place. Source: ClassAndInstances.java. This is the same reference-versus-equality issue behind equals and hashCode.

Retrieval practice

Answer from memory. One attempt each.

1. A class is...?

A class is the blueprint from which individual objects are created.[1]

2. Two references to one object. Change via one?

They alias the same object; the demo showed a's speed changing via alias.

3. What does this(1, 0) in a constructor do?

Constructor chaining delegates to another constructor of the same class.

4. Do instances share their field values?

Each instance has its own state; the demo's b stayed at 25 while a changed.
