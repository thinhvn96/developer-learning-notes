Polymorphism and virtual method invocation

OOP (Object-Oriented Programming) · Lesson 0008 · step 8 of 22 · Core · ~10 minutes · Home · OOP (Object-Oriented Programming) ladder · Roadmap

Today's win: explain virtual method invocation and distinguish runtime dispatch (overriding) from compile-time selection (overloading).

Definition

"Subclasses of a class can define their own unique behaviors and yet share some of the same functionality of the parent class." The key mechanism: "The Java virtual machine (JVM) calls the appropriate method for the object that is referred to in each variable. It does not call the method that is defined by the variable's type. This behavior is referred to as virtual method invocation."[1]

java oop/examples/PolymorphismDemo.java
Circle  area=3.14
Square  area=4.00
Circle  area=0.79
total=7.93
overload chosen for a Shape-typed variable holding a Circle: describe(Shape)

One loop over List<Shape> produced three different behaviors. The last line is the trap: overloads (describe(Shape) vs describe(Circle)) are chosen at compile time from the variable's declared type, so a Shape-typed variable holding a Circle selected describe(Shape). Overriding is dynamic; overloading is static. Source: PolymorphismDemo.java.

Why this matters: this is what lets callers depend on an interface and stay open to new types: the basis of most design patterns and of the Open/Closed Principle.

Retrieval practice

Answer from memory. One attempt each.

1. Which method runs for an overridden call?

The JVM calls the method of the object referred to.[1]

2. Overload resolution happens...?

The demo picked describe(Shape) from the declared type.

3. Virtual method invocation is...?

It is the runtime selection of the overridden method.[1]

4. What does polymorphism enable?

The demo's single loop printed three different areas.
