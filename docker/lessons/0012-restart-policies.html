Restart policies

Docker · Lesson 0012 · step 11 of 12 · Advanced · ~10 minutes · Home · Docker ladder · Roadmap

Today's win: pick a restart policy for a service and show how many times Docker restarts a failing container.

The four policies

  • no (default): do not restart.
  • on-failure[:max-retries]: restart if it exits with a non-zero code; optionally limit attempts.
  • always: always restart; if manually stopped, it restarts only when the daemon restarts or you restart it.
  • unless-stopped: like always, but a stopped container stays stopped even after a daemon restart.[1]

Set with docker run --restart ....[2]

Watch it

cd docker/examples && ./06-restart-policies.sh
/r-no-...   policy=no         restarts=0 state=exited exit=1
/r-fail-... policy=on-failure restarts=3 state=exited exit=1

Both containers ran exit 1. With on-failure:3 Docker retried three times then gave up. Source: 06-restart-policies.sh.

Restart policies restart a container that exits; they do not know if it is unhealthy but running. That is the job of health checks and, in Kubernetes, liveness probes (probes lesson).

Retrieval practice

Answer from memory. One attempt each.

1. Default restart policy?

no is the default.[1]

2. Which restarts only on non-zero exit?

on-failure restarts on error exits.[1]

3. Manually stopped, then daemon restarts. always does what?

always restarts when the daemon restarts, even if stopped manually.[1]

4. on-failure:3 with a crashing app. Restarts seen?

The demo recorded restarts=3 then exited.
