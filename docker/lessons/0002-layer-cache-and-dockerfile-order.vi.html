Layer cache và thứ tự lệnh trong Dockerfile

Docker · Bài 0002 · bước 4/12 · Foundation · ~10 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: sắp xếp một Dockerfile sao cho bước cài dependency vẫn dùng cache khi chỉ có source code thay đổi.

Quy tắc

"Mỗi lệnh trong Dockerfile này tương ứng với một layer trong image cuối cùng." Khi một layer thay đổi, cache của nó bị vô hiệu, và "nếu một layer thay đổi, mọi layer đứng sau nó cũng bị ảnh hưởng."[1]

Hệ quả

Đặt các lệnh ít thay đổi lên trước, các lệnh hay thay đổi xuống cuối. Trang build cache chỉ nêu quy tắc invalidation; lời khuyên về thứ tự là hệ quả thực tế của quy tắc đó (trong phần tài liệu tôi đã đọc không ghi rõ công thức sắp xếp này, nên hãy coi đây là suy luận, không phải trích dẫn).

# slow: any source edit invalidates the dependency download
COPY . .
RUN ./download-dependencies.sh

# better: dependency descriptor first, source afterwards
COPY pom.xml .
RUN ./download-dependencies.sh
COPY src/ src/

Với thứ tự thứ hai, sửa một file trong src/ chỉ làm mất cache các layer từ COPY src/ trở đi; layer dependency tốn kém vẫn được dùng lại.

.dockerignore loại các file như .git/ và output của build ra khỏi build context, nên những thay đổi không liên quan cũng không làm mất cache của các layer COPY.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Một layer thay đổi. Các layer phía sau thì sao?

Nếu một layer thay đổi, mọi layer phía sau nó đều bị ảnh hưởng.[1]

2. Lệnh nào nên đặt sớm nhất?

Đặt các layer ổn định lên trước để chúng luôn nằm trong cache.

3. Bạn chỉ sửa một file source. Layer nào chạy lại đầu tiên?

Cache bị vô hiệu bắt đầu từ layer đầu tiên thay đổi, tức lệnh COPY source, rồi lan xuống các layer sau.[1]

4. Vì sao nên thêm .dockerignore?

Nó loại các file không liên quan ra khỏi build context và các layer.
