CMD, ENTRYPOINT và exec form vs shell form

Docker · Bài 0009 · bước 5/12 · Core · ~10 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: dự đoán được container sẽ chạy gì từ ENTRYPOINT cộng CMD, và cái gì thay đổi khi bạn truyền tham số vào docker run.

Các quy tắc

  • "Chỉ có thể có một lệnh CMD ... chỉ lệnh cuối cùng có hiệu lực."
  • CMD cung cấp giá trị mặc định cho ENTRYPOINT, hoặc tự chạy một mình; "CMD sẽ bị ghi đè khi chạy container với các tham số khác".
  • Dùng ENTRYPOINT khi container đóng vai trò như một chương trình thực thi.[1]

không có ENTRYPOINT, có CMDCMD được chạy

Exec form vs shell form

Exec form (["executable","arg"]) là JSON, không gọi shell và không thay thế biến; shell form thì luôn dùng shell.[1] Best practices của Docker khuyên dùng exec form cho CMD/ENTRYPOINT để signal được xử lý đúng khi process là PID 1 (xem bài về hardening).[2]

./05-cmd-entrypoint-arg-env.sh
docker run lesson-entry                      -> hello world      # ENTRYPOINT + CMD
docker run lesson-entry Docker               -> hello Docker     # args replace CMD
docker run --entrypoint printenv lesson-entry APP_MODE -> prod

Với Java: ENTRYPOINT ["java","-jar","app.jar"], dùng CMD cho các tham số mặc định, và đặt JAVA_TOOL_OPTIONS trong biến môi trường cho các flag của JVM (gợi ý thiết kế; hãy test lại).

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. ENTRYPOINT exec form cộng CMD exec form. Cái gì được chạy?

ENTRYPOINT được chạy và CMD được nối vào làm tham số.[1]

2. Một Dockerfile có hai dòng CMD. Dòng nào có hiệu lực?

Chỉ CMD cuối cùng có hiệu lực.[1]

3. Tham số đặt sau tên image thay thế cái gì?

CMD bị ghi đè bởi các tham số khác truyền vào.[1]

4. Vì sao nên ưu tiên exec form?

Exec form đảm bảo signal được xử lý đúng khi process là PID 1.[2]
