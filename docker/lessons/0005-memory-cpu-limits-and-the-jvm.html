Memory and CPU limits, and what the JVM sees

Docker · Lesson 0005 · step 10 of 12 · Advanced · ~12 minutes · Home · Docker ladder · Roadmap · Tiếng Việt

Today's win: predict the JVM heap and CPU count inside a memory- and CPU-limited container, and explain what kills the container when it goes over.

Docker's limits

--memory (-m) is "the maximum amount of memory the container can use." When a container exceeds the limit on Linux, the kernel's out-of-memory handling "starts killing processes to free up memory". --cpus sets how much of the host CPU a container may use, for example --cpus="1.5" on a two-CPU host is at most one and a half CPUs.[1]

What the JVM sees

On Linux the JVM has container detection on by default ("automatic container detection support"), so it reads the container's memory and CPU limits; -Xlog:os+container=trace shows what it found.[2] -XX:MaxRAMPercentage defaults to 25 percent of the maximum memory; for small heaps (about 125 MB) -XX:MinRAMPercentage defaults to 50 percent.[2]

Measured with the example image

docker run --rm hello-multi
  processors: 12   max heap: 3920 MB      # no limits: 1/4 of host RAM

docker run --rm --memory=256m --cpus=1 hello-multi
  processors: 1    max heap: 121 MB       # heap about half of 256 MB

docker run --rm --memory=256m \
  -e JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75 hello-multi
  max heap: 185 MB

The 121 MB result is consistent with the documented 50 percent default for small heaps; that link is my reading of the reference, so confirm it in the exercise by changing the limit.

Senior point: heap is not the only memory the JVM uses (metaspace, thread stacks, direct buffers, code cache), so setting the heap to 100 percent of the limit invites the OOM killer. Choose a percentage below 100 and measure. The Kubernetes lesson on requests and limits builds on this.

Retrieval practice

Answer from memory. One attempt each.

1. Container exceeds --memory. What acts?

The kernel out-of-memory manager starts killing processes.[1]

2. With no limits, default max heap is about...?

The max heap defaults to 25 percent (MaxRAMPercentage), 3920 MB of about 15.7 GB in the run above.[2]

3. What does the JVM read to size itself in a container?

Container support is on by default on Linux.[2]

4. Why not set MaxRAMPercentage to 100?

The JVM also uses non-heap memory; heap plus that must fit within the limit (senior-level reasoning; measure it).
