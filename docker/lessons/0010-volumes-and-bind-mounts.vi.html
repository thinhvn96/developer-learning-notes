Volume và bind mount

Docker · Bài 0010 · bước 7/12 · Core · ~10 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: giữ dữ liệu sống lâu hơn container bằng volume, chia sẻ file của host bằng bind mount, và biết khi nào chọn cái nào.

Volume

"Volume là nơi lưu trữ dữ liệu lâu dài cho container, do Docker tạo và quản lý." Nội dung của volume "tồn tại bên ngoài vòng đời của một container cụ thể"; khi container bị hủy, writable layer của nó cũng bị hủy theo.[1] Tạo bằng docker volume create, liệt kê bằng docker volume ls, xóa bằng docker volume rm; mount bằng -v myvolume:/app hoặc cách viết tường minh hơn --mount source=myvolume,target=/app.[1]

Bind mount

Bind mount gắn một file hoặc thư mục của host vào container. Phù hợp khi dev (chia sẻ source code hoặc artifact của build) và để phân phối file cấu hình. Nhược điểm: "Container dùng bind mount gắn chặt với host" vì nó phụ thuộc vào cấu trúc thư mục của host. Thêm readonly để chặn container ghi vào.[2]

Xem cả hai

cd docker/examples && ./03-volumes-and-bind-mounts.sh
without a volume: cat: can't open '/data.txt': No such file or directory
named volume    : persisted
bind mount      : from host
readonly bind   : sh: can't create /mnt/new.txt: Read-only file system

Chọn volume cho dữ liệu mà Docker nên quản lý (database; xem bài về Compose); chọn bind mount khi bạn cần truy cập các file đó từ host.[1] Source: 03-volumes-and-bind-mounts.sh.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Container bị xóa. Named volume của nó thì sao?

Nội dung của volume tồn tại bên ngoài vòng đời của container.[1]

2. Kiểu mount nào phụ thuộc cấu trúc thư mục của host?

Container dùng bind mount gắn chặt với host.[2]

3. Làm sao để bind mount chỉ đọc?

Option readonly ngăn container sửa file của host.[2]

4. Dữ liệu ghi ra khi không có mount nằm ở đâu?

Writable layer bị hủy cùng với container.[1]
