Containers, images and layers

Docker · Lesson 0001 · step 1 of 12 · Foundation · ~10 minutes · Home · Docker ladder · Roadmap · Tiếng Việt

Today's win: explain in three sentences what a container, an image and a layer are, and why a container is not a VM.

Container

Per Docker's docs, a container is an isolated process that runs an application component "in their own environments without affecting the host system or other containers". It is self-contained and portable, and "more lightweight than virtual machines since multiple containers share the same kernel rather than each requiring a full operating system".[1]

Image

"A container image is a standardized package that includes all of the files, binaries, libraries, and configurations to run a container." Images are immutable: "Once an image is created, it can't be modified. You can only make a new image or add changes on top of it."[2]

Layer

"Container images are composed of layers. Each layer represents a set of file system changes that add, remove, or modify files."[2] Your Java app image is a base layer (OS plus JRE) with your application layers stacked on top.

Interview one-liner: an image is the immutable recipe-output, a container is a running (isolated) process started from it, and containers on one host share the host kernel.

See it

docker images --format '{{.Repository}}:{{.Tag}} {{.Size}}'
docker history hello-multi      # one row per layer

Retrieval practice

Answer from memory. One attempt each.

1. What do containers on one host share?

Multiple containers share the same kernel; that is why they are lighter than VMs.[1]

2. An image is best described as...?

Images are immutable; changes make a new image or add layers.[2]

3. What does one layer represent?

Each layer is a set of file system changes that add, remove, or modify files.[2]

4. A container's key isolation property?

Containers are isolated processes on the host.[1]
