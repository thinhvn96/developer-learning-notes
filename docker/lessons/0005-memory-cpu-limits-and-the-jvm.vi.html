Giới hạn memory và CPU, và JVM nhìn thấy gì

Docker · Bài 0005 · bước 10/12 · Advanced · ~12 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: dự đoán được heap của JVM và số CPU bên trong một container bị giới hạn memory và CPU, và giải thích cái gì kill container khi nó vượt giới hạn.

Các giới hạn của Docker

--memory (-m) là "lượng memory tối đa container được dùng." Khi container vượt giới hạn trên Linux, cơ chế xử lý out-of-memory của kernel "bắt đầu kill các process để giải phóng memory". --cpus quy định container được dùng bao nhiêu CPU của host, ví dụ --cpus="1.5" trên host có hai CPU nghĩa là tối đa một CPU rưỡi.[1]

JVM nhìn thấy gì

Trên Linux, JVM bật sẵn tính năng phát hiện container ("automatic container detection support"), nên nó đọc giới hạn memory và CPU của container; -Xlog:os+container=trace cho bạn thấy nó phát hiện được gì.[2] -XX:MaxRAMPercentage mặc định là 25 phần trăm memory tối đa; với heap nhỏ (khoảng 125 MB) thì -XX:MinRAMPercentage mặc định là 50 phần trăm.[2]

Đo bằng image ví dụ

docker run --rm hello-multi
  processors: 12   max heap: 3920 MB      # no limits: 1/4 of host RAM

docker run --rm --memory=256m --cpus=1 hello-multi
  processors: 1    max heap: 121 MB       # heap about half of 256 MB

docker run --rm --memory=256m \
  -e JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75 hello-multi
  max heap: 185 MB

Kết quả 121 MB khớp với mặc định 50 phần trăm cho heap nhỏ mà tài liệu ghi; mối liên hệ này là cách tôi hiểu tài liệu tham chiếu, nên hãy tự kiểm chứng trong bài tập bằng cách đổi giới hạn.

Điểm cấp Senior: heap không phải phần memory duy nhất JVM dùng (còn metaspace, thread stack, direct buffer, code cache), nên đặt heap bằng 100 phần trăm giới hạn là tự mời OOM killer tới. Hãy chọn tỷ lệ dưới 100 và đo đạc. Bài Kubernetes về requests và limits xây dựng tiếp trên nền này.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Container vượt --memory. Cái gì ra tay?

Bộ quản lý out-of-memory của kernel bắt đầu kill các process.[1]

2. Không có giới hạn, max heap mặc định khoảng...?

Max heap mặc định là 25 phần trăm (MaxRAMPercentage), tức 3920 MB trên khoảng 15.7 GB trong lần chạy ở trên.[2]

3. Trong container, JVM đọc gì để tự tính kích thước?

Hỗ trợ container được bật mặc định trên Linux.[2]

4. Vì sao không đặt MaxRAMPercentage bằng 100?

JVM còn dùng memory non-heap; heap cộng phần đó phải nằm gọn trong giới hạn (lập luận cấp senior; hãy đo để kiểm chứng).
