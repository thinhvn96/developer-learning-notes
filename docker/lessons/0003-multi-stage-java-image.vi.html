Image multi-stage cho ứng dụng Java

Docker · Bài 0003 · bước 6/12 · Core · ~10 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: viết một Dockerfile multi-stage compile trong image JDK và chạy trên image JRE nhỏ hơn, rồi chứng minh chênh lệch kích thước.

Vì sao cần multi-stage

Multi-stage build giúp "bất kỳ ai từng vất vả tối ưu Dockerfile mà vẫn muốn giữ nó dễ đọc, dễ bảo trì." Nó "tách bạch rõ ràng hơn giữa quá trình build image và đầu ra cuối cùng."[1][2] Bạn có thể đặt tên cho một stage (FROM ... AS build) và copy artifact ra khỏi nó bằng COPY --from=build; docker build --target build sẽ dừng ở stage được chọn.[1]

Phiên bản cho Java

FROM eclipse-temurin:21-jdk AS build
WORKDIR /src
COPY src/ src/
RUN mkdir out && javac -d out src/Hello.java

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /src/out/ ./
CMD ["java", "-cp", ".", "Hello"]

Compiler và source nằm lại ở stage đầu tiên; chỉ có các file class đi vào image runtime. File đầy đủ: Dockerfile và Dockerfile.naive.

Đo trên máy này

hello-naive:latest 475MB   (JDK image, one stage)
hello-multi:latest 318MB   (JRE image, two stages)

Một fat jar Spring Boot thật sẽ cộng thêm kích thước của chính nó, nhưng ý tưởng tiết kiệm nhờ đổi base từ JDK sang JRE vẫn y như vậy. Tài liệu Docker cũng khuyên dùng base image tối giản và tin cậy.[2]

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. COPY --from=build làm gì?

Nó copy artifact từ một stage trước đó đã được đặt tên (hoặc từ một image bên ngoài).[1]

2. Vì sao không để JDK trong image cuối cùng?

Multi-stage build tách quá trình build khỏi đầu ra cuối cùng.[2]

3. Làm sao dừng build tại stage build?

Flag --target dừng quá trình build tại một stage cụ thể.[1]

4. AS build trong FROM dùng để làm gì?

Đặt tên stage giúp COPY --from vẫn chạy đúng khi thứ tự các stage thay đổi.[1]
