Dockerfile instructions: ENV vs ARG, COPY vs ADD, EXPOSE

Docker · Lesson 0008 · step 3 of 12 · Foundation · ~10 minutes · Home · Docker ladder · Roadmap

Today's win: choose between ENV and ARG, COPY and ADD, and know that EXPOSE does not publish a port.

The instructions, one line each

InstructionMeaning[1]
FROMcreate a new build stage from a base image; the first instruction (after optional ARG)
RUNexecute build commands; creates a layer
COPY / ADDCOPY transfers files from the build context; ADD is similar but also handles remote URLs and tar extraction
ENVenvironment variables that persist in the final image and are available to later instructions
ARGbuild-time variables passed with --build-arg; not embedded in the final image
EXPOSEdescribes which ports the app listens on; documents, does not publish
USER, WORKDIR, VOLUME, HEALTHCHECKuser/group, working directory, mount points, health probe

Check it

cd docker/examples && ./05-cmd-entrypoint-arg-env.sh
ARG is not visible at runtime, ENV is
APP_MODE=prod BUILD_ID=<unset>

Practical rule: prefer COPY unless you need what ADD adds (a common recommendation; the reference page only states the difference). Never pass secrets as ARG or ENV if the image is shared (my inference from "persists in the final image"). Files: entrypoint-demo/Dockerfile.

Retrieval practice

Answer from memory. One attempt each.

1. Which variable exists only at build time?

ARG values are passed at build time and not embedded in the final image.[1]

2. What does EXPOSE do?

It describes the ports the app listens on without publishing them.[1]

3. COPY vs ADD: what does ADD also handle?

ADD also handles remote URLs and tar extraction.[1]

4. Where must FROM appear?

FROM is the first instruction, apart from optional ARG or parser directives.[1]
