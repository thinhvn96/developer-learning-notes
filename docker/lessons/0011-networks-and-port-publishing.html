Networks, DNS by name and port publishing

Docker · Lesson 0011 · step 8 of 12 · Core · ~10 minutes · Home · Docker ladder · Roadmap

Today's win: explain why containers on a user-defined bridge reach each other by name but not on the default bridge, and what -p actually publishes.

Drivers

Built-in Linux drivers: bridge (default), host (removes isolation), none (complete isolation), overlay (multiple daemons), plus ipvlan and macvlan.[1]

Default vs user-defined bridge

  • User-defined bridges provide automatic DNS resolution between containers by name or alias; containers on the default bridge can only use IP addresses (or the legacy --link).[2]
  • User-defined bridges give better isolation: only containers attached to that network can talk to each other.[2]

c (user) -> b (default) by name: ping: bad address

Publishing ports

Without -p, ports "are not accessible from outside the host or, with the default configuration, from containers in other networks". Publishing forwards traffic between host ports and container ports.[1][2] Containers on the same user-defined bridge expose all ports to each other without publishing.[2] This is why Compose services reach the database as db:5432. Source: 04-networks.sh.

Retrieval practice

Answer from memory. One attempt each.

1. Reach another container by name on the default bridge?

Default-bridge containers cannot refer to each other by name.[1]

2. Which network type gives automatic DNS?

User-defined bridges provide automatic DNS resolution.[2]

3. What does -p do?

It forwards traffic between host ports and container ports.[2]

4. Driver that removes network isolation?

host removes isolation between container and host.[1]
