Network, DNS theo tên và publish port

Docker · Bài 0011 · bước 8/12 · Core · ~10 phút · Trang chủ · Lộ trình Docker · Lộ trình tổng · English

Thành quả hôm nay: giải thích vì sao các container trên user-defined bridge gọi nhau được bằng tên còn trên default bridge thì không, và -p thực sự publish cái gì.

Các driver

Các driver có sẵn trên Linux: bridge (mặc định), host (bỏ cô lập), none (cô lập hoàn toàn), overlay (nhiều daemon), cùng với ipvlan và macvlan.[1]

Default bridge vs user-defined bridge

  • User-defined bridge tự động phân giải DNS giữa các container theo tên hoặc alias; container trên default bridge chỉ dùng được địa chỉ IP (hoặc --link kiểu cũ).[2]
  • User-defined bridge cô lập tốt hơn: chỉ những container gắn vào network đó mới nói chuyện được với nhau.[2]
cd docker/examples && ./04-networks.sh
default bridge       : ping: bad address 'b-...'
user-defined bridge  : PING d-... (172.18.0.3): 64 bytes ... time=0.056 ms
c (user) -> b (default) by name: ping: bad address

Publish port

Không có -p thì các port "không truy cập được từ bên ngoài host, hoặc với cấu hình mặc định, từ các container ở network khác". Publish là chuyển tiếp traffic giữa port của host và port của container.[1][2] Các container trên cùng một user-defined bridge thấy được mọi port của nhau mà không cần publish.[2] Đó là lý do các service trong Compose kết nối tới database bằng db:5432. Source: 04-networks.sh.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Gọi container khác bằng tên trên default bridge?

Các container trên default bridge không gọi nhau bằng tên được.[1]

2. Loại network nào có DNS tự động?

User-defined bridge cung cấp phân giải DNS tự động.[2]

3. -p làm gì?

Nó chuyển tiếp traffic giữa port của host và port của container.[2]

4. Driver nào bỏ cô lập network?

host bỏ cô lập giữa container và host.[1]
