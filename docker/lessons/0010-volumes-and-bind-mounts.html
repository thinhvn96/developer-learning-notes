Volumes and bind mounts

Docker · Lesson 0010 · step 7 of 12 · Core · ~10 minutes · Home · Docker ladder · Roadmap

Today's win: keep data beyond a container's life with a volume, share host files with a bind mount, and choose between them.

Volumes

"Volumes are persistent data stores for containers, created and managed by Docker." A volume's contents "exist outside the lifecycle of a given container"; when a container is destroyed its writable layer is destroyed with it.[1] Create with docker volume create, list with docker volume ls, remove with docker volume rm; mount with -v myvolume:/app or the more explicit --mount source=myvolume,target=/app.[1]

Bind mounts

A bind mount attaches a file or directory of the host. Good for development (share source code or build artifacts) and distributing config files. Downside: "Containers with bind mounts are strongly tied to the host" because they depend on its directory layout. Add readonly to stop the container writing.[2]

Choose a volume for data Docker should manage (databases; see the Compose lesson); a bind mount when you need to access the files from the host.[1] Source: 03-volumes-and-bind-mounts.sh.
