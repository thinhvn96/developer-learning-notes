The circuit breaker pattern

System Design · Lesson 0004 · step 3 of 11 · Core · ~10 minutes · Home · System Design ladder · Roadmap · Tiếng Việt

Today's win: explain the three states of a circuit breaker and how it differs from retry.

Purpose

The pattern helps prevent an application from repeatedly trying an operation that is likely to fail, so it can continue without waiting for the fault to be fixed and detect when it is resolved. It differs from Retry: "The Retry pattern enables an application to retry an operation with the expectation that it eventually succeeds. The Circuit Breaker pattern prevents an application from performing an operation that's likely to fail." You can combine them by retrying through a breaker.[1]

States

  • Closed: requests pass through; a failure counter is kept; too many failures within a period trips it to Open and starts a timeout timer.
  • Open: requests "fail immediately and an exception is returned".
  • Half-Open: after the timeout, a limited number of requests pass; success closes the breaker and resets the counter; any failure reopens it. This prevents a recovering service from being flooded.[1]
java system-design/examples/CircuitBreakerDemo.java
call 1-2 -> fallback state=CLOSED  real calls=1,2
call 3   -> fallback state=OPEN    real calls=3       # threshold of 3 failures reached
call 4-8 -> fallback state=OPEN    real calls=3       # service not touched
-- service recovers, wait for the timeout
call 9   -> ok       state=CLOSED  real calls=4

Source: CircuitBreakerDemo.java (my minimal implementation of the documented states, not production code; use a library). Considerations from the docs: handle the exceptions it raises (degrade, use an alternative, or tell the user), monitor state changes, tune timeouts, and remember that a long external timeout can still tie up threads.[1] Not needed when a message-driven design already routes failures to a dead letter queue.[1]

Retrieval practice

Answer from memory. One attempt each.

1. Which state rejects requests immediately?

In the Open state requests fail immediately.[1]

2. What does Half-Open do?

A limited number of requests may invoke the operation.[1]

3. Circuit breaker vs retry?

The breaker prevents an operation that is likely to fail.[1]

4. Trial fails in Half-Open. Next state?

Any failure reverts to Open and restarts the timer.[1]
