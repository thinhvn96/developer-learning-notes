Direct, fanout and topic exchanges

RabbitMQ · Lesson 0002 · step 2 of 9 · Foundation · ~10 minutes · Home · RabbitMQ ladder · Roadmap

Today's win: choose direct, fanout or topic for a routing requirement and predict which queues receive a message.

Four exchange types, three you will use

TypeRouting[1]
Directexact routing-key match; unicast
Fanoutcopies to all bound queues, ignoring the routing key
Topicrouting-key pattern match for selective distribution
Headersroutes on message header values, not the routing key

What the example did

  • ex.direct bound q.errors with key error. Publishing error reached it; info reached nothing.
  • ex.fanout bound q.all and q.eu. One publish put a copy in each.
  • ex.topic bound q.eu with pattern orders.eu.*. orders.eu.created matched; orders.us.created did not.
queue q.errors depth: 1
queue q.all depth: 1
queue q.eu depth: 2       # one from the fanout, one from the topic exchange

The orders.eu.* pattern uses the topic wildcard * as in the AMQP tutorial (the fetched excerpt describes topic exchanges as pattern matching; the wildcard behavior here was confirmed by the run above).

Interview angle: "Fanout versus topic?" Fanout is broadcast; topic is selective subscription by pattern. Use direct when you know the exact key, for example one queue per severity.

Retrieval practice

Answer from memory. One attempt each.

1. Which exchange ignores the routing key?

Fanout broadcasts copies to all bound queues and ignores the routing key.[1]

2. Which exchange matches routing-key patterns?

Topic exchanges match routing patterns.[1]

3. Which routes on header values?

The headers exchange uses message header values.[1]

4. Bound with key error, publish key info to direct. Result?

Direct requires an exact match; the example returned routed:false.[1]
