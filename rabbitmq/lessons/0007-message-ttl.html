Message TTL: per-queue and per-message expiry

RabbitMQ · Lesson 0007 · step 5 of 9 · Core · ~10 minutes · Home · RabbitMQ ladder · Roadmap · Tiếng Việt

Today's win: expire messages by queue TTL or per-message TTL, and know where expired messages go and the head-of-queue caveat.

Two ways

  • Per-queue message TTL: the x-message-ttl queue argument (or a policy), applied to every message in the queue.
  • Per-message TTL: the expiration property set when publishing. If both exist, "the lower value between the two will be chosen".[1]

What happens to expired messages

Quorum queues dead-letter expired messages when they reach the head of the queue; classic queues do so at the head or when notified of a policy change. Expiry is one of the four dead-letter reasons, so a DLX can capture them.[1][2]

Caveat (classic queues, per-message TTL): "expired messages can queue up behind non-expired ones until the latter are consumed or expired", so their resources are not freed; the docs suggest queue TTL if you need immediate cleanup.[1]

cd rabbitmq/examples && ./02-ttl-and-streams.sh
per-queue TTL 2000 ms + DLX:  right after publish q.ttl=2 q.expired=0 ; after 4 s q.ttl=0 q.expired=2
per-message expiration=1000:  queue depth after 3 s = 1   (the message without TTL is still there)

Retrieval practice

Answer from memory. One attempt each.

1. Queue TTL argument name?

Per-queue message TTL uses x-message-ttl.[1]

2. Both TTLs set. Which applies?

The lower of the two is chosen.[1]

3. Expired messages can go to...?

Expiry is a dead-letter reason.[2]

4. Classic queue per-message TTL caveat?

Expired messages can sit behind non-expired ones until they reach the head.[1]
