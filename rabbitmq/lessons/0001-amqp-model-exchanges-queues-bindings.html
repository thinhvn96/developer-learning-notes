The AMQP model: exchanges, queues and bindings

RabbitMQ · Lesson 0001 · step 1 of 9 · Foundation · ~10 minutes · Home · RabbitMQ ladder · Roadmap · Tiếng Việt

Today's win: trace a message from publisher to consumer through exchange, binding and queue, and explain why publishers never send to queues directly.

The model

"Messages are published to exchanges, which are often compared to post offices or mailboxes. Exchanges then distribute message copies to queues using rules called bindings."[1] Consumers take messages from queues, by subscription (push) or by polling (pull, which the docs discourage).[1]

publisher --> [exchange] --binding--> (queue) --> consumer
                        \--binding--> (queue) --> consumer

The default exchange

The "default exchange is a direct exchange with no name (empty string) pre-declared by the broker"; every new queue is automatically bound to it with the queue name as routing key.[1] That is why "publish straight to a queue name" works in tutorials: it is really the default exchange routing.

Because of this indirection, a publisher does not need to know which queues exist. A message that matches no binding is dropped unless you handle it: the example's API replies {"routed":false} for those.

Run it

cd rabbitmq/examples && ./01-routing-ack-dlx.sh
{"routed":true}  <- ex.direct 'error'
{"routed":false} <- ex.direct 'info'      # no binding matched: unroutable

Source: 01-routing-ack-dlx.sh (throwaway rabbitmq:4-management container, driven through the HTTP API).

Retrieval practice

Answer from memory. One attempt each.

1. Publishers send messages to what?

Messages are published to exchanges, which route copies to queues.[1]

2. What links an exchange to a queue?

Exchanges distribute copies to queues using rules called bindings.[1]

3. Default exchange type?

The default exchange is a nameless direct exchange.[1]

4. Message matches no binding. Example API says?

The publish call returned routed:false for messages with no matching binding.
