Dead letter exchanges

Today's win: name the four reasons a message is dead-lettered and configure a DLX, preferring policies over queue arguments.

What a DLX is

Messages from a queue can be "dead-lettered", "republished to an exchange" when certain events occur. A dead letter exchange is an ordinary exchange of any type.[1]

Four reasons

  1. Rejected without requeue: basic.reject or basic.nack with requeue=false (or the AMQP 1.0 rejected outcome).
  2. The message expires due to per-message TTL.
  3. The message is dropped because its queue exceeded a length limit.
  4. The message is returned more times to a quorum queue than its delivery limit.[1]

Configure

Via a policy (dead-letter-exchange, optional dead-letter-routing-key) or via queue arguments (x-dead-letter-exchange). The docs prefer policies: they can be changed without redeploying applications, while hardcoded arguments require deleting and redeclaring the queue.[1]

Retrieval practice

Answer from memory. One attempt each.

1. Which is a reason for dead-lettering?

basic.reject or basic.nack with requeue=false dead-letters a message.[1]

2. A DLX is which kind of exchange?

Dead letter exchanges are normal exchanges and can be any type.[1]

3. Preferred way to configure a DLX?

Policies can be updated without redeploying applications.[1]

4. Message TTL expires. What can happen?

Per-message TTL expiry is one of the dead-letter reasons.[1]
