CTEs: WITH and WITH RECURSIVE

PostgreSQL · Lesson 0009 · step 6 of 13 · Core · ~10 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: write a CTE to name intermediate results, and a recursive CTE to walk a hierarchy.

WITH

WITH defines auxiliary statements (CTEs) that act like "temporary tables that exist just for one query". Each can be a SELECT, INSERT, UPDATE, DELETE or MERGE.[1] They make long queries readable.

Recursive

A recursive query "always has a non-recursive term, then UNION (or UNION ALL), then a recursive term", where only the recursive term references its own output. It runs the non-recursive term, then repeats the recursive term on the working table until no rows are produced.[1]

WITH RECURSIVE chain AS (
    SELECT id, name, manager_id, 0 AS level FROM emp WHERE name = 'dev'
  UNION ALL
    SELECT e.id, e.name, e.manager_id, c.level + 1 FROM emp e JOIN chain c ON e.id = c.manager_id
) SELECT level, name FROM chain ORDER BY level;
-- 0 dev, 1 lead, 2 vp, 3 ceo

Inlining

A non-recursive, side-effect-free CTE referenced once is folded into the parent query by default; MATERIALIZED forces separate calculation (useful for expensive functions), NOT MATERIALIZED forces inlining.[1] Source: 09-cte.sql.

Retrieval practice

Answer from memory. One attempt each.

1. A CTE lives for...?

CTEs act as temporary tables just for one query.[1]

2. Shape of a recursive CTE?

Non-recursive term, then UNION [ALL], then a recursive term.[1]

3. When does a recursive CTE stop?

It loops until the recursive term produces no rows.[1]

4. Which keyword forces separate computation?

AS MATERIALIZED forces the CTE to be calculated on its own.[1]
