Các loại index: B-tree, hash, GIN, BRIN

PostgreSQL · Bài 0010 · bước 8/13 · Core · ~10 phút · Trang chủ · Lộ trình PostgreSQL · Lộ trình tổng · English

Thành quả hôm nay: kể tên các loại index có sẵn và chọn được loại phù hợp cho so sánh bằng/khoảng, kiểm tra mảng có chứa phần tử, hoặc table cực lớn sắp theo thời gian.

Các loại

LoạiPhù hợp với[1]
B-tree (mặc định)so sánh bằng và theo khoảng trên dữ liệu sắp xếp được: < <= = >= >, BETWEEN, IN, IS NULL, LIKE có neo đầu chuỗi
Hashchỉ so sánh bằng (lưu một giá trị hash 32-bit)
GINindex "đảo ngược" cho các giá trị phức hợp như mảng và full-text; mỗi thành phần một entry
GiST / SP-GiSThạ tầng cho nhiều chiến lược khác nhau (hình học, tìm láng giềng gần nhất)
BRINtóm tắt theo từng dải block; tốt nhất khi giá trị tương quan với thứ tự vật lý của các dòng

CREATE INDEX tạo B-tree trừ khi bạn chỉ định loại khác bằng USING.[1] Trong lần tôi chạy, một index GIN trên cột text[] đã được dùng cho tags @> ARRAY['x7'] (Bitmap Index Scan trên t_tags).

Source: 10-index-types.sql. Nền tảng: index: được gì.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Loại index mặc định?

B-tree là mặc định của CREATE INDEX.[1]

2. Index cho phép kiểm tra mảng có chứa phần tử?

GIN phù hợp với các giá trị phức hợp như mảng.[1]

3. Loại nào chỉ xử lý so sánh bằng?

Hash index chỉ xử lý phép so sánh bằng.[1]

4. BRIN hiệu quả nhất khi giá trị...?

Nó hiệu quả khi giá trị tương quan với thứ tự vật lý của các dòng.[1]
