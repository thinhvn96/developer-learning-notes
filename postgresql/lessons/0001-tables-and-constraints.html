Tables and constraints

PostgreSQL · Lesson 0001 · step 1 of 13 · Foundation · ~10 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: use constraints to make bad data impossible, and name what each one prevents.

Let the database say no

Constraints move data rules out of application code and into the schema, where every writer must obey them. The PostgreSQL docs define them as follows.[1]

  • CHECK: a value must satisfy a Boolean expression, e.g. price numeric CHECK (price > 0).
  • NOT NULL: a column must not assume the null value.
  • UNIQUE: data is unique among all rows, for a column or a group of columns.
  • PRIMARY KEY: unique and not null; "a table can have at most one primary key".
  • FOREIGN KEY: values must match a row in another table (referential integrity). ON DELETE RESTRICT prevents deleting a referenced row; ON DELETE CASCADE deletes the referencing rows too.

Watch each one fire

ERROR:  duplicate key value violates unique constraint "products_pkey"
ERROR:  insert or update on table "orders" violates foreign key constraint "orders_product_no_fkey"
ERROR:  update or delete on table "products" violates RESTRICT setting of foreign key constraint ...
ERROR:  null value in column "name" of relation "products" violates not-null constraint

Source: 01-constraints.sql. The runner starts a throwaway postgres:18 container (Docker required) and removes it afterwards.

Interview angle: "Where do you enforce uniqueness, the app or the database?" The database. An app-level check races with concurrent writers (see the isolation lesson); a unique constraint does not.

Retrieval practice

Answer from memory. One attempt each.

1. Which constraint stops price = 0 if price must be positive?

CHECK requires a Boolean expression to hold.[1]

2. How many primary keys can a table have?

A table can have at most one primary key.[1]

3. Delete a product referenced by orders with ON DELETE RESTRICT?

RESTRICT prevents deletion of a referenced row.[1]

4. Which option deletes the referencing rows automatically?

CASCADE deletes rows that reference the deleted row.[1]
