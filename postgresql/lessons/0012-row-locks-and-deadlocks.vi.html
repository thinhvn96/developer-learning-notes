Row lock, SELECT FOR UPDATE và deadlock

PostgreSQL · Bài 0012 · bước 12/13 · Advanced · ~12 phút · Trang chủ · Lộ trình PostgreSQL · Lộ trình tổng · English

Thành quả hôm nay: dùng SELECT ... FOR UPDATE, giải thích deadlock hình thành giữa hai transaction thế nào, và cách phòng tránh nó.

Row lock

SELECT ... FOR UPDATE lock các dòng được chọn "như thể sắp update chúng": các transaction khác cố UPDATE, DELETE hoặc lock những dòng đó sẽ bị chặn cho tới khi transaction này kết thúc.[1]

Deadlock

Deadlock xảy ra khi hai transaction mỗi bên giữ lock mà bên kia cần. PostgreSQL phát hiện ra và hủy (abort) một trong hai transaction. Cách phòng thủ tốt nhất là "lấy lock trên nhiều đối tượng theo một thứ tự nhất quán trong tất cả các ứng dụng"; nếu không thì retry transaction bị hủy.[1]

cd postgresql/examples && ./11-locking.sh
=== 1. SELECT ... FOR UPDATE makes another writer wait
second session UPDATE waited about 2.1 s for the row lock
=== 2. deadlock: opposite update order
ERROR:  deadlock detected
final balances: 1|91   2|110      # one transaction committed, one was aborted

So sánh với bài về deadlock bên Java: cùng nguyên nhân, cùng cách chữa. Trong Spring, transaction bị hủy sẽ hiện ra dưới dạng một exception mà bạn nên retry ở bên ngoài ranh giới transaction. Source: 11-locking.sh.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. FOR UPDATE ảnh hưởng gì tới các bên ghi khác?

Các transaction khác cố UPDATE hoặc DELETE những dòng đó sẽ bị chặn.[1]

2. Hai transaction chờ lẫn nhau. PostgreSQL...?

Nó phát hiện deadlock và hủy một trong các transaction.[1]

3. Cách phòng tránh tốt nhất?

Lấy lock theo một thứ tự nhất quán giữa các ứng dụng.[1]

4. Sau lỗi deadlock, ứng dụng nên làm gì?

Xử lý deadlock bằng cách retry transaction bị hủy.[1]
