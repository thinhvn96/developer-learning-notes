Index nhiều cột và partial index

PostgreSQL · Bài 0011 · bước 9/13 · Advanced · ~12 phút · Trang chủ · Lộ trình PostgreSQL · Lộ trình tổng · English

Thành quả hôm nay: sắp xếp thứ tự cột trong một index nhiều cột, và dùng partial index để giữ index nhỏ gọn.

B-tree nhiều cột

Hiệu quả nhất khi có điều kiện trên các cột đứng đầu: "các điều kiện so sánh bằng trên những cột đứng đầu, cộng với điều kiện bất đẳng thức trên cột đầu tiên không có điều kiện so sánh bằng, sẽ luôn được dùng để giới hạn phần index cần quét." Với index trên (a, b, c): WHERE a = 5 AND b >= 42 AND c < 77 là lý tưởng.[1] Các phiên bản gần đây còn có thể áp dụng tối ưu skip scan khi các cột đứng đầu có ít giá trị khác nhau.[1] Cảnh báo: hãy dùng tiết chế; index nhiều hơn ba cột hiếm khi có ích, trừ khi cách dùng cực kỳ cố định.[1]

Partial index

Partial index chỉ bao phủ một tập con các dòng được chọn bởi một điều kiện (predicate). Lợi ích chính của nó là "tránh đánh index cho các giá trị phổ biến": index nhỏ hơn, update nhanh hơn vì không phải lần ghi nào cũng đụng tới nó.[2]

./run.sh 10-index-types.sql
CREATE INDEX t_ab   ON t (a, b);                 -- 1352 kB
CREATE INDEX t_rare ON t (c) WHERE status='rare';-- 64 kB
EXPLAIN ... WHERE a = 5 AND b = 505      -> Bitmap Index Scan on t_ab
EXPLAIN ... WHERE b = 505                -> Bitmap Index Scan on t_ab   (a has 100 distinct values)
EXPLAIN ... WHERE status='rare' AND c=300 -> Index Scan using t_rare

Plan thứ hai vẫn dùng index dù a không có điều kiện: điều này khớp với ghi chú về skip scan, vì trong dữ liệu này a chỉ có 100 giá trị khác nhau. Đừng trông cậy vào điều đó với những cột có nhiều giá trị khác nhau. Source: 10-index-types.sql.

Luyện truy hồi

Trả lời theo trí nhớ. Mỗi câu chỉ một lần chọn.

1. Index trên (a, b, c). Điều kiện nào hữu ích nhất?

Điều kiện trên các cột đứng đầu giới hạn phần index cần quét.[1]

2. Lợi ích chính của partial index?

Nó tránh đánh index cho các giá trị phổ biến, nhờ vậy index nhỏ đi.[2]

3. Khuyến nghị về index có nhiều cột?

Index nhiều hơn ba cột khó mà có ích, trừ khi cách dùng cực kỳ cố định.[1]

4. Trong lần chạy, partial index lớn bao nhiêu?

64 kB, so với 1352 kB của index nhiều cột.
