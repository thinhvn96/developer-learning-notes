Inner and left joins, and the WHERE trap

PostgreSQL · Lesson 0002 · step 3 of 13 · Foundation · ~10 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: predict the row count of an inner and a left join, and spot the WHERE clause that silently turns a left join into an inner join.

Inner vs left outer

An inner join keeps only rows that match on both sides. A left outer join is named so because "the table mentioned on the left of the join operator will have each of its rows in the output at least once"; for a left row with no match, "empty (null) values are substituted for the right-table columns."[1]

cd postgresql/examples && ./run.sh 02-joins.sql
-- inner join: 2 rows (Hayward dropped)
-- left outer join: 3 rows (Hayward with NULL name, location)

The trap

Add WHERE cities.location IS NOT NULL to the left join and Hayward disappears again: the NULL that the outer join produced fails the filter. The run shows 2 rows. (This follows from the NULL-substitution rule above; the third query in the example demonstrates it.) To filter the right table without losing left rows, put the condition in the ON clause instead.

Interview angle: "Why does my LEFT JOIN return fewer rows than the left table?" Answer: a WHERE predicate on the right table's columns.

Retrieval practice

Answer from memory. One attempt each.

1. Inner join, left row has no match. Output?

Only rows matching both sides appear in an inner join.

2. Left outer join, left row has no match. Output?

Empty (null) values fill the right-table columns.[1]

3. Where should a right-table filter go to keep left rows?

A WHERE filter on right columns removes the NULL-extended rows; ON filters before null-extension.

4. Which side of a left join keeps every row?

The left table's rows each appear at least once.[1]
