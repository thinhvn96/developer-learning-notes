Aggregates, GROUP BY and HAVING

PostgreSQL · Lesson 0007 · step 2 of 13 · Foundation · ~10 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: use aggregates with GROUP BY, and say whether a filter belongs in WHERE or HAVING.

Aggregates

An aggregate computes one result from many input rows: count, sum, avg, max, min.[1] With GROUP BY you get one output row per group.

WHERE versus HAVING

"WHERE selects input rows before groups and aggregates are computed ... whereas HAVING selects group rows after groups and aggregates are computed." The WHERE clause must not contain aggregates; HAVING always does.[1]

cd postgresql/examples && ./run.sh 07-aggregates.sql
GROUP BY city:           Hayward 2 rows, Oakland 1, San Francisco 2
WHERE temp_lo < 40 ...:  Hayward 1, Oakland 1                  # rows filtered first
HAVING max(temp_lo)<40:  Oakland 35                            # groups filtered after
WHERE temp_lo = max(...): ERROR: aggregate functions are not allowed in WHERE

The fix the docs give: a subquery, WHERE temp_lo = (SELECT max(temp_lo) FROM weather).[1] Source: 07-aggregates.sql. Contrast with window functions, which keep every row.

Retrieval practice

Answer from memory. One attempt each.

1. Which clause filters rows before grouping?

WHERE selects input rows before groups are computed.[1]

2. Which clause contains aggregate conditions?

HAVING selects groups after aggregation and always contains aggregates.[1]

3. Can WHERE contain max(x)?

PostgreSQL rejects aggregates in WHERE (shown in the run).[1]

4. GROUP BY city returns how many rows per city?

One output row per group.[1]
