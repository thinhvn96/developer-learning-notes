Window functions

PostgreSQL · Lesson 0003 · step 5 of 13 · Core · ~10 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: write a window function that shows a group statistic beside every row, and use row_number() to pick the top row per group.

Aggregate versus window

A window function "performs a calculation across a set of table rows that are somehow related to the current row." Unlike a plain aggregate, window functions "do not cause rows to become grouped into a single output row"; the rows keep their separate identities.[1]

Syntax to memorize

  • OVER always follows the function, and marks it as a window function.[1]
  • PARTITION BY splits rows into groups that share values; the function is computed within the current row's partition.[1]
  • ORDER BY inside OVER controls processing order within the partition (it need not match the output order).[1]
SELECT depname, empno, salary,
       row_number() OVER (PARTITION BY depname ORDER BY salary DESC)
FROM empsalary;
cd postgresql/examples && ./run.sh 03-window.sql
-- aggregate: 2 rows, window: 6 rows with the average beside each
-- top earner per department: wrap the window query, then WHERE rn = 1

Interview favorite: "top N per group". Window functions cannot appear directly in WHERE, so compute row_number() in a subquery, then filter on it, as the last query of the example does.

Retrieval practice

Answer from memory. One attempt each.

1. How does a window function treat rows?

Rows retain their separate identities.[1]

2. What splits rows into groups inside OVER?

PARTITION BY divides rows into partitions.[1]

3. Six rows in, two departments. Rows out with a window average?

Windows do not collapse rows, so six rows return.

4. Which finds the top earner per department?

Number rows per partition by salary descending, then keep rn = 1.
