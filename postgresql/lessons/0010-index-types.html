Index types: B-tree, hash, GIN, BRIN

PostgreSQL · Lesson 0010 · step 8 of 13 · Core · ~10 minutes · Home · PostgreSQL ladder · Roadmap · Tiếng Việt

Today's win: name the built-in index types and pick one for equality/range, array containment, or huge time-ordered tables.

The types

TypeGood for[1]
B-tree (default)equality and range on sortable data: < <= = >= >, BETWEEN, IN, IS NULL, anchored LIKE
Hashequality only (stores a 32-bit hash)
GIN"inverted" index for composite values such as arrays and full-text; one entry per component
GiST / SP-GiSTinfrastructure for many strategies (geometry, nearest neighbor)
BRINsummaries of block ranges; best when values correlate with physical row order

CREATE INDEX makes a B-tree unless you say USING something else.[1] In my run a GIN index on a text[] column was used for tags @> ARRAY['x7'] (Bitmap Index Scan on t_tags).

Retrieval practice

Answer from memory. One attempt each.

1. Default index type?

B-tree is the default for CREATE INDEX.[1]

2. Index for array containment?

GIN suits composite values like arrays.[1]

3. Which handles only equality?

Hash indexes only handle equality comparisons.[1]

4. BRIN works best when values...?

It is effective when values correlate with physical row order.[1]
