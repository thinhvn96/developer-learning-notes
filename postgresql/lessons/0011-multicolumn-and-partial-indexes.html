Multicolumn and partial indexes

PostgreSQL · Lesson 0011 · step 9 of 13 · Advanced · ~12 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: order columns in a multicolumn index, and use a partial index to keep an index small.

Multicolumn B-tree

Most efficient with constraints on the leading columns: "equality constraints on leading columns, plus any inequality constraints on the first column that does not have an equality constraint, will always be used to limit the portion of the index that is scanned." For an index on (a, b, c): WHERE a = 5 AND b >= 42 AND c < 77 is ideal.[1] Recent versions can also apply a skip-scan optimization when leading columns have few distinct values.[1] Warning: use them sparingly; more than three columns is rarely helpful unless usage is extremely stylized.[1]

Partial indexes

A partial index covers a subset of rows chosen by a predicate. Its main benefit is to "avoid indexing common values": smaller index, faster updates because not every write touches it.[2]

./run.sh 10-index-types.sql
CREATE INDEX t_ab   ON t (a, b);                 -- 1352 kB
CREATE INDEX t_rare ON t (c) WHERE status='rare';-- 64 kB
EXPLAIN ... WHERE a = 5 AND b = 505      -> Bitmap Index Scan on t_ab
EXPLAIN ... WHERE b = 505                -> Bitmap Index Scan on t_ab   (a has 100 distinct values)
EXPLAIN ... WHERE status='rare' AND c=300 -> Index Scan using t_rare

The second plan used the index although a is not constrained: consistent with the skip-scan note, since a has only 100 distinct values in this data. Do not rely on that for columns with many distinct values. Source: 10-index-types.sql.

Retrieval practice

Answer from memory. One attempt each.

1. Index on (a, b, c). Most useful constraint?

Constraints on leading columns limit the scanned portion of the index.[1]

2. Main benefit of a partial index?

It avoids indexing common values, shrinking the index.[2]

3. Guidance on many-column indexes?

Indexes with more than three columns are unlikely to help unless usage is extremely stylized.[1]

4. In the run, the partial index was how big?

64 kB versus 1352 kB for the multicolumn index.
