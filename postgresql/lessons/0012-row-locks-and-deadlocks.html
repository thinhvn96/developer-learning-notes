Row locks, SELECT FOR UPDATE and deadlocks

PostgreSQL · Lesson 0012 · step 12 of 13 · Advanced · ~12 minutes · Home · PostgreSQL ladder · Roadmap

Today's win: use SELECT ... FOR UPDATE, explain how a deadlock forms between two transactions, and prevent it.

Row locks

SELECT ... FOR UPDATE locks the selected rows "as though for update": other transactions trying to UPDATE, DELETE or lock those rows are blocked until this transaction ends.[1]

Deadlocks

A deadlock occurs when two transactions each hold locks the other wants. PostgreSQL detects it and aborts one transaction. The best defense is to "acquire locks on multiple objects in a consistent order across all applications"; otherwise retry the aborted transaction.[1]

Retrieval practice

Answer from memory. One attempt each.

1. What does FOR UPDATE do to other writers?

Other transactions attempting UPDATE or DELETE on those rows are blocked.[1]

2. Two transactions wait on each other. PostgreSQL...?

It detects deadlocks and aborts one of the transactions.[1]

3. Best prevention?

Acquire locks in a consistent order across applications.[1]

4. After a deadlock error, what should the app do?

Handle deadlocks by retrying the aborted transaction.[1]
